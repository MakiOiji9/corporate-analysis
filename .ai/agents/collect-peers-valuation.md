# 担当: collect-peers-valuation（競合・株価指標）

collect-company-info の **Phase 5・6** を担当する。親（オーケストレーター）から起動され、他の担当と**同時に**動く。

## 前提として読むファイル
- `.ai/instructions/policy.md`（禁止事項）
- `.ai/skills/collect-company-info.md` の「保存ルール」「ツール」「同時実行のルール」
- `.ai/templates/collect-company-info/source-access.md`

## 入力（親のプロンプトで渡される）
ticker, name, url, market, mode, 企業ディレクトリ, 収集日, update の場合は「株価のみ」「競合も」「競合の再選定」の範囲指定と、前回の競合リスト（「競合も」でも 5-1 の5 の条件に当たれば選び直す）

## 書いてよいファイル（これ以外は書かない）
- `raw/market/{収集日}_competitors.md`, `raw/ir/{収集日}_valuation-data.md`
- `fetch.py` 経由の `sources/`（競合の短信など）
- **書かない**: `status.md`, `overview.md`, `summaries/`, `data/`（`tdnet_summary.py` を競合に使う場合は `--company` を付けず標準出力だけ使う）, 他担当の raw
- mode=update の差分ファイルは、今回の範囲の章だけを書く。範囲外の章は見出しごと書かない（「変更なし」と書かない。前回の値を再掲しない。collect-company-info.md の保存ルール）。例外: 競合を選び直したときの competitors.md は全章を書く（5-1 の5）

## Phase 5: 競合

### 5-1. 競合の選定（雛形 1章。1.1 → 1.2 → 1.3 の順に書く）

競合は 3C・モート・収益性・バリュエーションのすべてで同じ2〜5社を使う。**事業の近さを最優先し、規模と財務の年数は目安にとどめる**。

1. **比較の軸を書く（1.1）**: 主力事業について、次の6項目を有報（事業の内容・セグメント）と事業概要を出典にして書く。主力事業／提供する価値・工程（上流の戦略・設計か、開発・運用か、製造・販売か など）／主な顧客層／収益モデル（人月・成果報酬・ライセンス・サブスク・物販 など）／提供体制（社員・外注・フリーランスなどの比率）／売上規模（直近の連結売上高）
2. **候補を集める（1.2）**: 次の5つの情報源を**すべて**見て、見つかった会社を「候補の出どころ」に記号で書く。何も見つからなかった情報源は、表の下に「a: 該当なし（見た資料名）」の形で書く
   - a. 会社自身が挙げる競合・比較相手（有報の事業等のリスク・経営方針・経営環境、決算説明資料、質疑応答、中計）
   - b. 業界レポート・業界ランキングで並べて扱われる上場企業（`raw/market/*_industry-overview.md` の上位企業があれば使う。無ければ web 検索）
   - c. 同じ業種分類・テーマで並ぶ上場企業（IRBANK・株探などの「同業他社」「関連テーマ」。確度は二次）
   - d. 証券会社・アナリストのレポートや報道で比較対象にされている企業（確度は検索要約）
   - e. 会社が「競合はいない」とする、または a で見つからない場合: 顧客がこの会社に頼まないとき、代わりにどこへ頼むか（代替の依頼先）
   - 規模の大きい大手・非上場・外資も、事業が近ければ候補として表に載せる（除外する場合も理由を残すため）
3. **候補を評価する（1.2 の表）**: 1.1 の軸のうち「事業・工程」「顧客層」「収益モデル」「提供体制」の4項目について、自社との重なりを ○（ほぼ同じ）/ △（一部重なる）/ ×（違う）で付け、根拠を短く添える。規模は倍率（候補の売上高 ÷ 自社の売上高）で書く。「財務の取得」は、上場していて**売上高**が何期分取れるかで判定し、営業利益の期数が少なければ併記する（例: ○ 10期 / △ 売上高6期・営業利益3期 / × 非上場）。売上高が7期以上を ○、4〜6期を △、3期以下・非上場を × とする。並び順の「財務の年数」も売上高の期数で比べる
4. **選ぶ（1.3）**: 次の順に決める
   - 必須条件: 「事業・工程」が ○、かつ「財務の取得」が ○ か △（上場していて売上高が最低4期分。売上高3年CAGR と収益性の分解に要る）
   - 必須条件を満たす会社を、4項目の ○ の数が多い順に並べる。同数なら規模の倍率が **0.2〜5倍** に入る会社、次に財務の年数が長い会社を先にする。上位から**最大5社**を選ぶ（分析スクリプトが比べるのは最大5社）。○ が2つ以下の会社は入れない。必須条件を満たす会社が1社以下なら、事業・工程が △ の会社から ○ の多い順に足して2社にし、理由を書く
   - 財務が7年に満たない会社を選んだときは、1.3 の選定理由に取れる年数を書き、親への報告の未取得項目に「営業利益率の長期推移（会社名、N年分のみ）」と書く（モート分析の古い年度は、数値のある競合だけの平均になる）
   - 規模の目安（0.2〜5倍）から外れる会社を選んだときは、1.3 の選定理由に「規模は○倍だが、事業・工程が最も近いため」などと書く
   - 1.2 の「判定」には、採用した会社は「採用」、外した会社は「除外: 理由」（例: 事業・工程が △、非上場で財務が取れない、○ が2つ以下、上位5社に入らない）を書く
   - 規模の倍率は選ぶための補助であり、「規模が近い」ことだけを選定理由にしない
5. **update のとき**: 次のどれかに当たれば選び直す（5-1 の1〜4をやり直す）。どれにも当たらなければ前回の競合リストを使い、1章は書かない
   - 前回の1章に 1.1〜1.3 が無い（古い形式）
   - 親のプロンプトで「競合の再選定」が指定された、または主力事業の判定が前回の 1.1 と変わった
   - 前回の競合が上場廃止・事業の大幅な転換をした
   - **選び直したときは、1〜10章をすべて新しい競合で書く**（差分にしない）。分析スクリプトは、中身のある1章を持つ一番新しい competitors.md より古いファイルを使わないため、書かなかった章は「材料なし」になる

### 5-2. 競合の数値

1. 数値は可能なら各社の決算短信 iXBRL（`fetch.py --company {自社dir} --type peer-tanshin` → `tdnet_summary.py <htm>`、`--company` なし）で一次確認する。IRBANK 等の二次情報だけの値は確度「二次」
   - **米国の会社**: `edgar.py facts --ticker {競合ticker}`（`--company` なし。標準出力だけ使う）で売上高・営業利益・当期純利益・総資産・株主資本・売上原価・販管費の10年分を取る（一次。百万ドル）。決算期は会社の FY 名と期末日を併記する（例「FY2026（2026-01-25 終了）」）。日本の会社と並べるときは通貨を列に書き、換算しない

| 項目 |
|---|
| 売上高・営業利益・営業利益率（直近と最大10年推移。最低7年） |
| 市場シェア |
| 売上高の3年CAGR計算に必要な売上高（3年前と直近） |
| ROE、自己資本比率 |
| PER・PBR・EV/EBITDA（直近値）と、その計算に使う EPS（実績・会社予想）・BPS（直近期末） |
| 主力製品と強み（競合のIR資料で本人が主張しているもの） |
| 顧客・人員の KPI と第三者評価（顧客数・継続率・上位顧客比率・従業員数・一人当たり売上高・単価・第三者評価・受賞。自社も同じ列で並べる） |
| 売上原価率・販管費率・営業利益率（直近の実績。自社も同じ列で並べる） |
| 収益性の分解: 売上高・当期純利益・総資産・自己資本・ROE・自己資本比率（直近から最大5期。自社も同じ列で並べる） |
| 安全性の指標: 総資産・自己資本・自己資本比率・有利子負債・現金及び現金同等物・流動資産・流動負債（直近から最大5期。自社も同じ列で並べる） |
| EV/EBITDA の材料: 営業利益・減価償却費（直近期。自社も同じ列で並べる） |

2. **顧客・人員の KPI**（雛形 8章）は 3C 分析の KBF 比較（○△×）に使う。会社の主張（7章）だけでは自社と競合を比べられないため、数値と第三者の事実を集める
   - 一次: 各社の決算説明会資料・統合報告書・有報（従業員の状況、主要な販売先）。`fetch.py <url> --company {自社dir} --type peer-presentation --text` → `find_pages.py find <txt> "顧客数" "リピート" "継続率" "従業員"` で該当ページだけ読む
   - 第三者評価: 業界団体・調査会社の顧客満足度調査、受賞歴（ニュースリリース）。確度を付ける
   - 一人当たり売上高は、売上高と従業員数の両方が同じ年度で開示されている場合だけ計算し、計算式を出典列に書く
   - 探しても無い指標は「—（開示なし）」。会社ごとに探した資料名を出典列に書く（空の行は「材料が無い」と判定され再収集の対象になる）
   - 取れなかった会社・指標は、親への報告の未取得項目に「顧客・人員の KPI（会社名）」の形で書く（status.md の未取得項目になり、3C は再収集を求めなくなる）

3. **営業利益率の長期推移**（雛形 2章）はモート分析で自社と同業平均を年ごとに比べるのに使う（7年以上続けて上回るかを見る）。競合ごとに可能な限り10年分（最低7年）の実績を書く。古い年度は IRBANK 等の集計サイト（確度「二次」）でよい。取れた年数が7年未満の会社は、親への報告の未取得項目に「営業利益率の長期推移（会社名、N年分のみ）」と書く
4. **コスト構造**（雛形 9章）はモート分析の「コスト優位」の判定に使う。各社の損益計算書（短信・有報）の売上原価・販管費を売上高で割る（計算した場合は式を出典列に書く）。取れなかった会社は、親への報告の未取得項目に「売上原価率・販管費率（会社名）」と書く
5. **収益性の分解**（雛形 10章）は収益性分析で ROE を 売上高純利益率 × 総資産回転率 × 財務レバレッジ に分解して同業と比べるのに使う。自社と競合ごとに、直近から最大5期（取れれば6期目の総資産・自己資本も。期首期末平均の計算に使う）を1行ずつ書く
   - 一次: 各社の決算短信 iXBRL（`tdnet_summary.py <htm>`、`--company` なし）のサマリー（売上高・親会社株主に帰属する当期純利益・総資産・自己資本・自己資本比率・自己資本当期純利益率）。短信1本で当期と前期の2期分が取れる。前回の収集で取得した短信の原本（`sources/manifest.csv` で探す。親のプロンプトに場所があればそれ）があれば、取り直さずにそれを使う
   - 自社の行は、raw の有報・財務時系列と `data/tdnet_facts.csv`（読むだけ）から転記する。千円単位の値は百万円に換算し、出典列に換算した旨を書く
   - 古い期は IRBANK 決算まとめ等（確度「二次」）でよい。自己資本が無ければ自己資本比率を書く（純資産は書かない。非支配株主持分・新株予約権を含むため）
   - 金額は百万円で書く（別の単位ならセルに「億円」などを付ける）。IFRS の会社は「親会社の所有者に帰属する当期利益」「親会社の所有者に帰属する持分」を使い、出典列に IFRS と書く
   - 取れた期が3期未満の会社は、親への報告の未取得項目に「収益性の分解（会社名、N期分のみ）」と書く（status.md の未取得項目になり、収益性分析は再収集を求めなくなる）
6. **安全性の指標**（雛形 11章）は安全性分析で自己資本比率・D/E レシオ・流動比率・ネットキャッシュを同業平均と比べるのに使う。自社と競合ごとに、直近から最大5期を1行ずつ書く（いずれも期末残高）
   - 必須の列は 有利子負債・現金及び現金同等物・流動資産・流動負債。総資産・自己資本・自己資本比率は、10章（収益性の分解）に同じ会社・同じ年度の値があれば取り直さず「—（10章）」と書く（スクリプトが 10章の値で補う）
   - 一次: 各社の決算短信・有報の貸借対照表（総資産・自己資本・流動資産・流動負債・現金及び現金同等物）と、借入金・社債の合計（有利子負債）。短信1本で当期と前期の2期分が取れる。収益性の分解で取得した短信の原本があれば、取り直さずにそれを使う
   - 有利子負債は借入金（短期・1年内返済予定の長期・長期）＋社債＋CP の合計。借入が無ければ「0（科目なし）」と書く（空欄は不明と扱われる）。リース債務を含めた場合はその旨を出典・確度列に書く
   - 自社の行は、raw の有報・財務時系列から転記する。古い期は IRBANK 決算まとめ等（確度「二次」）でよい。自己資本が無ければ自己資本比率を書く（純資産は書かない）。金額は百万円（別の単位ならセルに書く。米国の会社は百万ドルと書く）
   - 取れた期が3期未満の会社は、親への報告の未取得項目に「安全性の指標（会社名、N期分のみ）」と書く（status.md の未取得項目になり、安全性分析は再収集を求めなくなる）
7. **EV/EBITDA の材料**（雛形 12章）はバリュエーション分析で同業の EV/EBITDA を計算するのに使う（6章の時価総額・11章の有利子負債と現金と組み合わせる。無料の情報源に EV/EBITDA が無くても比べられるようにするため）。自社と競合ごとに直近の通期を1行書く（11章と同じ年度）
   - 一次: 各社の有報・短信の CF 計算書の「減価償却費」と損益計算書の営業利益。安全性の指標で取得した原本があれば、取り直さずにそれを使う。米国の会社は `edgar.py facts` の DepreciationDepletionAndAmortization 等（百万ドル）
   - 取れなかった会社は、親への報告の未取得項目に「EV/EBITDA の材料（会社名）」と書く（status.md の未取得項目になり、バリュエーション分析は再収集を求めなくなる）

保存先: `raw/market/{収集日}_competitors.md`（雛形 competitors.md）

## Phase 6: 自社の株価・バリュエーション

| 項目 |
|---|
| 現在株価（取得日時を明記）、時価総額、発行済株式数（自己株式を除く） |
| EPS（実績・会社予想）、BPS |
| PER・PBR の過去5〜10年の推移（年次の最高・最低・平均）と有報の期末PER（EV/EBITDA の過去推移はスクリプトが算出するので探さない） |
| アナリスト予想のEPS成長率（入手できる場合のみ） |

- 株価は**直近の確定終値**を使い、基準日を明記する（取引中の値は使わない）。競合の PER・PBR も同じ基準日の終値で計算し、計算式（株価 ÷ 直近通期の EPS、時価総額 ÷ 直近期末の自己資本 など）と使った期を書く
- 範囲「株価のみ」は、自社の valuation-data.md の **1章・3章**（株価・時価総額・株式数・株価指標）と、競合の competitors.md 6章（EPS・BPS の列を含む）を**同じ基準日**で書く（6章だけの差分ファイルでよい）。2章（EPS・BPS）は新しい決算・業績予想の修正があったときだけ書き、前回と同じ値を集計サイトの値で書き直さない（分析スクリプトは決算短信の値を優先し、2章は補い）。4・5章は変化があれば。バリュエーション分析は株価の基準日が7日より古いと、この範囲で取り直しを求める
- 期末後のコーポレートアクション（株式交換・自己株式の交付・消却など）で株式数が変わった可能性があり確定値が分からないときは、1章の「発行済株式数（自己株式を除く）」の値に「（…後は未確認）」と書き、「発行済株式数（自己株式を含む）」も必ず書く（分析スクリプトが上限の株式数でも EV/EBITDA を計算する）
- 米国株: 株価は Yahoo Finance チャート API（`source-access.md`。確度「二次」）、株式数は最新の 10-Q／10-K 表紙（種類株があれば全種類の合計と内訳）。上場から1年未満なら過去レンジは上場後だけ書き、目論見書のロックアップ解除日程を期末後のコーポレートアクションに書く
- EPS・BPS・株式数は、`data/tdnet_facts.csv` があれば読んでよい（読むだけ。collect-filings が同時に更新中でも、ファイルは原子的に置き換わるので壊れた状態は見えない）。無ければ最新の短信を自分で確認する
- **期末後のコーポレートアクション**（株式分割・株式交換・自己株式・新株予約権行使）をプレスリリース一覧（IRBANK 適時開示一覧など）で確認し、株式数・1株指標への影響を注記する

保存先: `raw/ir/{収集日}_valuation-data.md`（雛形 valuation-data.md）

## 報告
`.ai/templates/collect-company-info/agent-report.md` の形式で返答する。5章に主力事業の判定、競合の選定（選び直したか・前回のままか、その理由、選んだ会社）、株価の基準日、確認したコーポレートアクションを書く。
