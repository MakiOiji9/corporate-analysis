# 投資の神の視点（legendary-investors）

企業分析レポートに「投資の神の考え方に当てはめると、この会社はこう見える」という**参考の視点**を添えるための資料。
ウォーレン・バフェット、ジョージ・ソロス、ジム・ロジャーズの3人の投資哲学・手法・判断基準を、一次資料（本人の著書・株主への手紙・インタビュー）にもとづいて整理し、このリポジトリの分析結果（company-report の brief）のどの項目で確かめるかに対応させてある。

| ファイル | 人物 | ひと言で |
|---|---|---|
| [buffett.md](buffett.md) | ウォーレン・バフェット | 理解できる優れた事業を、妥当な価格で買い、長く持つ |
| [soros.md](soros.md) | ジョージ・ソロス | 市場の思い込みと現実のずれ（再帰性）が生むブームと破綻に乗り、誤りに気づいたらすぐ引く |
| [rogers.md](rogers.md) | ジム・ロジャーズ | 誰も見向きしない安いものを、需給を変える前向きな変化が見えたときに買い、何年も待つ |

---

## 1. 使い方（レポートを書くとき）

company-report（`/company-report`）に組み込み済み。

1. **評価はスクリプト**: prepare のとき `tools/report/cr_legends.py` が、各人の資料の「5. 対応表」と「6. 評価の型」の条件を facts.json に当てはめ、**好む / 避ける / 保留** と確かめた項目（値・○×不明）を決める。結果は facts.json の `legends`、レポート md の「5. 投資の神の視点（参考）」の表、brief の「投資の神の視点」の節に出る
2. **説明は LLM**: レポート md の 5.1〜5.3 の欄（FILL: `buffett` / `soros` / `rogers`）に、下の「3. 書き方の型」で2〜3文を書く。読むのは brief の「投資の神の視点」だけで、この資料は読まなくてよい
3. **build が確かめる**: 5章の表がスクリプトの評価と同じか、各欄が「〈名前〉の考え方に当てはめると: 〈評価〉」で始まるか、本人が売買する・評価したと書いていないか

- **スクリプトの判定（投資検討・ウォッチ・見送り・判定保留、STEP 1〜3）は変えない**。投資の神の視点は判定の点数に入らない参考情報で、判定と食い違ってもよい（食い違うときは、何を重く見るかが違うことを書く）
- 材料が無い項目は「不明」として扱い、推測で埋めない。満たすかどうか決められない項目が多ければ評価は **保留** になる
- **規則を変えるときは、この資料（5・6章）と `cr_legends.py` を両方直す**（テスト: `tools/report/tests/test_cr_legends.py`）

## 2. 3人の比較

| 観点 | バフェット | ソロス | ロジャーズ |
|---|---|---|---|
| 主な対象 | 個別企業（事業そのもの） | 市場全体・通貨・金利・業界のテーマ | 国・コモディティ・業界（個別企業はその手段） |
| 時間軸 | 超長期（できれば永久に保有） | 数ヶ月〜数年（ブームと破綻の局面） | 数年〜10年以上（大きな流れの転換） |
| 一番見るもの | モート・ROE・利益の質・経営者・安全域 | 市場の思い込み（期待）と現実（ファンダメンタルズ）のずれ、その自己強化 | 安さ（歴史的な安値圏・不人気）と、需給を変える前向きな変化 |
| 買う条件 | 理解できる事業で、長く続く競争優位があり、価格が本質的価値より十分に低い | 思い込みと現実が互いを強め合う流れが始まった（またはその逆回転が始まった） | 安く放置されていて、かつ供給不足・政策転換などの変化が起きている |
| 売る条件 | 原則として売らない。事業の経済性が恒久的に損なわれたとき・経営者を信頼できなくなったとき | 仮説が誤っていたと分かったとき（すぐ）。ずれが限界まで広がり反転したとき | 過熱して皆が熱狂したとき。前提の変化が終わったとき |
| リスク管理 | 理解できない事業に手を出さない・借金に頼らない・安全域 | 誤りを認めて損を小さく切る。確信があるときだけ大きく張る | 知っているものだけに投資し、好機が来るまで何もしない |
| このレポートの期間で近いもの | 長期（3年以上） | 短期〜中期（〜1年） | 中期〜長期（6ヶ月〜数年） |

3人の視点はぶつかることがある（例: バフェットは「モートの無い会社は避ける」が、ロジャーズは「不人気で安く、変化が起きているなら買う」）。**レポートでは食い違いをそのまま示す**。どちらが正しいかを決めない。

## 3. 書き方の型

```
〈人物〉の考え方に当てはめると: 〈好む / 避ける / 保留〉。
〈その人が重視する項目〉が〈brief の値〉で、〈その人の基準〉を〈満たす / 満たさない〉ため。
〈気にする点（逆の材料・材料なし）を1つ〉。
```

例（形の例。数値は架空）:

> バフェットの考え方に当てはめると: 避ける。ROE は10年平均 12.0% と高いが、モートは「なし」で、長く続く競争優位を数字で示せないため。安全性は良好で、借金に頼らない点は基準に合う。

## 4. してはいけないこと

- **本人が実際にこの企業をこう評価した、と書かない**。「バフェットなら買う」「ソロスは売る」ではなく「〜の考え方に当てはめると」と書く（本人の発言・保有を捏造しない）
- 投資の勧誘（「買うべき」「買い時」）、株価の予測（「〜円になる」）、「おそらく」「〜と思われる」を書かない（policy.md 禁止事項 1・2・6）
- 資料に載っていない言葉を本人の言葉として引用しない。引用は各資料の「本人の言葉」に載っているものだけを、出典つきで使う
- brief に無い数値・一般論で補わない（policy.md 禁止事項 7）
- 3人の評価を足し合わせて点数にしない（考え方の前提が違うため）

## 5. 資料の作り方と更新

- 作成: 2026-11-04。「本人の言葉」として英語の原文を載せているのは、原文（株主への手紙・講義録・インタビュー記事）で確かめたものだけ。原文を確かめられなかった考え方は「要旨」「根拠（二次資料）」と明記して載せ、本人の言葉としては引用しない。確認の方法は各資料の「8. 出典」を参照
- 本人の考えは時期によって変わる（バフェットの「シケモク投資」から「優れた事業」への転換など）。資料はその変化も「7. 誤解しやすい点・限界」に書いてある
- 対応表の項目は company-report の facts.json（`companies/{ticker}_{name}/reports/{日付}_company-report_facts.json`）の値と、brief の見出しに合わせてある。分析の json の構成が変わったら対応表と `cr_legends.py` も直す
