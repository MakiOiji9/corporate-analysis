# 企業分析レポート（company-report）

`企業分析フレームワーク.md` の **STEP 1〜3** を分析スキルで一気に実行し、その結果を1つの HTML レポートにまとめる。
レポートは投資のプロから初心者まで読む想定で、**短期（〜3ヶ月）・中期（6ヶ月〜1年）・長期（3年以上）**それぞれで投資を検討してよいかを判定し、根拠と株価の過去レンジ、テクニカル分析（今のチャートの状態と、押し目・利益確定・損切りの目安の価格）を載せる。成果物は次のとおり（`{日付}` は作成日）。

- `companies/{ticker}_{name}/reports/{日付}_company-report.html` — レポート本体（単一ファイル。オフラインで開ける）
- `.../{日付}_company-report.md` — レポートの文章（判定の表はスクリプト、文章は LLM）
- `.../{日付}_company-report.json` — 3期間の判定・STEP 1〜3・株価レンジの要約（機械可読）
- `.../{日付}_company-report_facts.json`・`_brief.md` — 数値・判定のすべてと執筆の材料（スクリプトが生成）
- `companies/{ticker}_{name}/data/prices.csv` — 日々の株価（分割調整済み、最大10年。`tools/collect/stock_prices.py`）

**分析の鮮度確認・STEP 1/2 の総合判定（A/B/C）・3期間の判定・株価レンジの計算・HTML の生成はすべてスクリプト（`tools/report/company_report.py`）が行う。**
LLM が受け持つのは、(1) 鮮度が新しくない分析スキルを順に実行すること、(2) レポート md の FILL 欄（3行まとめ・会社の説明・各期間の判定の説明・投資の理由・判断が崩れる条件・次に確かめること・投資の神の視点の説明・テクニカルの読み方）を書くことだけ。
投資の神の視点（バフェット・ソロス・ロジャーズの考え方に当てはめた 好む/保留/避ける）も、評価は `tools/report/cr_legends.py` が `.ai/knowledge/legendary-investors/` の条件で決める（判定の点数には入らない参考の視点）。
テクニカル分析（移動平均の並び・RSI・MACD・ボリンジャーバンド・出来高・支持線/抵抗線・ATR）は `tools/report/cr_technicals.py` が日々の株価から計算し、状態語・テクニカル点数（短期・中期の「株価のテクニカル」要素）・押し目/利益確定/損切りの目安の価格まで決める。目安の価格は「ここを下回ったら」と見る条件で、株価の予想でも推奨でもない。
手順は **企業の選択 → 鮮度確認とスキルの実行（繰り返し）→ 準備 → 執筆 → ビルド** に固定されている。

## 前提として読むファイル

## 引数

| 引数 | 内容 | 省略時 |
|---|---|---|
| `company` | 銘柄コード（`3798`）・企業ディレクトリ名（`3798_uls-group`）・社名の一部 | 手順 0 で選んでもらう |
| `redo` | 今日のレポートが build 済みでも作り直す（ユーザーが指示したときだけ。分析スキルの redo ではない。build 済みのレポートは `reports/_superseded/{日付}-{n}/` に退避され、prepare の返り値 `superseded` に出る） | なし |
| `use-existing` | 分析後に材料が変わった（`triggered`）分析を作り直さず、既存の結果でレポートを作る。期限切れ（`expired`）・未実施（`none`）・作成途中（`draft`）の分析はこれまでどおり実行する。既存の結果を使った分析はレポートの冒頭と8章に理由つきで明記される | なし（作り直す） |

## 実行手順

Python は `.venv` のものを使う（Windows: `.venv\Scripts\python.exe`、macOS/Linux: `.venv/bin/python`）。以下 `$PY` と書く。
各コマンドの標準出力は1行の JSON。

### 0. 企業の選択（`company` が無いときだけ）

```
$PY -I tools/report/company_report.py list
```

`companies` の各行（`dir`・`name`・`not_fresh`（鮮度が新しくない分析）・`report_date`・`report_state`）から選択肢を作り、ユーザーに選んでもらう（提示の方法はエントリーポイントの指示に従う）。
企業が1社だけなら選択肢を出さずにその企業で進み、完了報告の「材料」行に「対象は1社だけのため選択を省略」と書く。
一覧に無い企業を指定されたら、手順 1 の `company_missing` と同じ扱いにする。

### 1. 鮮度確認とスキルの実行（スクリプト ⇄ スキル）

```
$PY -I tools/report/company_report.py check --company {company} [--redo] [--use-existing]
```

`use-existing` の指示があるときは、check と prepare の両方に `--use-existing` を付ける（付けると `triggered` の分析は `next` に出ない）。

`steps` が9つの分析の状態（依存の順。`result` は各分析スクリプト自身の判定: `fresh` 有効 / `expired` 期限切れ / `triggered` 材料・上流が変わった / `draft` 作成途中 / `none` 未実施）。`next` に従う。

| `next` | すること |
|---|---|
| `ok: false` で `candidates` あり | 複数の企業が当たった。候補からユーザーに選んでもらい、もう一度 check |
| `ok: false` で `company_missing: true` | 企業の情報が無い。ユーザーにホームページ URL を確認し、collect-company-info を `mode=full` で実行してから check をやり直す |
| `five-forces` / `three-c` / `moat` / `swot` | その分析が新しくない。**そのスキルを引数 `{ticker}` で最後の完了報告まで実行**し、check をやり直す（各スキルが収集・上流の確認を自分で行う。上流の結論（C・懸念・判定保留）では止めない） |
| `profitability` / `growth` / `safety` / `cash-flow` / `valuation` | STEP 2・3 が新しくない。手順 1.5 の run でまとめて進める（スキルの手順書は読まない） |
| `market-report` | 地合い判断（outlook.md）が無いか古い（分析が使うのは35日以内、レポートの株価の動き・業種の比較は7日以内。`materials` の `market` 行）。market-report スキルを実行し（材料が古ければ market-report が collect-market-info を先に実行する）、check をやり直す |
| `collect-company-info` | レポートの材料（`materials`。直近3か月の開示・ニュース、アナリスト予想・株価指標）が古いか無い。**collect-company-info を `{ticker} mode=update 担当={collect.agents をカンマ区切り} 項目={collect.items をカンマ区切り}` で最後まで実行**し、check をやり直す |
| `prepare` | 9つの分析がすべて新しい。手順 2 へ |
| `write` | 今日のレポート md が作成途中（FILL が残っている）。手順 2 の prepare を実行してから（判定の表が最新になる）手順 3 の続きから書く |
| `build` | 今日のレポート md は書き終わっているが build されていない。手順 4 へ |
| `report_existing` | 今日のレポートは build 済み。完了報告の形式で既存の HTML を伝えて**終わる**。`redo` の指示があるときだけ `--redo` を付けて手順 2 へ |

- 実行の順は check が決める（five-forces → three-c → moat → swot → profitability → growth → safety → cash-flow → valuation）。上流を作り直すと下流が `triggered` になるので、**1つ実行するたびに check をやり直す**。複数のスキルをまとめて実行しない（STEP 1 の4つ。STEP 2・3 の5つは手順 1.5 の run が依存の順に進める）
- 鮮度が新しい（`fresh`）分析は実行しない（スキップ）。分析スキルの `redo` は使わない
- **同じスキルは1回の実行につき1回まで**。実行し終えたのに check でまだ同じスキルが `next` に出たら、もう一度は実行せず、そのスキルの `reason` を添えて止まり、ユーザーに報告する（材料の取り直し・作り直しはユーザーの判断）
- 分析スキルが止まった（ユーザーへの確認待ち・エラー）ときは、このコマンドも止めて状況を報告する
- check と prepare を1つのコマンドにつなげない（check の `next` を見てから次へ進む）。prepare も鮮度を確かめ、新しくない分析があれば `ok: false` で拒否する
- 材料の収集（`collect-company-info` / 材料による `market-report`）も1回の実行で1回まで。実行したのにまだ同じ `next` が出たら、check・run・prepare に **`--use-stale`** を付けて進み（レポートに「古い材料」と基準日が出る）、完了報告の「警告」行に古い材料と `why` を書く
- `materials` の基準日は完了報告の「材料」行に「材料の基準日: …」として書く

### 1.5 STEP 2・3 の一括実行（スクリプト ⇄ 執筆）

```
$PY -I tools/report/company_report.py run --company {company} [--use-existing]
```

run は、profitability → growth → safety → cash-flow → valuation のうち新しくない分析を、スクリプトで進められるところまで進めて止まる（依存: cash-flow は収益性・成長性・安全性の後、valuation は STEP 2 の4つの後）。書き手の JSON があれば流し込んで build し、依存がそろった分析を prepare し、valuation の不足が株価だけなら `tools/collect/refresh_valuation.py` で株価を取り直す（エージェントなし）。`next` に従い、run をやり直す。

| `next` | すること |
|---|---|
| `write` | `write` の各分析について、`brief` を読み、`fill_spec`（書く欄のキー・指示・表のセルか）と `rules`（md 冒頭の書き方の規則）に従って本文を書き、`{"FILL のキー": "本文"}` の JSON を `fills_json` に Write する。全部書いたら run をやり直す（流し込み・build・次の分析の prepare は run が行う）。`warnings` は完了報告の「警告」行に書く |
| `collect` | `collect` の分析は材料が足りない（`missing_inputs`）。その分析のスキルを最後まで実行し（スキルが収集から build まで行う）、run をやり直す。valuation で `fallback` があるのは株価の取り直しに失敗したとき（collect-company-info の「株価のみ」で取り直す） |
| `fix` | `errors` の分析は JSON のキーが違う、または build の指摘がある。指摘の箇所だけを直し（JSON を作り直すか md を Edit する）、run をやり直す（2回まで。残れば未完了として報告する） |
| `five-forces` などの STEP 1 のスキル | STEP 1 が新しくない。手順 1 の表のとおりスキルを実行する |
| `prepare` / `market-report` / `collect-company-info` ほか | STEP 2・3 はすべて新しい。手順 1 の表の同じ語の行に戻る（`collect-company-info` の引数は `collect_request`） |

- brief の「（… の「### 見出し」と同じ内容のため省略。…）」は、同じ日のほかの分析の brief にある節。この実行で読んでいればその内容を使い、読んでいなければその節だけを読む
- 書く本文の規則は各分析のスキルと同じ（数値は brief にあるものだけ、分からない背景は「不明（brief に記載なし）」、推測で埋めない、「おそらく」「〜と思われる」・投資の勧誘を書かない）。前回からの変更点・欠損・引き継ぎの定型の欄はスクリプトが記入済みなので書かない
- `price_refreshed` に株価の基準日が出たら、完了報告の「材料」行に「株価のみスクリプトで更新（基準日 {base_date}）」と書く
- 同じ分析が2回続けて `collect` に出たら、もう一度は収集せず、その分析のスキルを `--skip-collect` 付きの手順で進める（スキルの手順書に従う）

### 2. 準備（スクリプト）

```
$PY -I tools/report/company_report.py prepare --company {company} [--redo] [--use-existing] [--skip-market-report]
```

- 株価を取得して `data/prices.csv` を更新し（`prices.ok`。取れなければ raw の年次の高値・安値表で代える: `price_source: fallback`）、判定をすべて計算して facts.json・brief.md・md の骨組みを作る
- 返り値の `step1`・`step2`・`step3`・`horizons`（3期間の判定）が結論。build まで変わらない
- `fill_keys` が書く欄の一覧
- 作成途中の md（FILL が残っている）は文章を残し、1章の判定の表だけを最新の判定に置き換える（`kept: true`）
- `--skip-market-report` は、market-report を実行しても地合い判断を作れなかったときだけ使う（brief に「地合い判断が古い」と出る）
- `prices.ok: false` は完了報告の「警告」行に書く（株価の取得を再試行しない）
- `used_existing` は作り直さずに使った分析。完了報告の「スキップした分析」に「既存の結果を使用（材料が変わった）」として書く

### 3. 執筆（LLM）

brief.md を読み、prepare の返り値 `fill_spec`（書く欄のキーと指示）に従って本文を書く。

- 書いた本文は `{"FILL のキー": "本文"}` の JSON 1つにまとめて、返り値の `fills_json`（`reports/{日付}_fills.json`）に Write し、`$PY -I tools/report/company_report.py fill --company {company} --build` で流し込んで build する（FILL が残っていれば build せず `remaining` を返す）。md の FILL を Edit で置き換えてもよい
- `break`（4.2）と `watch`（4.3）は、brief「5.1〜5.3」の候補と「6. 材料不足」から2行以上作れるときは prepare がスクリプトで記入済みで、`fill_keys` に出ない（書き直さない）

- 読むのは brief.md だけ（md は build の指摘を直すときだけ開く）。raw・分析の md・CSV を個別に開かない（必要なことは brief.md に集約済み）
- 書く順番（`fill_keys` にあるものだけ）: `summary` → `about` → `short` → `mid` → `long` → `thesis` → `break` → `watch` → `buffett` → `soros` → `rogers` → `technical`
- 書き方の規則は md 冒頭の `>` 行と各 FILL の指示に従う。要点:
  - **読み手は初心者からプロまで**。専門用語は使ってよいが、初めて出るところで「（＝…）」と言い換える。1文を短く、結論を先に書く
  - 各期間の説明は**判定語から書き始め**（build が確かめる）、brief「3. 期間ごとの判定」の**良い点・悪い点から寄与の大きいものを1つ以上ずつ**、要素名と値を添えて説明する（build が要素名の有無を確かめる）。点数表に無い理由を足さない
  - 長期の説明の最後に、フレームワークの判定マトリクス（参考）の結果を1文で添える
  - 「保守的に判定（材料不足）」の分析があれば、何が不明でどう倒したかに触れる
  - 投資の理由はフレームワークの型（「〈勝てる理由〉があり、〈STEP 2 の数字〉で裏付けられている。現在の株価は〈STEP 3 の根拠〉で割安/妥当」）。長期が投資検討でなければ、見送り・ウォッチの理由と、判定が上がる数字の条件を書く
  - 判断が変わる条件（4.2）は、各行の先頭に【改善】（判定が上がる条件）か【悪化】（判定が下がる条件）を付け、数値の閾値つきで書く（build が先頭の語を確かめる。brief「5.1〜5.3」の候補から選んでよい）。見送り・ウォッチなら【改善】を先に、投資検討なら【悪化】を先に書く。次に確かめることは、いつ・何で確かめるかを書く
  - 短期・中期の説明では、brief「直近の材料」から52週高値からの下落（上昇）と良い材料（受注・進捗など）にも触れ、悪い材料だけを並べない。点数が境目に近いとき（brief「最も近い境目」が ±0.10 以内）はそのことを書く（判定が1段階動きうることを読み手に伝える）
  - 同業との比較は、brief に中央値があれば「同業平均 〇%（中央値 〇%）」と並べて書く（平均は飛び抜けた1社に引っ張られる）
  - 数値は brief にあるものだけを使う。新しく計算しない。分からないことは「不明」と書き、良い方に解釈しない
  - 地合いが警戒のときは、短期・中期の説明でそのことに触れる（policy.md 行動指針10）
  - 投資の神の視点（5.1〜5.3）は brief「投資の神の視点」だけを見て書く。各欄は「〈名前〉の考え方に当てはめると: 〈評価〉。」で書き始め（build が確かめる）、表の項目から決め手を1つ以上、値を添えて書き、逆の材料か不明の項目を1つ添える。評価（好む・保留・避ける）と5章の表は変えない。本人が実際にこの会社を売買する・評価したとは書かない（「〜なら買う」も build が検出する）。`.ai/knowledge/legendary-investors/` の資料は読まなくてよい
  - テクニカルの読み方（6.1）は brief「4.1 テクニカル」だけを見て書く。「今の状態は〈状態〉。」で書き始め（build が状態語を確かめる）、決め手の指標を値と一緒に1つ以上書く。押し目・利益確定・損切りの目安は表の価格を使い、「〜を下回ったら」「〜に近づいたら」の**条件形**で書く。到達の予想（「〜円まで上がる」）は build が検出する。brief に「長期の判定との関係」があれば必ず触れる（テクニカルは値動きの参考で、事業・財務の判定は変えない）。短期・中期の説明で「株価のテクニカル」が良い点・悪い点に出たら、状態語と値を添える
- 1章の判定の表・見出し・ヘッダーは変えない。ファイルを丸ごと書き直さない（Write は hook がブロックする）

#### 判定の規則（企業分析フレームワーク.md の転記。判定はすべてスクリプト）

| 判定 | 規則 |
|---|---|
| STEP 1 総合 | **A**: 業界の魅力度 中以上 かつ 勝てる理由 明確 かつ モート 広い かつ SWOT Yes / **C**: 勝てる理由 なし または SWOT No / **B**: それ以外。勝てる理由・SWOT が判定保留なら確定しない（暫定 B。A にも C にもしない） |
| STEP 2 総合 | 良好 +1・普通 0・懸念 −1 の平均。**A**: +0.5 以上で整合性チェック（モート 広い なのに営業利益率が同業平均以下、勝てる理由 明確 なのに収益性 懸念）に食い違いなし / **C**: −0.25 以下、懸念が2つ以上、または深刻な赤信号（営業CF のマイナスが続く・FCF の累計がマイナス・安全性が懸念で悪化傾向） / **B**: それ以外 |
| STEP 3 | 4指標の平均点で 割安/妥当/割高。最終確認では判定を変えず「割安だが理由あり」と注記する（STEP 2 の懸念を二重に減点しない） |
| 期間ごとの判定 | 各要素を +1・0・−1 にして期間ごとの重みで平均（`tools/report/cr_judge.py` の WEIGHTS）。**+0.3 以上 投資検討 / −0.2 以下 見送り / その間 ウォッチ**。短期は 地合い25・株価のテクニカル25・決算の進捗20・割安さ20・安全性10、中期は 割安さ20・成長性15・決算の進捗15・収益性10・CF10・地合い10・株価のテクニカル10・安全性5・SWOT5、長期は 3C15・モート15・割安さ15・業界10・成長性10・収益性10・CF10・地合い5・安全性5・SWOT5 |
| 足切り | 深刻な赤信号は全期間 見送り。STEP 1 が C なら長期だけ 見送り。短期・中期は長期に縛られない |
| 良い点・悪い点 | 点数を押し上げた要素が良い点、押し下げた要素が悪い点（寄与の大きい順）。材料が無い要素は点数から外す。判定保留の分析は 0 点 |
| 長期の参考 | フレームワークの判定マトリクス（STEP 1×2×3）の結果を併記する |
| 投資の神の視点 | `.ai/knowledge/legendary-investors/{buffett,soros,rogers}.md` の6章の条件で 好む/保留/避ける（`cr_legends.py`）。避ける → 好む → 保留 の順に確かめる。期間ごとの判定の点数には入らない |
| 株価のテクニカル | `cr_technicals.py`。トレンド（株価 > 13週線 > 26週線 > 52週線 かつ26週線が上向き +1、逆 −1）・勢い（RSI(14) 30 以下 +1・70 以上 −1、MACD のヒストグラムの向きで ±0.5）・位置（52週レンジ 33% 以下 +1・67% 以上 −1、26週線との差 ±15% 超 −1）の平均。状態語は対応表で決める。出来高・ボリンジャーバンドは表示だけ |
| 需給（参考） | `cr_positioning.py` が `raw/market/*_positioning.md`（collect-peers-valuation が公開ページから集めた週次の信用残・空売り）を brief「4.1 テクニカル」と HTML に表示する。信用倍率5倍超・1倍未満、空売りが浮動株の10%超・買い戻し5日超を注目点として出す。点数には入れない |
| 売買の目安（参考） | 押し目＝株価より下の 26週線・52週線・直近の安値・52週安値（近い順に2つ）、利益確定＝株価より上の直近の高値・52週高値・ボリンジャー +2σ（近い順に2つ）、損切り＝最も近い支持線の 1 ATR 下（52週安値が支持線でなければ52週安値より下にはしない）。条件の目安で、予想でも推奨でもない |

### 4. ビルド（スクリプト）

```
$PY -I tools/report/company_report.py build --company {company}
```

- `ok: true` → HTML と json を作る。返り値の `html`・`horizons`・`step1`〜`step3`・`warnings`（文字数の目安超え）を完了報告に使う。`warnings` があれば該当の欄を短く直して build し直してよい（1回まで）
- `ok: false` → `issues` の指摘箇所だけを Edit で直し、もう一度 build（2回まで。それでも残れば未完了として、指摘をそのまま報告する）

---

## してはいけないこと

- 分析スキルを check の `next` 以外の順で実行しない。`fresh` の分析を作り直さない。同じスキルを1回の実行で2回動かさない
- スクリプトが作るファイル（facts.json・brief.md・json・HTML・data/prices.csv）と、md の1章の判定の表・5章の投資の神の表・6章のテクニカルの表を手で直さない
- 判定（投資検討・ウォッチ・見送り・判定保留）を文章で言い換えたり、表と違う判定を書いたりしない
- 投資の勧誘・推奨（「買うべき」「買い時」など）、将来の株価の予測（「〜円になる」）、「おそらく」「〜と思われる」を書かない（build が検出する）
- 書く欄に内部の言葉（「手順N」・brief・FILL・ファイル名やパス・収集エージェントの名前・判断の迷いのメモ）を書かない。レポートだけを読む人に通じる言葉（確かめた中身・資料の名前）に言い換える。スクリプトの文も表示の前に言い換えるが、残っていれば build が止まる
- 執筆のために追加の web 検索・raw の閲覧・数値の手計算をしない
- 過去の日付の完成済みレポートを変更しない（hook がブロックする）

※ グローバル設定の hook（Fact-Forcing Gate）が、最初の Bash と、ファイルごとの最初の Edit を一度差し戻すことがある。求められた事実を示して同じ操作を再実行すれば通る。

## 完了報告（ユーザー向け）

check・prepare・build の JSON（実行したスキルはその完了報告も）だけを使い、次の形式で短く報告する。

```
## 企業分析レポート — {name}
- レポート: {html}（文章: {md}、機械可読: {json}）
- 判定（{date} 時点。投資の勧誘ではなく、株価の予測でもない）
  - 短期（〜3ヶ月）: {horizons.short}
  - 中期（6ヶ月〜1年）: {horizons.mid}
  - 長期（3年以上）: {horizons.long}
- STEP 1: {step1} / STEP 2: {step2} / STEP 3: {step3}
- 投資の神の視点（参考）: バフェット {legends.buffett} / ソロス {legends.soros} / ロジャーズ {legends.rogers}
- テクニカル（参考）: {technical.state}（点数 {technical.score}）。目安の価格はレポート6章
- 実行した分析: {今回実行したスキルと結論。無ければ「なし（すべて有効期間内）」}
- スキップした分析: {fresh だったスキルと分析日}
- 株価: {prices の取得結果（期間・行数）。fallback ならその旨}
- 地合い: {outlook のパスと注意の度合い。古ければその旨}
- 材料: {1社のため選択を省略したならその旨。分析スキルが収集した内容の要点}
- 削除した古いファイル: {build と分析スキルの `pruned` の件数（直近と1つ前だけを残す）。無ければ「なし」}
- 警告: {prices の取得失敗・build の warnings。無ければ「なし」}
```

今日のレポートが build 済みで作り直さなかった場合は、check の `report.md` と同じ日付の HTML（`{日付}_company-report.html`）のパスと「今日のレポートは作成済み（作り直す場合は redo を指示）」だけを書く。
