# 企業分析レポート（company-report）

`企業分析フレームワーク.md` の **STEP 1〜3** を分析スキルで一気に実行し、その結果を1つの HTML レポートにまとめる。
レポートは投資のプロから初心者まで読む想定で、**短期（〜3ヶ月）・中期（6ヶ月〜1年）・長期（3年以上）**それぞれで投資を検討してよいかを判定し、根拠と株価の過去レンジを載せる。成果物は次のとおり（`{日付}` は作成日）。

- `companies/{ticker}_{name}/reports/{日付}_company-report.html` — レポート本体（単一ファイル。オフラインで開ける）
- `.../{日付}_company-report.md` — レポートの文章（判定の表はスクリプト、文章は LLM）
- `.../{日付}_company-report.json` — 3期間の判定・STEP 1〜3・株価レンジの要約（機械可読）
- `.../{日付}_company-report_facts.json`・`_brief.md` — 数値・判定のすべてと執筆の材料（スクリプトが生成）
- `companies/{ticker}_{name}/data/prices.csv` — 日々の株価（分割調整済み、最大10年。`tools/collect/stock_prices.py`）

**分析の鮮度確認・STEP 1/2 の総合判定（A/B/C）・3期間の判定・株価レンジの計算・HTML の生成はすべてスクリプト（`tools/report/company_report.py`）が行う。**
LLM が受け持つのは、(1) 鮮度が新しくない分析スキルを順に実行すること、(2) レポート md の FILL 欄（3行まとめ・会社の説明・各期間の判定の説明・投資の理由・判断が崩れる条件・次に確かめること）を書くことだけ。
手順は **企業の選択 → 鮮度確認とスキルの実行（繰り返し）→ 準備 → 執筆 → ビルド** に固定されている。

---

## 前提として読むファイル

- `.ai/instructions/role.md`
- `.ai/instructions/policy.md`
- `.ai/instructions/output-format.md`

`企業分析フレームワーク.md` は読まなくてよい（判定の規則は下に転記してある）。各分析スキルの手順書は、そのスキルを実行するときにだけ読む。

---

## 引数

| 引数 | 内容 | 省略時 |
|---|---|---|
| `company` | 銘柄コード（`3798`）・企業ディレクトリ名（`3798_uls-group`）・社名の一部 | 手順 0 で選んでもらう |
| `redo` | 今日のレポートが build 済みでも作り直す（ユーザーが指示したときだけ。分析スキルの redo ではない） | なし |

## 実行手順

Python は `.venv` のものを使う（Windows: `.venv\Scripts\python.exe`、macOS/Linux: `.venv/bin/python`）。以下 `$PY` と書く。
各コマンドの標準出力は1行の JSON。

### 0. 企業の選択（`company` が無いときだけ）

```
$PY -I tools/report/company_report.py list
```

`companies` の各行（`dir`・`name`・`not_fresh`（鮮度が新しくない分析）・`report_date`・`report_state`）から選択肢を作り、ユーザーに選んでもらう（提示の方法はエントリーポイントの指示に従う）。
企業が1社だけなら選択肢を出さずにその企業で進み、完了報告の「材料」行に「対象は1社だけのため選択を省略」と書く。
一覧に無い企業を指定されたら、手順 1 の `company_missing` と同じ扱いにする。

### 1. 鮮度確認とスキルの実行（スクリプト ⇄ スキル）

```
$PY -I tools/report/company_report.py check --company {company} [--redo]
```

`steps` が9つの分析の状態（依存の順。`result` は各分析スクリプト自身の判定: `fresh` 有効 / `expired` 期限切れ / `triggered` 材料・上流が変わった / `draft` 作成途中 / `none` 未実施）。`next` に従う。

| `next` | すること |
|---|---|
| `ok: false` で `candidates` あり | 複数の企業が当たった。候補からユーザーに選んでもらい、もう一度 check |
| `ok: false` で `company_missing: true` | 企業の情報が無い。ユーザーにホームページ URL を確認し、collect-company-info を `mode=full` で実行してから check をやり直す |
| `five-forces` / `three-c` / `moat` / `swot` / `profitability` / `growth` / `safety` / `cash-flow` / `valuation` | その分析が新しくない。**そのスキルを引数 `{ticker}` で最後の完了報告まで実行**し、check をやり直す（各スキルが収集・上流の確認を自分で行う。上流の結論（C・懸念・判定保留）では止めない） |
| `market-report` | 地合い判断（outlook.md）が無いか35日より古い（短期・中期の判定に使う）。market-report スキルを実行し、check をやり直す |
| `prepare` | 9つの分析がすべて新しい。手順 2 へ |
| `write` | 今日のレポート md が作成途中（FILL が残っている）。手順 2 の prepare を実行してから（判定の表が最新になる）手順 3 の続きから書く |
| `build` | 今日のレポート md は書き終わっているが build されていない。手順 4 へ |
| `report_existing` | 今日のレポートは build 済み。完了報告の形式で既存の HTML を伝えて**終わる**。`redo` の指示があるときだけ `--redo` を付けて手順 2 へ |

- 実行の順は check が決める（five-forces → three-c → moat → swot → profitability → growth → safety → cash-flow → valuation）。上流を作り直すと下流が `triggered` になるので、**1つ実行するたびに check をやり直す**。複数のスキルをまとめて実行しない
- 鮮度が新しい（`fresh`）分析は実行しない（スキップ）。分析スキルの `redo` は使わない
- **同じスキルは1回の実行につき1回まで**。実行し終えたのに check でまだ同じスキルが `next` に出たら、もう一度は実行せず、そのスキルの `reason` を添えて止まり、ユーザーに報告する（材料の取り直し・作り直しはユーザーの判断）
- 分析スキルが止まった（ユーザーへの確認待ち・エラー）ときは、このコマンドも止めて状況を報告する
- check と prepare を1つのコマンドにつなげない（check の `next` を見てから次へ進む）。prepare も鮮度を確かめ、新しくない分析があれば `ok: false` で拒否する

### 2. 準備（スクリプト）

```
$PY -I tools/report/company_report.py prepare --company {company} [--redo] [--skip-market-report]
```

- 株価を取得して `data/prices.csv` を更新し（`prices.ok`。取れなければ raw の年次の高値・安値表で代える: `price_source: fallback`）、判定をすべて計算して facts.json・brief.md・md の骨組みを作る
- 返り値の `step1`・`step2`・`step3`・`horizons`（3期間の判定）が結論。build まで変わらない
- `fill_keys` が書く欄の一覧
- 作成途中の md（FILL が残っている）は文章を残し、1章の判定の表だけを最新の判定に置き換える（`kept: true`）
- `--skip-market-report` は、market-report を実行しても地合い判断を作れなかったときだけ使う（brief に「地合い判断が古い」と出る）
- `prices.ok: false` は完了報告の「警告」行に書く（株価の取得を再試行しない）

### 3. 執筆（LLM）

brief.md を読み、company-report.md の `<!-- FILL:... -->` を Edit で置き換える。

- 読むのは brief.md と company-report.md だけ。raw・分析の md・CSV を個別に開かない（必要なことは brief.md に集約済み）
- 書く順番と Edit の単位（各1回）: `summary` → `about` → `short` → `mid` → `long` → `thesis` → `break` → `watch`
- 書き方の規則は md 冒頭の `>` 行と各 FILL の指示に従う。要点:
  - **読み手は初心者からプロまで**。専門用語は使ってよいが、初めて出るところで「（＝…）」と言い換える。1文を短く、結論を先に書く
  - 各期間の説明は**判定語から書き始め**（build が確かめる）、brief「3. 期間ごとの判定」の条件表のうち判定を決めた行を、値と一緒に説明する。条件表に無い理由を足さない
  - 長期の説明は、STEP 1・2・3 の結論が判定マトリクスでどう組み合わさったかを書く（例: STEP 2 が C なので株価にかかわらず見送り）
  - 判定保留（暫定あり）のときは、何の材料が足りないか（brief「6. 材料不足」）と暫定の判定を書く
  - 投資の理由はフレームワークの型（「〈勝てる理由〉があり、〈STEP 2 の数字〉で裏付けられている。現在の株価は〈STEP 3 の根拠〉で割安/妥当」）。長期が投資検討でなければ、見送り・ウォッチの理由と、判定が上がる数字の条件を書く
  - 判断が崩れる条件は数値の閾値つきで（brief「5.」の候補から選んでよい）。次に確かめることは、いつ・何で確かめるかを書く
  - 数値は brief にあるものだけを使う。新しく計算しない。分からないことは「不明」と書き、良い方に解釈しない
  - 地合いが警戒のときは、短期・中期の説明でそのことに触れる（policy.md 行動指針10）
- 1章の判定の表・見出し・ヘッダーは変えない。ファイルを丸ごと書き直さない（Write は hook がブロックする）

#### 判定の規則（企業分析フレームワーク.md の転記。判定はすべてスクリプト）

| 判定 | 規則 |
|---|---|
| STEP 1 総合 | **A**: 業界の魅力度 中以上 かつ 勝てる理由 明確 かつ モート 広い かつ SWOT Yes / **C**: 勝てる理由 なし または SWOT No / **B**: それ以外。勝てる理由・SWOT が判定保留なら確定しない（暫定 B。A にも C にもしない） |
| STEP 2 総合 | **A**: 4項目すべて良好、または良好3つ＋普通1つで、STEP 1 との整合性チェック（モート 広い なのに営業利益率が同業平均以下、勝てる理由 明確 なのに収益性 懸念）に食い違いなし / **C**: 懸念が2つ以上、またはキャッシュフローが懸念 / **B**: それ以外（判定保留・未実施を含めば暫定） |
| 長期（3年以上） | 判定マトリクス: STEP 1・2 とも A → 割安 投資検討 / 妥当 投資検討（分割購入など）/ 割高 ウォッチ。B を含む（C なし）→ 割安 投資検討（割安の理由を精査）/ 妥当 ウォッチ / 割高 見送り。C を含む → 見送り。STEP 3 が判定保留ならウォッチ以下の暫定 |
| 中期（6ヶ月〜1年） | 長期の判定から、次のどれかを満たさない（不明を含む）と1段下げる: 直近四半期の営業利益の進捗率が前年同期（無ければ標準ペース）の90%以上、地合いの中期が警戒でない、会社計画が信頼できるか株価が割高でない |
| 短期（〜3ヶ月） | 長期が見送り、または地合いの短期が警戒で株価が52週レンジの上位1/3（67%以上）→ 見送り。長期が投資検討で、地合いの短期が警戒でなく、株価が52週レンジの上位1/3になく、26週移動平均を15%より大きく上回っていない → 投資検討。それ以外 → ウォッチ |
| 共通 | 短期・中期は長期より良い判定にしない（迷ったら低い方）。判定保留を含む判定は「判定保留（暫定: …）」 |

### 4. ビルド（スクリプト）

```
$PY -I tools/report/company_report.py build --company {company}
```

- `ok: true` → HTML と json を作る。返り値の `html`・`horizons`・`step1`〜`step3`・`warnings`（文字数の目安超え）を完了報告に使う。`warnings` があれば該当の欄を短く直して build し直してよい（1回まで）
- `ok: false` → `issues` の指摘箇所だけを Edit で直し、もう一度 build（2回まで。それでも残れば未完了として、指摘をそのまま報告する）

---

## してはいけないこと

- 分析スキルを check の `next` 以外の順で実行しない。`fresh` の分析を作り直さない。同じスキルを1回の実行で2回動かさない
- スクリプトが作るファイル（facts.json・brief.md・json・HTML・data/prices.csv）と、md の1章の判定の表を手で直さない
- 判定（投資検討・ウォッチ・見送り・判定保留）を文章で言い換えたり、表と違う判定を書いたりしない
- 投資の勧誘・推奨（「買うべき」「買い時」など）、将来の株価の予測（「〜円になる」）、「おそらく」「〜と思われる」を書かない（build が検出する）
- 執筆のために追加の web 検索・raw の閲覧・数値の手計算をしない
- 過去の日付の完成済みレポートを変更しない（hook がブロックする）

※ グローバル設定の hook（Fact-Forcing Gate）が、最初の Bash と、ファイルごとの最初の Edit を一度差し戻すことがある。求められた事実を示して同じ操作を再実行すれば通る。

## 完了報告（ユーザー向け）

check・prepare・build の JSON（実行したスキルはその完了報告も）だけを使い、次の形式で短く報告する。

```
## 企業分析レポート — {name}
- レポート: {html}（文章: {md}、機械可読: {json}）
- 判定（{date} 時点。投資の勧誘ではなく、株価の予測でもない）
  - 短期（〜3ヶ月）: {horizons.short}
  - 中期（6ヶ月〜1年）: {horizons.mid}
  - 長期（3年以上）: {horizons.long}
- STEP 1: {step1} / STEP 2: {step2} / STEP 3: {step3}
- 実行した分析: {今回実行したスキルと結論。無ければ「なし（すべて有効期間内）」}
- スキップした分析: {fresh だったスキルと分析日}
- 株価: {prices の取得結果（期間・行数）。fallback ならその旨}
- 地合い: {outlook のパスと注意の度合い。古ければその旨}
- 材料: {1社のため選択を省略したならその旨。分析スキルが収集した内容の要点}
- 警告: {prices の取得失敗・build の warnings。無ければ「なし」}
```

今日のレポートが build 済みで作り直さなかった場合は、check の `report.md` と同じ日付の HTML（`{日付}_company-report.html`）のパスと「今日のレポートは作成済み（作り直す場合は redo を指示）」だけを書く。
