# キャッシュフロー分析スキル（cash-flow）

`企業分析フレームワーク.md` の **STEP 2-4 キャッシュフロー分析**（利益が実際に現金として入ってきているか（利益の質）。キャッシュフロー 良好 / 普通 / 懸念。材料不足なら 判定保留）を、
collect-company-info が集めた財務時系列・有報の材料から行う。成果物は次の3つ。

- `companies/{ticker}_{name}/analysis/cash-flow/{日付}_cash-flow.md` — 分析結果。企業分析レポート・STEP 2 判定はこれ（と json）を参照する
- `.../{日付}_cash-flow.json` — 同じ結果の機械可読版（年次の CF 表・手順1〜5の判定と数値・成長投資期の確認・運転資本の増加率・CF パターン・株主還元と FCF・収益性分析との関係・引き継ぎ・有効期限）
- `.../{日付}_brief.md` — 執筆の材料（数値の要点と、数値の背景になる raw の節の抜粋）

`{日付}` は分析日。結果は **200日有効**で、期間内は再実行しても既存の結果を返すだけにする。
ただし期限前でも、新しい中間・本決算の決算短信が出たとき、または収益性・成長性・安全性の結論が変わったときは再分析する。競合・株価・事業概要の取り直しや、同じ期の数値の訂正だけでは再分析しない（有効期限を待つ）。上流の分析は作り直されても結論が同じなら再分析しない（`tools/analysis/freshness.py`）。

**数値の抽出・FCF と比率の計算・手順1〜6の判定・収益性分析との関係はすべてスクリプト（`tools/analysis/cash_flow.py`）が行う。**
LLM が受け持つのは cash-flow.md の FILL 欄（数値の背景と解釈・引き継ぎ）だけ。手順は **企業の選択 → 鮮度確認 → 準備 → 執筆 → ビルド** に固定されている。

同業比較は使わない（2-4 は自社の数値だけで判定する）。STEP 1（five-forces / three-c / moat / swot）も前提にしない。
STEP 2 の他の分析（収益性 profitability・成長性 growth・安全性 safety）の結果があれば 7章の関係チェックに使い、無ければ「未実施」と記録する（それらのスキルは実行しない）。
地合い（outlook.md）は md のヘッダーで参照するだけで、キャッシュフローの判定には使わない。古くても market-report・collect-market-info は実行しない。

## 実行手順

Python は `.venv` のものを使う（Windows: `.venv\Scripts\python.exe`、macOS/Linux: `.venv/bin/python`）。以下 `$PY` と書く。
各コマンドの標準出力は1行の JSON。

### 0. 企業の選択（`company` が無いときだけ）

```
$PY -I tools/analysis/cash_flow.py list
```

`companies` の各行（`dir`・`name`・`last_collected`・`cash_flow`・`cash_flow_date`・`verdict`・`profitability`・`growth`・`safety`）から選択肢を作り、ユーザーに選んでもらう（提示の方法はエントリーポイントの指示に従う）。
企業が1社だけなら選択肢を出さずにその企業で進み、完了報告の「材料」行に「対象は1社だけのため選択を省略」と書く。
選択肢には `cash_flow` の状態（`none` 未分析 / `fresh` 有効 / `expired` 期限切れ / `triggered` 材料・数値・収益性分析が変わった / `draft` 作成途中）と、収益性分析の結論（無ければ「未実施」）を添える。
一覧に無い企業を指定されたら、手順 1 の `company_missing` と同じ扱いにする。

### 1. 鮮度確認（スクリプト）

```
$PY -I tools/analysis/cash_flow.py check --company {company}
```

`next` に従う。

| `next`・状態 | すること |
|---|---|
| `ok: false` で `candidates` あり | 複数の企業が当たった。候補からユーザーに選んでもらい、もう一度 check |
| `ok: false` で `company_missing: true` | 企業の情報が無い。ユーザーにホームページ URL を確認し、collect-company-info を `mode=full` で実行してから check をやり直す |
| `report_existing`（`result: fresh`） | 有効期間内。`latest`（md・結論・有効期限）を完了報告の形式で伝えて**終わる**（執筆しない）。`redo` の指示があるときだけ手順 2 へ |
| `collect` で `needs_full_collect: true` | raw が無い。collect-company-info を `mode=full` で実行し、check をやり直す |
| `collect` | 材料が足りない。collect-company-info を `mode=update` で実行し、`missing_inputs` の担当（`agent`）と項目（`items`）を範囲として伝える。終わったら check をやり直す。主な項目: 自社の営業CF・投資CF・財務CF・当期純利益が5年未満（collect-filings「財務時系列: 営業CF・投資CF・財務CF・当期純利益（5年以上）」）、配当金の支払額・自己株式の取得が無い（collect-filings「財務時系列: 株主還元」）、手順3が懸念で純利益と営業CF の差の内訳が無い年がある（collect-filings「有報: 連結CF計算書の営業活動の内訳」。懸念の原因を示すための収集） |
| `prepare`（`none` / `expired` / `triggered` / `draft`） | 手順 2 へ |

- 収集（collect-company-info）は**1回の実行につき1回まで**。やり直した check でまだ `collect` が出ても、もう一度は収集せず手順 2 に `--skip-collect` を付けて進む（判定できない手順はスクリプトが「判定できない」として扱い、結論が 判定保留 になることがある。10章に書く）
- check と prepare を1つのコマンドにつなげない（check の `next` を見てから次へ進む）。prepare も `next` を確かめ、`collect` のままなら `ok: false` で拒否する
- `unavailable` は「収集を試みたが取れなかった」材料（status.md の未取得項目。上場からの年数が短く5年に届かない場合など）。再収集しない
- 収集スキルが止まった（ユーザーへの確認待ち・エラー）ときは、このスキルも止めて状況を報告する

#### 収集を依頼するとき

collect-company-info には `missing_inputs` の担当・項目だけを渡す。担当へのプロンプトに載せる原本の場所・同じ日の raw の扱いは、collect-company-info.md の mode=update の手順（分析スキルからの依頼）に従う。終わったら collect-company-info の集約（status.md・overview.md・summaries）まで済ませてから check に戻る。

### 2. 準備（スクリプト）

```
$PY -I tools/analysis/cash_flow.py prepare --company {company} [--redo] [--skip-collect]
```

- `{日付}_brief.md`（材料）と `{日付}_cash-flow.md`（FILL つきの骨組み）を作る。返り値の `brief`・`md` がそのパス
- 骨組みには **1章 年次の CF 表と手順1の判定**、**2章 FCF の5年の表・成長投資期の確認と手順2の判定**、**3章 営業CF対純利益比率（平均と累計）・売上高と売上債権・棚卸資産の増加率・純利益と営業CF の差の内訳と主因・直近の推移・最も古い年を除いた平均と手順3の判定**、**4章 年ごとの CF パターン（財務CF の中身で書き分けた状態）と手順4の判定**、**5章 株主還元と FCF の表と手順5の判定**、**7章 収益性・成長性・安全性分析との関係の判定**がすべて記入済み。`candidate` が結論の候補（build が同じ規則で確定する）
- `fill_keys` が書く欄の一覧（md を読み直して探さなくてよい）、`negative_years` が背景を書く営業CF マイナスの年、`borderline` が境界に近い比較
- 作成途中の md（FILL が残っている）は上書きせず残す（`kept: true`）。続きから書く
- 一字も書いていない骨組み（前回の prepare が書いたままの md）は、`--redo` なしで作り直す（`regenerated: true`）
- `--redo` は完成済みの結果（有効期間内）と書きかけの md を作り直すときだけ使う（ユーザーの指示があるときだけ）。同じ日に build 済みの結果があると `--redo` は拒否される。その日の md を Edit で直して build し直す
- `warnings`（brief の「警告」節にも出る）は、スクリプトが raw を読み違えた可能性（隣り合う年の営業CF が100倍超違う＝単位の読み違い、二次情報を使った年）。空でなければ完了報告の「警告」行に書く

### 3. 執筆（LLM）

brief.md を読み、cash-flow.md の `<!-- FILL:... -->` を Edit で置き換える。

- 読むのは brief.md と cash-flow.md だけ。raw・PDF・CSV・summaries を個別に開かない（必要な節は brief.md に集約済み）
- 書く順番と Edit の単位（各1回）: 1章 営業CF がマイナスの年の背景（`negative-cfo`。マイナスの年が無ければ欄はスクリプトが「該当なし」と記入済み） → 2章 投資の中身 → 3章 利益と営業CF の差の背景 → 7章 コメント → 8章 → 9章 → 10章
- 書き方の規則は cash-flow.md 冒頭の `>` 行に従う。要点:
  - 書くのは**数値の背景と解釈だけ**。表の数値・判定・年度の行を変えない。数値を新しく計算しない
  - 背景は brief の CF 計算書の注記・設備投資・事業・特別損益の記述から書く。brief に無ければ「不明（brief に記載なし）」（推測で埋めない）
  - 3章の「利益と営業CF の差の背景」は、内訳表の「主因」を引用し、その事業上の理由を brief から書く。「内訳なし」の年は理由を推測しない。「要確認」（売上債権・棚卸資産の増加率が売上高を上回る）が出ていれば、その理由が brief にあるか（大型案件・前受金・在庫の積み増しなど）を書く
  - brief「数値の要点」の「境界に近い比較」と、3章の「直近の推移」「最も古い年を除いた平均」は、8章の「評価が変わる条件」にそのまま引用する（次の決算の影響を自分で計算・推論しない）
  - **数値は md の表・brief にあるものだけを引用する。** build は、書いた欄にある数値が md のスクリプト記入部分と brief のどちらにも無いとき、また「約〜」「〜割」の概数を書いたときに拒否する（年・ページ番号・10未満の数は対象外）
  - 7章は「不整合」「要確認」の行があれば、どの分析のどの評価を割り引く・見直す候補かを書く（判定そのものは変えない。他の分析を作り直すのはユーザーの判断）
  - 8章は企業分析レポートの INPUT になる。レポートで使う要点（6章の結論と根拠の数値）、会社の資本政策・還元方針との関係、STEP 2 の他の分析（成長性・安全性）で確かめること、評価が変わる条件
  - 根拠に書く事実は brief.md の記述と同じ強さで書く。表のセルに `|` を書かない。6章（結論）は build が書くので触らない
- 見出し・表の列・ヘッダー・スクリプト記入済みの欄は変えない。ファイルを丸ごと書き直さない（Write は hook がブロックする）

#### 判断基準（企業分析フレームワーク.md 2-4 の転記。判定はすべてスクリプト）

- FCF = 営業CF ＋ 投資CF。営業CF対純利益比率 = 営業CF ÷ 当期純利益（親会社株主に帰属）
- 各年の値は 決算短信・EDINET の CSV → 有報 → 財務時系列の表 の順に一次の値を採用（集計サイトの値は一次が無い年だけ）。配当は CF 計算書の「配当金の支払額」を優先し、無ければ配当総額
- 対象は営業CF が取れた直近最大10年（手順1は5年以上）。手順2〜5は直近5年
- 「一時要因として説明できる」「成長投資期として理由が説明できる」は、下の数値の代理指標で判定する（会社の説明の当否は 1・2章の背景に書くだけで、判定は変えない）

| 手順 | 見るもの | 判定（スクリプト） |
|---|---|---|
| 1 営業CF の安定性 | 営業CF の推移（最大10年） | **良好**: 全年プラス / **普通**: マイナスが1回で、翌年にプラスへ戻り、直近年でない（一時要因の代理指標） / **懸念**: マイナスが2回以上、または1回でも直近年か翌年に戻っていない / 5年未満は判定できない |
| 2 FCF の創出力 | FCF の5年の推移と累計 | **良好**: 累計プラスで過半数の年がプラス / **普通**: 累計プラスだがマイナスの年が多い、または累計マイナスでも成長投資期の代理指標（投資CF の流出が営業CF を超えた年があり、売上 CAGR 5%以上、直近の営業CF が期初を上回る）を満たす / **懸念**: 累計マイナスで代理指標を満たさない |
| 3 利益の質 | 営業CF対純利益比率の「5年平均」と「5年累計の営業CF ÷ 5年累計の純利益」（純損失の年を含むときは累計だけ）、売上債権・棚卸資産の増加率 | 平均と累計の**低い方**で（純利益がごく小さい年が平均を押し上げるのを防ぐ）**良好**: 1.0倍以上 / **普通**: 0.8〜1.0倍 / **懸念**: 0.8倍未満（売上債権・棚卸資産の増加率が売上高を上回れば「要確認」） / 5年累計の純利益がマイナスなら判定できない（純損失）。判定には使わない参考として、純利益と営業CF の差の内訳（減価償却費・売上債権の増減・棚卸資産の増減・税金の支払いと計上の差・その他）と主因、直近2年の比率、最も古い年を除いた平均を出す |
| 4 CF パターン | 直近5年（最低3年）の 営業・投資・財務CF の符号 | 年ごとに（+,−,−）良好・（+,−,+）普通・（+,+,−）普通・（+,+,+）普通・営業CF がマイナスの年は懸念。最も多い評価を採り、同数なら保守的な方。状態の文は財務CF の中身で書き分ける（流出の半分以上が配当＋自社株買いなら「株主還元」、それ未満なら「借入の返済など」、不明なら「返済・還元」） |
| 5 株主還元の持続性 | 配当金の支払額＋自己株式の取得と FCF（5年） | **注意**: 累計の還元額が累計 FCF を上回り、かつ還元が FCF を上回った年が3年以上 / **問題なし**: それ以外 / **対象外**: 還元の支出なし / **不明**: 材料なし。片方の行だけがある年は、無い方を0として計算し、表に「0（記載なし）」と書く |

**手順6 キャッシュフロー**（上から順に当てはめる）

| 結論 | 条件 |
|---|---|
| **懸念** | 手順1〜4のいずれかが懸念 |
| **懸念** | 純損失以外の理由で手順2〜4を判定できない（判定できない手順は懸念とみなす（材料不足のため保守的に判定。結果 JSON の conservative に記録）） |
| **判定保留** | 手順1を判定できない（判定に使える事実が無い） |
| **良好** | 手順1〜4がすべて良好で、手順5が問題なし・対象外 |
| **普通** | 上記以外（手順3が純損失で判定できない、手順5が注意・不明を含む） |

**STEP 2 の他の分析との関係**（7章。スクリプト。キャッシュフローの判定は変えない）

| チェック項目 | 不整合・要確認になる条件 |
|---|---|
| 収益性が良好 ⇔ 利益の質 | 収益性が「良好」なのに手順3が懸念 → 不整合（収益性の評価を割り引く候補） |
| ROE が本業由来 ⇔ 営業CF の安定 | ROE の源泉が「本業由来」なのに手順1が懸念 → 不整合 |
| 成長性 ⇔ 運転資本 | 売上債権か棚卸資産の増加率が売上高を上回る → 要確認（成長が運転資本の積み上がりを伴う） |
| 安全性 ⇔ 還元・FCF | 手順5が注意で、安全性分析のネットキャッシュが0以下 → 不整合（還元を借入で賄っている候補）。プラスなら「整合（手元資金で還元。継続性は要確認）」 |

### 4. ビルド（スクリプト）

```
$PY -I tools/analysis/cash_flow.py build --company {company}
```

- `ok: true` → md の6章に結論を書き込み、json を作る。返り値の `verdict`・`verdict_reason`・`step1`〜`step5`（各手順の結論の文）・`relation`・`borderline`（境界に近い比較）・`flagged_working_capital`（増加率が売上高を上回る科目）・`unknown_backgrounds`（背景が不明の欄）・`gaps`（10章の全件）を完了報告に使う
- `ok: false` → `issues` の指摘箇所だけを Edit で直し、もう一度 build（2回まで。それでも残れば未完了として、指摘をそのまま報告する）

## してはいけないこと

- 5段以外の作業（追加の web 検索、raw・PDF・CSV の閲覧、数値の手計算）をしない。材料が足りなければ背景を「不明」にして 10章に書く
- スクリプトが作るファイル（brief.md・json）と、cash-flow.md のスクリプト記入済みの欄（1〜5章の表と判定、6章、7章の表）を手で直さない
- 有効期間内の結果を作り直さない（`--redo` はユーザーの指示があるときだけ）。過去の日付の完成済み md を変更しない（hook がブロックする）
- STEP 1 のスキル（five-forces・three-c・moat・swot）、profitability・growth・safety、地合いのスキル（collect-market-info・market-report）をこのスキルから実行しない
- 投資の勧誘・推奨、「おそらく」「〜と思われる」を書かない（build が検出する）
- 収集担当（collect-company-info）へのプロンプトで、raw の書き方（範囲外の章に「変更なし」と書く、前回の表を再掲するなど）を指示しない。書き方は collect-company-info.md の保存ルールに任せる

※ グローバル設定の hook（Fact-Forcing Gate）が、最初の Bash と、ファイルごとの最初の Edit を一度差し戻すことがある。求められた事実を示して同じ操作を再実行すれば通る。

## 完了報告（ユーザー向け）

check・prepare・build の JSON（収集を実行した場合はその完了報告も）だけを使い、次の形式で短く報告する。

```
## キャッシュフロー分析 — {name}
- 結果: {md}（機械可読: {json}）
- キャッシュフロー: {verdict}（{verdict_reason}。前回 {previous.verdict または「初回」}）
  - 手順1: {step1}
  - 手順2: {step2}
  - 手順3: {step3}
```
