# ファイブフォース分析スキル（five-forces）

`企業分析フレームワーク.md` の **STEP 1-1 ファイブフォース分析**（業界の魅力度 高 / 中 / 低）を、
collect-company-info・collect-market-info・market-report が集めた材料から行う。成果物は次の3つ。

- `companies/{ticker}_{name}/analysis/five-forces/{日付}_five-forces.md` — 分析結果。企業分析レポートはこれ（と json）を参照する
- `.../{日付}_five-forces.json` — 同じ結果の機械可読版（業界の定義・各要因の評価と点数・合計・魅力度・有効期限・SWOT の T に送る要因）
- `.../{日付}_brief.md` — 執筆の材料（raw から必要な節だけを抜き出したもの）

`{日付}` は分析日。業界の構造は頻繁に変わらないため、結果は **365日有効**で、期間内は再実行しても既存の結果を返すだけにする。
ただし期限前でも、分析が使った節（有報・業界概要・競合）の中身が新しい raw で変わったら再分析する。分析が使わない節だけを足した raw（モート用のコスト構造など）や、同じ値を再掲した raw では再分析しない。

抽出・数値の判定・採点・検証はスクリプト（`tools/analysis/five_forces.py`）が行う。
LLM が受け持つのは five-forces.md の FILL 欄（各要因の評価と根拠の文章）だけ。手順は **企業の選択 → 鮮度確認 → 準備 → 執筆 → ビルド** に固定されている。

## 前提として読むファイル

`企業分析フレームワーク.md` は読まなくてよい（1-1 の判断基準は下に転記してある）。

|---|---|---|

## 実行手順

Python は `.venv` のものを使う（Windows: `.venv\Scripts\python.exe`、macOS/Linux: `.venv/bin/python`）。以下 `$PY` と書く。
各コマンドの標準出力は1行の JSON。

### 0. 企業の選択（`company` が無いときだけ）

```
$PY -I tools/analysis/five_forces.py list
```

`companies` の各行（`dir`・`name`・`last_collected`・`five_forces`・`five_forces_date`・`attractiveness`）から選択肢を作り、ユーザーに選んでもらう（提示の方法はエントリーポイントの指示に従う）。
企業が1社だけなら選択肢を出さずにその企業で進み、完了報告の「材料」行に「対象は1社だけのため選択を省略」と書く。
選択肢には `five_forces` の状態（`none` 未分析 / `fresh` 有効 / `expired` 期限切れ / `triggered` 新しい raw あり / `draft` 作成途中）を添える。
一覧に無い企業を指定されたら、手順 1 の `company_missing` と同じ扱いにする。

### 1. 鮮度確認（スクリプト）

```
$PY -I tools/analysis/five_forces.py check --company {company}
```

`next` に従う。

| `next`・状態 | すること |
|---|---|
| `ok: false` で `candidates` あり | 複数の企業が当たった。候補からユーザーに選んでもらい、もう一度 check |
| `ok: false` で `company_missing: true` | 企業の情報が無い。ユーザーにホームページ URL を確認し、collect-company-info を `mode=full` で実行してから check をやり直す |
| `report_existing`（`result: fresh`） | 有効期間内。`latest`（md・魅力度・有効期限）を完了報告の形式で伝えて**終わる**（執筆しない）。`redo` の指示があるときだけ手順 2 へ |
| `collect` | 必須の材料が足りない。`needs_full_collect: true` なら collect-company-info を `mode=full`、そうでなければ `mode=update` で実行し、`missing_inputs` の担当（`agent`）と項目（`items`）を範囲として伝える。終わったら check をやり直す |
| `prepare`（`none` / `expired` / `triggered` / `draft`） | 手順 2 へ |

- 地合い（outlook.md）は md のヘッダーで参照するだけで、業界構造の判断には使わない。そのため古くても（`outlook_stale: true`）market-report は実行しない。完了報告の「材料」行に「地合いは N 日前の週（古い）」と書く
- 収集（collect-company-info）は**1回の実行につき1回まで**。やり直した check でまだ `collect` が出ても、もう一度は収集せず手順 2 に `--skip-collect` を付けて進む（取れなかった材料の要因は「不明」として扱い、6章に書く）
- check と prepare を1つのコマンドにつなげない。prepare も `next` を確かめ、`collect` のままなら `ok: false` で拒否する
- `unavailable` は「収集を試みたが取れなかった」材料（status.md の未取得項目）。再収集しない
- 収集スキルが止まった（ユーザーへの確認待ち・エラー）ときは、このスキルも止めて状況を報告する

### 2. 準備（スクリプト）

```
$PY -I tools/analysis/five_forces.py prepare --company {company} [--redo] [--skip-collect]
```

- `{日付}_brief.md`（材料）と `{日付}_five-forces.md`（FILL つきの骨組み）を作る。返り値の `brief`・`md` がそのパス
- 作成途中の md（FILL が残っている）は上書きせず残す（`kept: true`）。続きから書く
- 一字も書いていない骨組み（前回の prepare が書いたままの md）は、`--redo` なしで作り直す（`regenerated: true`）
- 同じ日に build 済みの結果があると `--redo` は拒否される。その日の md を Edit で直して build し直す
- `candidates` はスクリプトの判定候補（数値で決まる基準: ③ 買い手の最大顧客比率と前期からの変化、④ 売り手の粗利率の最大低下幅）
- brief には、スクリプトが計算した数値も入る: ④ に自社の粗利率・営業利益率の時系列、⑤ に競合と自社の営業利益率の推移（最新実績の前年差・会社予想）。比率・差分が欲しいときはここから転記し、自分で計算しない

### 3. 執筆（LLM）

brief.md を読み、five-forces.md の `<!-- FILL:... -->` を Edit で置き換える。

- 読むのは brief.md と five-forces.md だけ。raw・PDF・CSV・summaries を個別に開かない（必要な節は brief.md に集約済み）
- brief.md が Read の上限を超えるときは、offset/limit で分けて最後（8. 取れていない材料）まで読む
- 書く順番: 1章（業界の定義）→ 2.1〜2.5（各要因。見たもの → 情報源 → 根拠の確度 → 評価 → 理由 → 評価が変わる条件）→ 5章 → 6章
- Edit は**要因ごとに1回**（その要因の表の FILL 行をまとめて old_string にして置き換える）。1章・5章・6章もそれぞれ1回
- 書き方の規則は five-forces.md 冒頭の `>` 行に従う。要点:
  - 評価は `強` / `中` / `弱` / `不明` の1語。下の「判断基準」と「文章で決める要因の判定条件」で決める。2段階で迷ったら**強い方**（業界の魅力にとって不利な方）を採り（policy.md 行動指針6）、理由に「迷った:」で始まる文を入れる（build が数え、完了報告に出す）
  - 理由に書く事実は brief.md の記述と同じ強さで書く。brief で「未確認」「要旨」とある事柄を確認済みの事実として書かない（例: 減益の理由が未確認の会社を「人件費増で減益」とまとめない）
  - 「根拠の確度」は、評価を決めた根拠のうち最も弱いものの種類: `一次`（有報・会社資料・官公庁統計）/ `二次`（調査会社の公表値を記事経由で引用）/ `参考`（ブログ・比較サイト・検索結果の要旨）。不明の要因で根拠が無ければ `—`
  - 「評価が変わる条件」は、監視する指標と、評価が1段階変わるしきい値を1文で書く（例: パソナの比率が20%以上になれば強、粗利率が前年比5pt以上下がれば強）。企業分析レポートの監視項目になる
  - 「見たもの」には brief.md の数値と時点を、「情報源」には brief.md に書かれた出典ファイル名と節を書く
  - 根拠が書けない要因は「不明」（1点＝中と同じ扱い。不明が2つ以上だと魅力度が1段階下がる）。良い方に解釈して埋めない
  - スクリプトの判定候補より**有利**な評価にするときは、理由に「候補と異なる理由:」で始まる文を入れる。「強（確定）」は変えられない
  - 前回の評価と違う評価にするときは、理由に「前回から変更:」で始まる文を入れ、5章にも書く。前回と同じ材料なら同じ評価にする（結果を安定させるため）
  - 表のセルに `|` を書かない。3章（点数・合計・魅力度）と4章（SWOT の脅威）は build が書くので触らない
- 見出し・表の列・ヘッダー・スクリプト記入済みの欄（判定候補・前回の評価）は変えない。ファイルを丸ごと書き直さない（Write は hook がブロックする）

#### 手順1: 業界の定義

有報のセグメント情報で、営業利益の最大の割合を占めるセグメントを主力事業とし、「〇〇業界（主力セグメント：〇〇、営業利益構成比〇%）」の1行にする。
単一セグメントなら構成比の代わりに「単一セグメント」と書く。

#### 判断基準（企業分析フレームワーク.md 1-1 手順2 の転記）

| 要因 | 弱 | 中 | 強 |
|---|---|---|---|
| ① 新規参入の脅威 | 大規模投資や許認可が必要で、過去5年に有力な新規参入がない | 参入障壁はあるが、資本力のある異業種や海外企業の参入例がある | 少額で参入でき、新興企業の参入が続いている |
| ② 代替品の脅威 | 有力な代替手段がない、または乗り換えコストが高い | 代替手段はあるが、価格・性能面で劣るか普及途上 | 安価で同等以上の代替手段が普及し始めている |
| ③ 買い手の交渉力 | 顧客が分散しており（単一顧客10%未満）、製品が差別化されている | 主要顧客への依存がある（単一顧客10〜20%）、または製品の差別化が限定的 | 単一顧客が売上の20%以上、または製品が汎用品で価格だけで選ばれる |
| ④ 売り手の交渉力 | 調達先が多数あり、原材料高騰時も粗利率がほぼ維持された（低下2pt未満） | 調達先は限られるが代替可能、高騰時に粗利率が2〜5pt低下した | 供給元が寡占・独占状態、高騰時に粗利率が5pt以上低下した |
| ⑤ 業界内の競争 | 上位2〜3社でシェアの過半を占める寡占で、市場が成長しており、業界の利益率が安定している | 上位数社が拮抗しているが、市場成長や差別化により価格競争は限定的 | 多数の企業が拮抗し、市場が横ばい・縮小しており、値下げ競争で利益率が低下傾向 |

- ③ は「単一顧客の比率」と「差別化」の**両方**が弱の条件を満たすときだけ弱。どちらかが中なら中
- ④ の粗利率の低下は、スクリプトが「前年比の最大低下幅」として計算している。その年が原材料（人件費・外注費など調達コスト）の高騰によるものでないと brief.md から言えるときだけ、「候補と異なる理由:」を書いて有利側に変えてよい
- ⑤ は3条件（集中度・成長・利益率）のうち、brief.md で確認できたものだけで判断し、確認できなかった条件を理由に書く。シェアが非公表で集中度が分からず、他の2条件でも弱と言えないときは中以上（不利側）にする

#### 文章で決める要因の判定条件（①②⑤。結果を安定させるための補足）

同じ材料なら誰が書いても同じ評価になるよう、判断基準の「続いている」「普及し始めている」「低下傾向」を次の条件で読む。

| 要因 | 強にする条件 | 弱にする条件 | どちらでもなければ |
|---|---|---|---|
| ① 新規参入 | 事業に許認可が不要、かつ**参入障壁（下の注）が無い**、かつ brief で過去5年の新規参入（新規上場・異業種や海外からの参入）の具体例を**2件以上**確認できる | 許認可または参入障壁が有り、かつ brief に過去5年の有力な新規参入の例が無い | 中。参入障壁が有り、参入例が資本力のある企業（巨額の資金調達をした新興企業・異業種・海外大手）だけのとき（判断基準の中「資本力のある異業種や海外企業の参入例がある」）も中。新規参入の網羅的な一覧が無く例が1件以下でも中とし、6章に書く |
| ② 代替品 | 代替手段の普及を示す**数値**（導入率・利用率・シェア・市場規模の伸び）が brief にあり、価格または性能で同等以上と書かれている | brief に有力な代替手段の記載が無い、または乗り換えコストが高いと書かれている | 中。代替手段の論考だけで普及の数値が無いときは中 |
| ⑤ 業界内競争 | 市場成長率（brief の CAGR・前年比）が**3%未満または縮小**、かつ競合の営業利益率（brief の推移）が過半の会社で低下 | 上位2〜3社のシェア合計が過半（brief に数値がある）、かつ市場成長率が5%以上、かつ競合の営業利益率が過半の会社で横ばい以上 | 中。市場成長率が5%以上なら強にしない |

- ① の**参入障壁**は、brief に次のどれかの記載があるとき「有り」とする。どれも無ければ「無し」。理由にどれに当たるか（または当たらないか）を書く
  - 資本: 参入に要る初期投資、または事業を続けるための年間の研究開発費・設備投資が大きい（目安: 数百億円・数億ドル規模以上。自社の研究開発費・設備投資の金額も手がかりにする）
  - 供給: 製造能力・主要部材の確保が少数の大手に押さえられている（例: 先端製造・パッケージ・メモリの供給の大半を大手が確保）
  - 技術: 特許・技術的な難度・規模の経済が参入を妨げていると書かれている（会社の主張だけのときは、確度に「参考」と書いたうえで使ってよい）
- ① の新規参入の例として数えるのは、製品の出荷・売上の計上・新規上場が brief で確認できたものだけ。資金調達や計画の報道だけの例は数えない（「見たもの」には書いてよい。参入障壁の高さを示す材料にもなる）
- 条件の境目に当たるとき（例: 上場例が2件だが上場年が未確認）は、不利な方を採って理由に「迷った:」を書く

#### 採点（build が行う。参考）

弱 = 2点、中 = 1点、強 = 0点、不明 = 1点 の合計（0〜10点）。7点以上 **高** / 4〜6点 **中** / 3点以下 **低**。
不明が2つ以上なら1段階下げる。「強」の要因は 4章（SWOT の脅威 T に必ず記載する要因）に入る。

### 4. ビルド（スクリプト）

```
$PY -I tools/analysis/five_forces.py build --company {company}
```

- `ok: true` → md の3章・4章に点数・合計・魅力度を書き込み、json を作る。返り値の `attractiveness`・`total`・`ratings`・`tie_breaks`（迷った要因）・`low_confidence`（根拠の確度が参考の要因）・`gaps`（6章の全件）を完了報告に使う
- `ok: false` → `issues` の指摘箇所だけを Edit で直し、もう一度 build（2回まで。それでも残れば未完了として、指摘をそのまま報告する）

---

## してはいけないこと

- 5段以外の作業（追加の web 検索、raw・PDF・CSV の閲覧、数値の手計算）をしない。材料が足りなければ「不明」にして 6章に書く
- スクリプトが作るファイル（brief.md・json）と、five-forces.md の判定候補・前回の評価・3章・4章を手で直さない
- 有効期間内の結果を作り直さない（`--redo` はユーザーの指示があるときだけ）。過去の日付の完成済み md を変更しない（hook がブロックする）
- 投資の勧誘・推奨、「おそらく」「〜と思われる」を書かない（build が検出する）

※ グローバル設定の hook（Fact-Forcing Gate）が、最初の Bash と、ファイルごとの最初の Edit を一度差し戻すことがある。求められた事実を示して同じ操作を再実行すれば通る。

## 完了報告（ユーザー向け）

check・prepare・build の JSON（収集を実行した場合はその完了報告も）だけを使い、次の形式で短く報告する。

```
## ファイブフォース分析 — {name}
- 結果: {md}（機械可読: {json}）
- 業界: {industry}
- 業界の魅力度: {attractiveness}（{total}/10点。前回 {previous.attractiveness または「初回」}）{downgraded なら「不明 {unknown_count} 件のため1段階下げた」}
  - 新規参入 {評価} / 代替品 {評価} / 買い手 {評価} / 売り手 {評価} / 業界内競争 {評価}
  - SWOT の脅威に送る要因: {swot_threats。無ければ「なし」}
- 判断が分かれた要因: {tie_breaks。無ければ「なし」} / 根拠が参考情報だけの要因: {low_confidence。無ければ「なし」}
- 有効期限: {valid_until}（それまでは再実行しても再分析しない）
- 材料: {今回 collect-company-info を実行した・しなかった。地合いが古ければ「地合いは N 日前の週（古い）」。1社のため選択を省略したならその旨。unavailable があれば列挙}
- 欠損: {gaps の全件の要点。無ければ「なし」}
```

有効期間内で再分析しなかった場合は、`latest` の md・魅力度・有効期限と「有効期間内のため再分析していない（作り直す場合は redo を指示）」だけを書く。
