# 成長性分析スキル（growth）

`企業分析フレームワーク.md` の **STEP 2-2 成長性**（会社が持続的に成長しているか、その成長が本物か。成長性 良好 / 普通 / 懸念。材料不足なら 判定保留）を、
collect-company-info が集めた財務時系列・有報・中期経営計画の材料から行う。成果物は次の3つ。

- `companies/{ticker}_{name}/analysis/growth/{日付}_growth.md` — 分析結果。企業分析レポート・STEP 2 判定・STEP 3 の成長率設定はこれ（と json）を参照する
- `.../{日付}_growth.json` — 同じ結果の機械可読版（年次表・CAGR・手順1〜4の判定と数値・減収減益の年の分類・計画達成率・成長の質・STEP 1 との整合性・引き継ぎ・有効期限）
- `.../{日付}_brief.md` — 執筆の材料（数値の要点と、数値の背景になる raw の節の抜粋・SWOT の弱み/脅威）

`{日付}` は分析日。結果は **180日有効**で、期間内は再実行しても既存の結果を返すだけにする。
ただし期限前でも、分析が使った節（有報・財務時系列・中期経営計画）の中身や年次の数値（新しい決算期・訂正）が変わったとき、または新しい 3C・SWOT 分析ができたときは再分析する。

**数値の抽出・EPS の株式分割の調整・CAGR・減収減益の年の抽出と回復の確認・計画達成率・成長の質・手順1〜5の判定・STEP 1 との整合性はすべてスクリプト（`tools/analysis/growth.py`）が行う。**
LLM が受け持つのは growth.md の FILL 欄（減収・減益の年の会社の説明と **分類（一時 / 構造 / 不明）**、数値の背景、引き継ぎ）だけ。手順は **企業の選択 → 鮮度確認 → 準備 → 執筆 → ビルド** に固定されている。

STEP 1（five-forces / three-c / moat / swot）は前提にしない。3C の「市場の成長性」は整合性チェックに、SWOT の弱み・脅威は構造要因との照合に使い、無ければ「未実施」と記録する（上流のスキルは実行しない）。
地合い（outlook.md）は md のヘッダーで参照するだけで、成長性の判定には使わない。古くても market-report・collect-market-info は実行しない。

## 実行手順

Python は `.venv` のものを使う（Windows: `.venv\Scripts\python.exe`、macOS/Linux: `.venv/bin/python`）。以下 `$PY` と書く。
各コマンドの標準出力は1行の JSON。

### 0. 企業の選択（`company` が無いときだけ）

```
$PY -I tools/analysis/growth.py list
```

`companies` の各行（`dir`・`name`・`last_collected`・`growth`・`growth_date`・`verdict`・`three_c`・`swot`）から選択肢を作り、ユーザーに選んでもらう（提示の方法はエントリーポイントの指示に従う）。
企業が1社だけなら選択肢を出さずにその企業で進み、完了報告の「材料」行に「対象は1社だけのため選択を省略」と書く。
選択肢には `growth` の状態（`none` 未分析 / `fresh` 有効 / `expired` 期限切れ / `triggered` 材料・数値・上流の分析が変わった / `draft` 作成途中）と、3C の市場の成長性・SWOT の結論（無ければ「未実施」）を添える。
一覧に無い企業を指定されたら、手順 1 の `company_missing` と同じ扱いにする。

### 1. 鮮度確認（スクリプト）

```
$PY -I tools/analysis/growth.py check --company {company}
```

`next` に従う。

| `next`・状態 | すること |
|---|---|
| `ok: false` で `candidates` あり | 複数の企業が当たった。候補からユーザーに選んでもらい、もう一度 check |
| `ok: false` で `company_missing: true` | 企業の情報が無い。ユーザーにホームページ URL を確認し、collect-company-info を `mode=full` で実行してから check をやり直す |
| `report_existing`（`result: fresh`） | 有効期間内。`latest`（md・結論・有効期限）を完了報告の形式で伝えて**終わる**（執筆しない）。`redo` の指示があるときだけ手順 2 へ |
| `collect` で `needs_full_collect: true` | raw が無い。collect-company-info を `mode=full` で実行し、check をやり直す |
| `collect` | 材料が足りない。collect-company-info を `mode=update` で実行し、`missing_inputs` の担当（`agent`）と項目（`items`）を範囲として伝える。終わったら check をやり直す。主な項目: 自社の財務時系列が5年未満（collect-filings「財務時系列: 売上高・営業利益・当期純利益・EPS（5年以上）」）、会社計画（期初予想）と実績が無い、M&A・連結範囲の変更の節が無い、減収・減益の年の会社説明が無い（いずれも collect-filings） |
| `prepare`（`none` / `expired` / `triggered` / `draft`） | 手順 2 へ |

- 収集（collect-company-info）は**1回の実行につき1回まで**。やり直した check でまだ `collect` が出ても、もう一度は収集せず手順 2 に `--skip-collect` を付けて進む（確かめられない点はスクリプトが「不明」として扱い、結論が 判定保留 になることがある。9章に書く）
- check と prepare を1つのコマンドにつなげない（check の `next` を見てから次へ進む）。prepare も `next` を確かめ、`collect` のままなら `ok: false` で拒否する
- `unavailable` は「収集を試みたが取れなかった」材料（status.md の未取得項目）。再収集しない
- 収集スキルが止まった（ユーザーへの確認待ち・エラー）ときは、このスキルも止めて状況を報告する

#### 収集を依頼するとき

collect-company-info には `missing_inputs` の担当・項目だけを渡す。担当へのプロンプトに載せる原本の場所・同じ日の raw の扱いは、collect-company-info.md の mode=update の手順（分析スキルからの依頼）に従う。終わったら collect-company-info の集約（status.md・overview.md・summaries）まで済ませてから check に戻る。

### 2. 準備（スクリプト）

```
$PY -I tools/analysis/growth.py prepare --company {company} [--redo] [--skip-collect]
```

- `{日付}_brief.md`（材料）と `{日付}_growth.md`（FILL つきの骨組み）を作る。返り値の `brief`・`md` がそのパス
- 骨組みには **1章 年次表（売上高・営業利益・EPS と前年比）・CAGR・手順1の判定**、**2章 減収・減益の年の年度・減少した指標・その後の回復**、**3章 期初予想と実績・達成率・手順3の判定**、**4章 成長の質の3点の判定と質の補正後の手順1**、**6章 STEP 1 との整合性の判定**がすべて記入済み。`candidate` が結論の候補（build が 2章の分類を入れて同じ規則で確定する）
- `fill_keys` が書く欄の一覧（md を読み直して探さなくてよい）、`cagr` が売上・営業利益・EPS・純利益の CAGR、`decline_years` が分類する年、`borderline` が境界に近い比較
- 作成途中の md（FILL が残っている）は上書きせず残す（`kept: true`）。続きから書く
- 一字も書いていない骨組み（前回の prepare が書いたままの md）は、`--redo` なしで作り直す（`regenerated: true`）
- `--redo` は完成済みの結果（有効期間内）と書きかけの md を作り直すときだけ使う（ユーザーの指示があるときだけ）。同じ日に build 済みの結果があると `--redo` は拒否される。その日の md を Edit で直して build し直す
- `warnings`（brief の「警告」節にも出る）は、スクリプトが数値を補正した・読み違えた可能性（EPS を株式分割とみなして調整した年、EPS の代わりに純利益を使った、二次情報の年）。空でなければ完了報告の「警告」行に書く。分割の調整は brief の有報・財務時系列の記述（「分割考慮後」「1株→10株」など）と合っているかを確かめ、合わなければ 9章に書く

### 3. 執筆（LLM）

brief.md を読み、growth.md の `<!-- FILL:... -->` を Edit で置き換える。

- 読むのは brief.md と growth.md だけ。raw・PDF・CSV・summaries を個別に開かない（必要な節は brief.md に集約済み）
- 書く順番と Edit の単位（各1回）: 2章の各年（会社の説明 → 分類 → SWOT との照合。1行を1回の Edit で）→ 2章 構造要因の評価 → 3章 中期経営計画の達成状況 → 4章 成長の背景 → 6章 コメント → 7章 → 8章 → 9章
- 書き方の規則は growth.md 冒頭の `>` 行に従う。要点:
  - 書くのは**数値の背景と解釈、減収・減益の年の分類だけ**。表の数値・判定・年度の行を変えない。数値を新しく計算しない
  - 2章の **会社の説明** は、brief の「減収・減益の年の会社説明」・損益の注記にある会社の説明を1文で。無ければ「不明（brief に記載なし）」（推測で埋めない）
  - 2章の **分類** は `一時` / `構造` / `不明` のどれか1語だけ（build がこれで判定する）
    - 一時: 景気後退・為替・災害・一過性の特別損失など、要因が消えれば戻るもの。「その後の回復」が `未回復` の年には使えない（build が拒否する）
    - 構造: シェア低下・市場縮小・製品の陳腐化など、自然には戻らないもの。1年でもあれば成長性は 懸念
    - 不明: 会社の説明が無い・説明から判断できない。他が良好なら成長性は 判定保留
  - 2章の **SWOT との照合** は、構造に分類した年について brief 0章の SWOT の弱み・脅威のどの ID に当たるかを1文。一時・不明なら「—（構造要因ではない）」、SWOT が未実施なら「SWOT 未実施」
  - brief「数値の要点」の「境界に近い比較」は、7章の「評価が変わる条件」に使う
  - 6章は「不整合」の行があれば、シェアを落としている可能性と確かめる材料を書く（判定そのものは変えない）
  - 7章は企業分析レポートと STEP 3 の INPUT になる。レポートで使う要点（5章の結論と根拠の数値）、STEP 3 の成長率設定への示唆（3章の判定から、会社計画をそのまま使えるか・実績の CAGR や保守的な値を使うか）、STEP 2 の他の分析（収益性・安全性・キャッシュフロー）で確かめること、評価が変わる条件
  - 根拠に書く事実は brief.md の記述と同じ強さで書く。表のセルに `|` を書かない。5章（結論）は build が書くので触らない
- 見出し・表の列・ヘッダー・スクリプト記入済みの欄は変えない。ファイルを丸ごと書き直さない（Write は hook がブロックする）

#### 判断基準（企業分析フレームワーク.md 2-2 の転記。判定はすべてスクリプト）

- CAGR =（最終年の値 ÷ 初年の値）^(1 ÷ 年数) − 1。対象は売上高のある直近最大10年。初年が赤字の指標は計算しない
- EPS は直近の株式数の基準にそろえる（純利益 ÷ EPS が黒字の隣の年と 1.25・1.5・2・3・4・5・10 倍など分割の比率（誤差5%以内）に変わった年を株式分割・併合とみなし、それより前の年（間の赤字の年も）を割る。150倍を超える変化は単位の読み違いとみなして調整せず警告する）。EPS が5年に満たず純利益の方が長ければ、純利益で代用する
- CAGR は売上高と EPS（代用なら純利益）が揃う同じ期間で計算する。期初予想に対する達成率が 20〜500% の範囲外の年は単位の違いとみなして手順3から除き、警告する。子会社取得の支出がその年の売上高の1%未満なら M&A として扱わない
- 年次の値は 決算短信（data/tdnet_facts.csv）→ data/financials.csv → 有報・財務時系列の表 の順に、一次の値を優先（二次は欠けた年の補完だけ）

| 手順 | 見るもの | 判定（スクリプト） |
|---|---|---|
| 1 成長の水準 | 売上高・営業利益・EPS の CAGR（5年未満なら判定しない） | **停滞・縮小**: 売上か EPS の CAGR がマイナス / **高成長**: 売上 5% 以上かつ EPS 7% 以上 / **安定成長**: それ以外でともにプラス |
| 2 減収・減益の年 | 売上高・営業利益・EPS のどれかが前年を下回った年 | スクリプトは年度と回復（減少前の水準に2年以内に戻れば 回復、それより後なら 遅れて回復、戻らなければ 未回復、まだ確かめる年が無ければ 未確認）を出す。分類（一時 / 構造 / 不明）は LLM |
| 3 会社計画の信頼性 | 期初予想と実績（営業利益、無ければ経常利益、無ければ純利益） | 達成率 90% 以上の年が過半で、直近2年が続けて未達でない → **信頼できる** / それ以外 → **割り引いて扱う**（手順5には使わず、STEP 3 への引き継ぎに使う） |
| 4 成長の質 | 3点 | (a) 営業利益 CAGR ≥ 売上 CAGR（赤字からの黒字化は問題なし、直近が赤字なら問題あり）、(b) M&A: 期間内に子会社取得（CF の支出・M&A の節）があれば、買収先の年間売上を最終年から除いた CAGR との差が 1pt 超なら M&A 頼み（買収先の売上が分からなければ 不明）、(c) EPS CAGR − 純利益 CAGR が 2pt 超なら自社株買い頼み。(b)(c) が問題ありなら、除いた CAGR・純利益 CAGR で手順1を判定し直す |

**手順5 成長性**（上から順に当てはめる）

| 結論 | 条件 |
|---|---|
| **懸念** | 手順1（または質の補正後の手順1）が停滞・縮小、または2章に「構造」の年がある |
| **判定保留** | 手順1を判定できない（5年未満、CAGR を計算できない） |
| **普通** | 成長の質に問題あり（利益が売上ほど伸びない・M&A 頼み・自社株買い頼み） |
| **判定保留** | 2章に「不明」の年がある、または成長の質の確認ができない点がある（材料不足。普通・懸念とは区別する） |
| **良好** | 手順1が高成長または安定成長、構造要因なし、成長の質が高い |

**STEP 1 との整合性**（6章。スクリプト）: 3C の市場の成長性が「高」なのに、売上 CAGR が市場成長率（3C の理由にある CAGR、無ければ 3%）を下回る → 不整合（シェアを落としている可能性）。成長性の判定は変えない。

### 4. ビルド（スクリプト）

```
$PY -I tools/analysis/growth.py build --company {company}
```

- `ok: true` → md の5章に結論を書き込み、json を作る。返り値の `verdict`・`verdict_reason`・`step1`〜`step4`（各手順の結論の文）・`consistency`・`borderline`・`structural_years`／`temporary_years`／`unknown_years`（分類ごとの年）・`unknown_reasons`（会社の説明が不明の年）・`gaps`（9章の全件）を完了報告に使う
- `ok: false` → `issues` の指摘箇所だけを Edit で直し、もう一度 build（2回まで。それでも残れば未完了として、指摘をそのまま報告する）

## してはいけないこと

- 5段以外の作業（追加の web 検索、raw・PDF・CSV の閲覧、数値の手計算）をしない。材料が足りなければ会社の説明を「不明」、分類を「不明」にして 9章に書く
- スクリプトが作るファイル（brief.md・json）と、growth.md のスクリプト記入済みの欄（1・3・4章の表と判定、2章の年度・指標・回復の列、6章の表、5章）を手で直さない
- 説明の無い減収・減益の年を、良い方に解釈して「一時」にしない
- 有効期間内の結果を作り直さない（`--redo` はユーザーの指示があるときだけ）。過去の日付の完成済み md を変更しない（hook がブロックする）
- STEP 1 のスキル（five-forces・three-c・moat・swot）や地合いのスキル（collect-market-info・market-report）をこのスキルから実行しない
- 投資の勧誘・推奨、「おそらく」「〜と思われる」を書かない（build が検出する）
- 収集担当（collect-company-info）へのプロンプトで、raw の書き方（範囲外の章に「変更なし」と書く、前回の表を再掲するなど）を指示しない。書き方は collect-company-info.md の保存ルールに任せる

※ グローバル設定の hook（Fact-Forcing Gate）が、最初の Bash と、ファイルごとの最初の Edit を一度差し戻すことがある。求められた事実を示して同じ操作を再実行すれば通る。

## 完了報告（ユーザー向け）

check・prepare・build の JSON（収集を実行した場合はその完了報告も）だけを使い、次の形式で短く報告する。

```
## 成長性分析 — {name}
- 結果: {md}（機械可読: {json}）
- 成長性: {verdict}（{verdict_reason}。前回 {previous.verdict または「初回」}）
  - 手順1: {step1}
  - 手順2: {step2}
  - 手順3: {step3}
  - 手順4: {step4}
- STEP 1 との整合性: {consistency を「、」で}
- 境界に近い比較: {borderline を「。」で。無ければ「なし」}（材料の誤差や次の決算で判定が1段階動きうる）
- 減収・減益の年: 構造 {structural_years} / 一時 {temporary_years} / 不明 {unknown_years}（無ければ「なし」）。会社の説明が不明の年: {unknown_reasons。無ければ「なし」}
- 有効期限: {valid_until}（それまでは再実行しても再分析しない）
- 材料: {今回 collect-company-info を実行した・しなかった（--skip-collect で進んだならその項目）。3C・SWOT の結果の日付（無ければ「未実施」）。1社のため選択を省略したならその旨。unavailable があれば列挙}
- 警告: {prepare の warnings。無ければ「なし」}
- 欠損: {gaps の全件の要点。無ければ「なし」}
- 次に集める材料: {verdict が「判定保留」のときだけ。自社の財務時系列（collect-filings）・減収減益の会社説明・M&A の買収先の売上 など}
```

有効期間内で再分析しなかった場合は、`latest` の md・結論・有効期限と「有効期間内のため再分析していない（作り直す場合は redo を指示）」だけを書く。
