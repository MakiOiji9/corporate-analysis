# 投資の質の分析スキル（investment）

会社が**何に投資したか**（設備・研究開発・M&A・出資）を過去最大10期の推移で示し、**どこで変化したか**と**投資の質**（投資の質 良好 / 普通 / 懸念。材料不足なら 判定保留）を判定する。成果物は次の3つ。

- `companies/{ticker}_{name}/analysis/investment/{日付}_investment.md` — 分析結果。企業分析レポートの「何に投資したか」の節と点数はこれ（と json）を参照する
- `.../{日付}_investment.json` — 同じ結果の機械可読版（年次表・変化点・(a)〜(h)・6つの軸・テーマ・中計と設備計画の照合・判定・有効期限）
- `.../{日付}_brief.md` — 執筆の材料（各期の有報の設備投資・設備計画・研究開発・企業結合の文章、中期経営計画、業界の構造変化、地合いの政策）

`{日付}` は分析日。結果は **365日有効**で、期間内は再実行しても既存の結果を返すだけにする。期限前でも、新しい期の有報・中期経営計画・業界データが収集されたとき、またはファイブフォース・3C の結論が変わったときは再分析する（`tools/analysis/freshness.py` の annual）。

設計の経緯と決定事項は `docs/proposals/investment-analysis.md`。

**数値・変化点・(a)〜(h)・① 投資効率・④ 競合比較・⑤・⑥・判定はすべてスクリプト（`tools/analysis/investment.py`、数値は `iv_metrics.py`）が出す。**
LLM が受け持つのは investment.md の FILL 欄（各年に何に投資したか、投資テーマ T1〜T5 と潮流との照合、変化点の背景、中期経営計画・設備計画との照合とその分類、引き継ぎ）だけ。② 中計との整合・③ 潮流との整合は、LLM が書いた分類から build が集計する。手順は **企業の選択 → 鮮度確認 → 準備 → 執筆 → ビルド** に固定されている。

成長投資の比率と増分 ROIC（以前の成長性分析の手順5）はこのスキルに移した。成長性分析の結果は前提にしない（同じ計算をこのスキルの中で行う）。地合い（outlook.md）は政策の材料として brief に載せるだけで、判定には使わない。

## 実行手順

Python は `.venv` のものを使う（Windows: `.venv\Scripts\python.exe`、macOS/Linux: `.venv/bin/python`）。以下 `$PY` と書く。各コマンドの標準出力は1行の JSON。

### 0. 企業の選択（`company` が無いときだけ）

```
$PY -I tools/analysis/investment.py list
```

`companies` の各行（`dir`・`name`・`investment`・`investment_date`・`verdict`・`has_investments_json`）から選択肢を作り、ユーザーに選んでもらう（提示の方法はエントリーポイントの指示に従う）。`peer_only: true` の行（他社の同業比較のために原本だけ集めた、未分析の会社）は名前に「未分析（同業として収集のみ）」を添える。
企業が1社だけなら選択肢を出さずにその企業で進み、完了報告の「材料」行に「対象は1社だけのため選択を省略」と書く。

### 1. 鮮度確認（スクリプト）

```
$PY -I tools/analysis/investment.py check --company {company}
```

| `next`・状態 | すること |
|---|---|
| `ok: false` で `candidates` あり | 複数の企業が当たった。候補からユーザーに選んでもらい、もう一度 check |
| `ok: false` で `company_missing: true` | 企業の情報が無い。ユーザーにホームページ URL を確認し、collect-company-info を `mode=full` で実行してから check をやり直す |
| `report_existing`（`result: fresh`） | 有効期間内。`latest` を完了報告の形式で伝えて**終わる**。`redo` の指示があるときだけ手順 2 へ |
| `collect` で `needs_full_collect: true` | raw が無い。collect-company-info を `mode=full` で実行し、check をやり直す |
| `collect` | 材料が足りない。collect-company-info を `mode=update` で実行し、`missing_inputs` の担当（`agent`）と項目（`items`）を範囲として伝える（`hints` もそのままプロンプトに書く）。主な項目: 設備投資・減価償却費の財務時系列、日本株の `data/investments.json`（有報の XBRL→CSV が `sources/` にあれば collect-filings が `yuho_investments.py` を1回実行するだけ） |
| `prepare`（`none` / `expired` / `triggered` / `draft`） | 手順 2 へ |

- 収集（collect-company-info）は**1回の実行につき1回まで**。やり直した check でまだ `collect` が出ても、手順 2 に `--skip-collect` を付けて進む（材料が無い軸は「不明」になり、判定保留になることがある）
- check と prepare を1つのコマンドにつなげない

### 2. 準備（スクリプト）

```
$PY -I tools/analysis/investment.py prepare --company {company} [--redo] [--skip-collect]
```

- `{日付}_brief.md`（材料）と `{日付}_investment.md`（FILL つきの骨組み）を作る
- 骨組みには **1章 年ごとの表（設備投資・売上比・設備投資 ÷ 減価償却・研究開発費・子会社の取得・減損損失・セグメント配分）**、**2章 変化点の年度・種類・数値**、**5章 ① 投資効率・④ 競合比較**、**6章 (a)〜(h)・⑤・⑥** がすべて記入済み。`candidate` が結論の候補（build が執筆者の分類を入れて確定する）
- `fill_keys`・`fill_spec` が書く欄の一覧、`years` が1章の年度、`points` が変化点の数、`plan_years` が設備計画を照合する年
- 作成途中の md（FILL が残っている）は上書きせず残す（`kept: true`）。一字も書いていない骨組みは作り直す（`regenerated: true`）
- `--redo` は完成済みの結果を作り直すときだけ（ユーザーの指示があるときだけ）
- `warnings` は完了報告の「警告」行に書く（文章ブロックが見つからない期、セグメント名が英語の要素名のままなど）

### 3. 執筆（LLM）

brief.md を読み、`fill_spec` に従って本文を書く。書いた本文は `{"FILL のキー": "本文"}` の JSON 1つにまとめて `fills_json` に Write し、`$PY -I tools/analysis/investment.py fill --company {company} --build` で流し込んで build する（FILL が残っていれば `remaining` を返すので、その欄を書いて JSON を作り直す）。

- 書く順番: 3章のテーマ（T1〜T5）→ 1章の各年（主な内容 → 主なテーマ）→ 2章の変化点の背景 → 4章（中期経営計画 → 設備計画）→ 8章
- **3章 テーマ**: 期間を通じた主な投資テーマを最大5つ、多い順に。短い名詞句（例: ロボットの増産、DX 基盤、海外の生産拠点）。使わない行はテーマ・照合・根拠をすべて「—」
  - **潮流との照合** は `合う` / `一部` / `逆行` / `不明` の1語。brief の「業界: 構造を変えうる要因」と「地合いの政策の材料」に照らす。根拠にその記述と出典を書く。出典が無ければ `不明`（推測で `合う` にしない）
- **1章 主な内容**: その年の有報の設備投資等の概要・研究開発活動・企業結合の記述から、何に・何のために投資したかを1文。記載が無ければ「不明（brief に記載なし）」。セグメント名は有報の日本語の名前で書く
- **1章 主なテーマ**: 3章の ID を「、」で区切る（例: `T1、T3`）。当たるものが無ければ「—」。build がこれで (g) 重点テーマの継続性と「新しい投資テーマ」の変化点を計算する
- **2章 背景**: 変化点ごとに、brief の有報・中期経営計画の記述から何に投資したか・なぜかを1文。無ければ「不明（brief に記載なし）」
- **4章 中期経営計画**: 中計の目標値・重点施策・経営方針の投資計画と、1章の実際の投資（配分・内容）を照らした結果。分類は `整合` / `一部` / `乖離` / `不明`
- **4章 設備計画**: その年の「設備の新設、除却等の計画」の主な計画と、次の期の有報で分かる結果。分類は `予定どおり` / `延期` / `中止・縮小` / `金額の膨張` / `不明`
- 単位付きの数値は brief.md か md のスクリプト記入済みの欄にある値だけを引用する。計算しない（build が照合して差し戻す）
- 見出し・表の列・ヘッダー・スクリプト記入済みの欄は変えない。表のセルに `|` を書かない。7章（結論）と 3・4章の「（build が集計）」の行は build が書く

#### 判断基準（判定はすべてスクリプト。しきい値は `iv_metrics.py`）

**変化点**（2章）: 設備投資 ÷ 売上が前3年平均の 1.5倍以上（急増）/ 0.5倍以下（急減）、セグメント別の設備投資の構成比が前年から 10pt 以上、研究開発費 ÷ 売上が前3年平均から 1pt 以上、子会社の取得が売上の 5% 以上か企業結合の注記がある年（M&A）、設備投資 ÷ 減価償却費が 1倍をまたいだ年（局面の切り替わり）、1章の主なテーマに初めて出たテーマ（新しい投資テーマ。build が足す）

| 軸 | 見ること | 結果 |
|---|---|---|
| ① 投資効率 | 増分 ROIC（資本コスト 日本 7%・米国 9% 以上 良好 / 半分以上 普通 / 未満 問題あり。人材集約型は人材の指標）。良好でも、(c) が問題あり、または設備投資が最も多いセグメントの営業利益率が下がっていれば 普通 | 良好 / 普通 / 問題あり / 不明 |
| ② 中計との整合 | 中計の分類が 乖離、または設備計画の半分以上（2件以上）が延期・中止・縮小・金額の膨張 → 乖離。中計が 整合 で予定どおりでない計画が無い → 整合。中計が 不明 で照合した計画も無い → 不明。ほかは 一部 | 整合 / 一部 / 乖離 / 不明 |
| ③ 潮流との整合 | 照合できたテーマに 逆行 があり 合う が無い → 逆行。逆行 が無く 合う が半分以上 → 合う。照合できたテーマが無い → 不明。ほかは 一部 | 合う / 一部 / 逆行 / 不明 |
| ④ 競合比較 | 売上に対する成長投資を、以前の5年と同業の中央値と比べる（以前の成長性の手順5の投資比率） | 高い / 同等 / 低い / 不明 |
| ⑤ 失敗の履歴 | (a)・(b) の悪い方 | 問題なし / 注意 / 問題あり |
| ⑥ 資金と規律 | (d)・(f)・(h) と、注意までに抑えた (e)・(g) の悪い方 | 問題なし / 注意 / 問題あり |

| 項目 | 指標 | 注意 | 問題あり |
|---|---|---|---|
| (a) 減損の履歴 | 直近5年の減損損失の累計 ÷ 直近の純資産 | 5% 以上 | 10% 以上、またはのれんの減損とみなした年が2回以上（のれんが減り、その年の減損損失が減少の半分以上かつ純資産の 0.5% 以上） |
| (b) のれん | のれん ÷ 純資産 | 30% 以上 | 50% 以上で、(a) に減損あり |
| (c) 有形固定資産回転率 | 売上 ÷ 有形固定資産の連続低下 | 3年 | 5年で、営業利益率も低下 |
| (d) 建設仮勘定 | 建設仮勘定 ÷ 有形固定資産 | 前3年平均の2倍以上 | それが3年続く |
| (e) 設備投資 ÷ 減価償却費 | 直近3年 | 3年続けて 0.8倍未満（設備投資が売上の 3% 未満の業態は使わない） | — |
| (f) 資金源 | 直近5年の設備投資＋子会社の取得のうち営業CF で賄えなかった割合 | 30% 以上 | 50% 以上で、① が普通以下 |
| (g) 重点テーマの継続性 | 前年から続くテーマの割合 | 50% 未満の年が2回以上 | — |
| (h) 政策保有株 | 投資有価証券 ÷ 純資産（政策保有株の代わり。銘柄ごとは brief の株式の保有状況）と3年前からの増減 | 10% 以上で増加 | 20% 以上で増加 |

**投資の質の結論**（上から順に）

| 結論 | 条件 |
|---|---|
| **懸念** | ① 投資効率・⑤ 失敗の履歴・⑥ 資金と規律のどれかが 問題あり |
| **判定保留** | ① が 不明 で、②〜④ の半分以上が 不明。または設備投資・減価償却費の時系列が無い。金融業（対象外） |
| **良好** | ① が 良好、② が 整合 か 一部、③ が 合う か 一部（④ が 低い なら 普通） |
| **普通** | 上のどれでもない |

### 4. ビルド（スクリプト）

```
$PY -I tools/analysis/investment.py build --company {company}
```

- `ok: true` → 3・4章の集計と 7章の結論を書き込み、json を作る。返り値の `verdict`・`verdict_reason`・`axes`・`points`・`themes`・`gaps` を完了報告に使う
- `ok: false` → `issues` の指摘箇所だけを直し、もう一度 build（2回まで。それでも残れば未完了として、指摘をそのまま報告する）

---

## してはいけないこと

- 5段以外の作業（追加の web 検索、raw・PDF・CSV の閲覧、数値の手計算）をしない。材料が足りなければ「不明」にして 10章に書く
- スクリプトが作るファイル（brief.md・json）と、investment.md のスクリプト記入済みの欄を手で直さない
- 出典の無い潮流の照合を `合う` にしない。延期・中止の記述がある設備計画を `予定どおり` にしない
- 有効期間内の結果を作り直さない（`--redo` はユーザーの指示があるときだけ）。過去の日付の完成済み md を変更しない（hook がブロックする）
- 投資の勧誘・推奨、「おそらく」「〜と思われる」を書かない（build が検出する）

## 完了報告（ユーザー向け）

```
## 投資の質の分析 — {name}
- 結果: {md}（機械可読: {json}）
- 投資の質: {verdict}（{verdict_reason}。前回 {previous.verdict または「初回」}）
  - ① 投資効率: {axes.efficiency}
  - ② 中計との整合: {axes.plan}
  - ③ 潮流との整合: {axes.trend}
  - ④ 競合比較: {axes.peer}
  - ⑤ 失敗の履歴: {axes.failure}
  - ⑥ 資金と規律: {axes.discipline}
- 主な投資テーマ: {themes を「、」で}
- 変化点: {points を「、」で。無ければ「なし」}
- 有効期限: {valid_until}
- 材料: {collect-company-info を実行した・しなかった。data/investments.json の有無}
- 警告: {prepare の warnings。無ければ「なし」}
- 欠損: {gaps の要点。無ければ「なし」}
```

有効期間内で再分析しなかった場合は、`latest` の md・結論・有効期限と「有効期間内のため再分析していない（作り直す場合は redo を指示）」だけを書く。
