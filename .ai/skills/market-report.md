# 地合いレポート作成スキル（market-report）

collect-market-info が集めた材料（時系列・指標表・日程・政策文書の要旨）を統合し、日米の市場動向と
短期・中期・長期の展望をまとめた**週次レポート**を作る。成果物は次の2つ。

- `market/report/{週}_market-report.html` — プレゼンテーション形式の単一 HTML（16 スライド。表紙の次が初心者向けの「今週のポイント」、最後に用語集。外部ファイル不要でオフラインでも開ける）
- `market/report/{週}_outlook.md` — 地合い（3つの軸: 金融環境・景気・市場のストレス と、注意の度合い 平常/注意/警戒）と展望。企業分析はこのファイルを参照する（10章が引き継ぎの表）
- `market/report/{週}_judgment.json` — 軸ごとの候補・採用と注意の度合い（build が書く。翌週の prepare がヒステリシスと推移の表に使う）

`{週}` は出力週の**月曜日**（YYYY-MM-DD）。同じ週に再実行すると同じファイル名になる。

数値・チャート・日程・計算した指標（実質金利・益利回りと10年債の差など）・軸ごとの評価の候補はスクリプト（`tools/report/market_report.py`）が収集データから機械的に作る。
LLM が受け持つのは outlook.md の FILL 欄（文章と、候補を変えるときの根拠）だけ。手順は **鮮度確認 → 準備 → 執筆 → ビルド** の4段に固定されている。

---

## 前提として読むファイル

- `.ai/instructions/role.md`
- `.ai/instructions/policy.md`
- `.ai/instructions/output-format.md`

---

## 引数

| 引数 | 内容 | 省略時 |
|---|---|---|
| `week` | 出力週の任意の日（YYYY-MM-DD）。その週の月曜日がファイル名になる | 今日 |
| `redo` | 完成済みの outlook.md を作り直す（ユーザーが指示したときだけ） | なし |

省略した引数は既定値を使い、その旨を完了報告に1行書く。

## 実行手順

Python は `.venv` のものを使う（Windows: `.venv\Scripts\python.exe`、macOS/Linux: `.venv/bin/python`）。以下 `$PY` と書く。

### 1. 鮮度確認（スクリプト）

```
$PY -I tools/report/market_report.py check [--week {week}]
```

標準出力は1行の JSON（`week`・`latest_session`・`fresh`・`running`・`outlook`・`html_exists`・`reason`）。

| 状態 | すること |
|---|---|
| `running` が空でない | 収集が実行中。**止めて**ユーザーに報告する（収集を横から始めない） |
| `fresh: false` | 材料が出力週より古い。collect-market-info を `market=both topic=weekly` で実行する（起動方法はエントリーポイントの指示に従う）。finalize が `ok: true` で終わったら check をもう一度実行する。`ok: true` にならなければ止めて、収集の完了報告と一緒にユーザーに報告する |
| `outlook: "done"` | この週のレポートは作成済み。ユーザーが作り直しを指示していなければ、既存の HTML の場所を伝えて終わる。指示があれば手順 2 で `--redo` を付ける |
| `fresh: true` | 手順 2 へ |

### 2. 準備（スクリプト）

```
$PY -I tools/report/market_report.py prepare --week {week} [--redo]
```

- `facts.json`（数値・チャート用系列・日程・文書一覧・計算した指標・評価の候補）・`brief.md`（執筆の材料）・`outlook.md`（FILL 欄つきの骨組み）を `market/report/` に作る
- 作成途中の outlook.md（FILL が残っている）は上書きせずに残す（`outlook_kept: true`）。続きから書く
- 標準出力の `kpis_missing`（取れなかった主要指標）・`series_failed`・`candidates`（注意の度合いの候補）・`warnings`（前週との食い違い・データの点検）は完了報告に使う

### 3. 執筆（LLM）

`brief.md` を読み、`outlook.md` の `<!-- FILL:... -->` を Edit で置き換える。

- 読むのは brief.md と outlook.md だけ。CSV・原本・要旨ファイル・status.md を個別に開かない（必要な要点は brief.md に集約済み）
- brief.md が Read の上限を超えるときは、offset/limit で分けて最後（14. 値動きの材料と市場予想）まで読む。途中までで書き始めない
- 書く順番: 8章（軸ごとの評価。候補を変えるかを決める）→ 1章の3軸と注意の度合い（8章の採用と、そこから決まる語）→ 3章 → 1章の要約 → 2章 → 4章 → 9章 → 5〜7章 → 11章（やさしい要約）
- 11章（やさしい要約）は投資を始めたばかりの人向け。「今週を3行で」は箇条書き3つ（日本・米国・今週いちばん大事な出来事）、「気をつけること」は1つ。専門用語（用語集 `tools/report/glossary.py` の語。政策金利・利上げ・長期金利・FOMC など日常的な語は除く）を使わず、数値は各項目1つまで、各60字以内。行動を勧めない。build が個数を確かめ、専門用語と文字数は warnings で知らせる
- 12章（業種の動き）はスクリプトの記入。業種の動きの理由は、14.1 の報道に出典があるときだけ 2章・3章に書ける
- 書き方の規則は outlook.md 冒頭の `>` 行と各節の説明に従う。要点:
  - 1章は、3つの軸（8章の採用と同じ語）と注意の度合い（`平常` / `注意` / `警戒`。採用から下の規則で決まる語）を書く。4章の**短期**の判断は 1章の注意の度合いと同じ語にする（build が確かめる）。中期・長期が短期と2段階離れる（平常と警戒）ときは、1章の要約にそのことを書く
  - 地合いは「いまの環境と危うさの説明」で、先行きの株価の予測ではない。「注意＝下がる」「平常＝上がる」と読める書き方をしない
  - 3章は「見たもの → 情報源 → 結論」。見たものには brief.md の数値と時点を、情報源には**原典の名前**（例: FRED（S&P500）、JPX 投資部門別売買、日銀公表文 2026-09-18）を書く。brief.md の節番号は書かない（HTML の読者は brief.md を見られない。build が warnings で知らせる）
  - 4章の展望は 短期（今後4週）・中期（6か月程度）・長期（1〜3年）。基本シナリオは「何が続く／変わる前提か」を書き、株価・為替の水準は予想しない。短期の間に FOMC・日銀会合があるときは、上振れ・下振れ要因を会合の結果で分けて書く
  - 前回の判断（brief.md 10.）から1章を変えた場合は、1章の要約に変えた理由を書く。4章の判断を前回から変えた行は、9章に理由を書く（変えなければ「変更なし」。build が確かめる）
  - 取れていない指標（—）を推測で埋めない。時点に（古い）が付いた指標は足元の根拠にしない。判断に効く欠損と brief.md 13. の要確認事項は 7章に書く
  - 文字数の目安（判断の要約 80・キーメッセージ 100・見たもの 120・結論 60・4章の各欄 60 字）を守る。キーメッセージは「**見出し**: 事実 → 意味（出典）」の形にする
- 見出し・表の列・ヘッダー・スクリプト記入済みの欄（6章の日付・イベント、8章の候補、9章の前回、10章・12章の全体）は変えない。ファイルを丸ごと書き直さない（Write は hook がブロックする）

#### 判断基準（3つの軸と注意の度合い）

地合いは **3つの軸** で表す。先行きの株価の予測ではなく、いまの環境と市場の緊張の説明である（過去10年の検証で、旧来の1語の判断はその後の騰落率と逆向きだったため、2026-10 に作り替えた）。

軸の評価はスクリプトが brief.md 12. に信号ごとに出す。各信号は −1 / 0 / +1 で、**どの軸も +1 が注意の側**。合計が **+2 以上で注意の側のラベル、−2 以下で反対側のラベル、それ以外は中間**。前週に端のラベルだった軸は、合計が 0 に戻るまでそのラベルを保つ（ヒステリシス）。取れない信号は 0 点で、推測で埋めない。しきい値は `tools/report/scoring.py` の定数にまとめてある。

| 軸 | ラベル（+2 以上 / 中間 / −2 以下） | 信号（+1 / −1 の条件） |
|---|---|---|
| 金融環境 | 引き締め / 中立 / 緩和 | 政策金利の3か月の変化（+0.10 超の引き上げ / 引き下げ）、10年債の1か月の変化（≥ +0.30 / ≤ −0.30）、実質政策金利（> 1.0% / < 0%）、基調インフレ（日本は生鮮・エネルギー除く CPI、米国はコア PCE。≥ 3.0% / < 1.5%）、原油（WTI）の前年比（≥ +30% / ≤ −30%）、米国は実質10年金利（> 2.0% / < 0.5%） |
| 景気 | 減速 / 横ばい / 拡大 | 失業率の3か月の変化（≥ +0.3 / ≤ −0.2）。日本は景気動向指数 一致・先行と鉱工業生産の3か月の変化（低下 / 上昇）、米国は雇用者数前月差の3か月平均（< 5万人 / > 15万人）、小売売上高（< 0% / > 3%）、鉱工業生産（< 0% / > 1%） |
| 市場のストレス | 高い / 普通 / 低い | HY スプレッド（米国の値を日米共通の信用指標として使う。1か月 +0.50 以上か5年での位置 80% 以上 / 1か月 −0.30 以下かつ位置 20% 以下）、IG スプレッド（米国。1か月 +0.20 以上 / −0.10 以下）、VIX（≥ 25 / ≤ 15）、指数の20日の実現変動率（日本 > 28% / < 14%、米国 > 25% / < 12%）、1年高値からの下落（≤ −10% / ≥ −3%） |

- **古い時点は半分の重み**: 月次データの信号で、その月の末日からレポート週の月曜まで45日を超えるもの（例: 10月下旬に読む8月分）は ±0.5 点
- **参考（軸に入れない）**: 1か月・12か月の騰落率、200日線、週末値の連続、海外投資家・CFTC、予想PER・益利回り。短期の反転が知られていて、緊張や環境の向きを表さないため、brief.md 12. と HTML に参考として出すだけにする

**注意の度合い**（1章。8章の採用から決まる。すべての組み合わせが当てはまる）:

| 組み合わせ | 注意の度合い |
|---|---|
| 市場のストレスが「高い」、または 金融環境が「引き締め」かつ 景気が「減速」 | 警戒 |
| 金融環境が「引き締め」、または 景気が「減速」（警戒に当たらないもの） | 注意 |
| それ以外 | 平常 |

**過去データでの検証**: `$PY -I tools/report/market_report.py backtest --years 10` で、過去の毎週を公表済みのデータだけで再現し、ラベルが意味どおりか（ストレス・注意の度合い → その後の値動きの大きさと大きな下落、金融環境 → その後の金利の変化、景気 → その後の失業率の変化）を前半・後半に分けて `market/report/backtest/` に出す。しきい値を変えるのは、前半の結果を見て案を作り、ユーザーの承認を得たときだけ。後半の結果で確かめる。

候補を変える（8章の採用を書き換える）規則:

- 変えてよいのは、信号が拾えない材料が根拠になるときだけ。例: 金融環境で、中央銀行の公表文・議事要旨（brief.md 8.）が引き続き利上げを示している。景気で、月例経済報告・ベージュブックの判断が変わった。時点の古い信号を除くと評価がずれる
- 変えたら、理由に指標と時点か文書名を書く（8字以上。build が確かめる）。変えない行の理由は「—」
- 「2段階で迷ったら注意の側」（policy.md 行動指針6）は、候補を変えるかどうかで迷ったときの1回だけ使う。軸ごとに重ねて使わない

#### 数値と情報の扱い

- 書いてよい数値: brief.md の値・変化幅・1年高値比・連続（brief.md 1. と 4. の「連続」列）・計算した指標（brief.md 11.）・信号（brief.md 12.）の転記。新しい比率・乖離率・平均を自分で計算しない（必要なら 7章に「brief に無い」と書く）
- 書いてはいけない情報: brief.md に無い因果の一般論（例: 「円安は輸出企業の収益を支える」「利上げは銀行株に追い風」）、brief.md に無い業績・需給・指数イベントの影響の推測。8. の文書要旨に同じ趣旨の記述があるとき、または 14.1 の報道（確度 一次・二次）が値動きの材料として挙げているときだけ、その文書名・報道の出典を付けて書く（検索要約の行は「〜と報じられた（検索要約）」と書く）
- 6章の注目点には、14.2 に市場予想・織り込みがあれば添える（例: 「市場予想 前年比 3.6%」）。発表後に予想との差を見られるようにするため
- 大統領令・行政文書の一覧（presidential-actions）から使うのは、金融政策（FRB の人事・独立性を含む）・財政・関税・通商・エネルギーに関わるものだけ。記念日・宣言の類は使わない

### 4. ビルド（スクリプト）

```
$PY -I tools/report/market_report.py build --week {week}
```

- `ok: true` → `html` に出力先、`judgments` に日米の注意の度合い、`candidates` にスクリプトの候補、`overrides` に候補から変えた軸が入り、`judgment.json` を書く。`warnings` を見る
  - 情報源に brief.md の節番号が残っている → 指摘された欄を原典の名前に直して build をやり直す（文字数の直しと合わせて1回まで）
  - 文字数の目安超え（「目安 N 字を超える」）→ 指摘された欄を Edit で短くして build をやり直す（1回まで）。数値や判断は変えない
  - 11章に専門用語がある → ふだんの言葉に言い換えて build をやり直す（上と合わせて1回まで）
  - それ以外（作成途中の outlook.md が古い収集から作られている など）→ 完了報告に書く。自分では `--redo` しない
- `ok: false` → `issues` の指摘箇所だけを Edit で直し、もう一度 build（2回まで。それでも残れば未完了として、指摘をそのまま報告する）

## してはいけないこと

- 4段以外の作業（追加の web 検索、CSV や原本の閲覧、数値の手計算・手入力）をしない。材料が足りなければ 7章に書く
- スクリプトが作るファイル（`facts.json`・`brief.md`・`judgment.json`・`*_market-report.html`）を手で直さない（hook がブロックする）
- 過去の週の完成済み outlook.md を変更しない。`--redo`・`--allow-stale` は自分の判断で使わない（ユーザーの指示があるときだけ）
- 投資の勧誘・推奨、株価・為替の水準予想、「おそらく」「〜と思われる」を書かない（build が検出する）

※ グローバル設定の hook（Fact-Forcing Gate）が、最初の Bash と、ファイルごとの最初の Edit を一度差し戻すことがある。求められた事実を示して同じ操作を再実行すれば通る。並列に出した Edit は、差し戻された1件だけを再実行する（ほかは通っている）。

## 完了報告（ユーザー向け）

build の JSON と prepare の JSON（collect-market-info を実行した場合はその finalize の JSON も）だけを使い、次の形式で短く報告する。

```
## 地合いレポート — {week} 週
- レポート: {html}（判断の根拠: {outlook}）
- 注意の度合い: 日本 {judgments.japan}（3軸 {金融環境・景気・市場のストレス}、前回 {previous.japan または「初回」}・候補 {candidates.japan}）/ 米国 {judgments.us}（…）
  - 決め手: {日米それぞれ1行。1章の要約を短くしたもの}
  - 候補から変えた軸: {overrides。無ければ「なし」}
- 材料: 収集セッション {session}（今回 collect-market-info を実行した / しなかった）
- 収集: {実行した場合だけ。時系列 取得 {series_ok} / 失敗 {len(series_failed)}、新しい文書 {len(new_docs)} 件、タスク {tasks_done}/{tasks_total}、範囲外の変更 {なし / 一覧}}
- 欠損: 主要指標 {kpis_missing を列挙。無ければ「なし」}、取得失敗の系列 {series_failed} 件、判断に効く欠損 {outlook.md 7章の要点を2〜3個}
- 要確認: {prepare の warnings（前週との食い違い・データの点検）。無ければ行ごと省く}
- 注意: {build の warnings。無ければ行ごと省く}
- 次にやること: {例: FRED_API_KEY を設定すると株価指数が取れる}
```

省略して既定値を使った引数（`week` など）は、最後に1行で書く。
