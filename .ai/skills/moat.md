# モート分析スキル（moat）

`企業分析フレームワーク.md` の **STEP 1-3 経済的な堀（モート）分析**（強みの持続性。モート 広い / 狭い / なし。材料不足なら 判定保留）を、
collect-company-info・collect-market-info・market-report が集めた材料と、three-c（STEP 1-2）・five-forces（STEP 1-1）の結果から行う。成果物は次の3つ。

- `companies/{ticker}_{name}/analysis/moat/{日付}_moat.md` — 分析結果。企業分析レポート・SWOT はこれ（と json）を参照する
- `.../{日付}_moat.json` — 同じ結果の機械可読版（モート5種の判定・営業利益率の同業比較・コスト構造・シェアの推移・崩しうる要因・裏付け・結論・SWOT/STEP 2 への引き継ぎ・有効期限）
- `.../{日付}_brief.md` — 執筆の材料（raw から必要な節を抜き出し、営業利益率の同業比較と判定候補を計算したもの）

`{日付}` は分析日。結果は **365日有効**で、期間内は再実行しても既存の結果を返すだけにする。
ただし期限前でも、新しい期の有報、業界データ・中期経営計画の新しい収集、または3Cの結論が変わったときは再分析する。競合・株価・事業概要の取り直しや、同じ期の数値の訂正だけでは再分析しない（有効期限を待つ）。上流の分析は作り直されても結論が同じなら再分析しない（`tools/analysis/freshness.py`）。

抽出・数値の計算（自社と同業平均の営業利益率の年次比較・連続して上回った年数・コスト構造の表）・材料の過不足の判定・検証・**数字の裏付け（強い/弱い/なし/不明）と結論（広い/狭い/なし/判定保留）の判定**はスクリプト（`tools/analysis/moat.py`）が行う。
LLM が受け持つのは moat.md の FILL 欄（モート5種の判定と根拠・シェアの推移・崩しうる要因・引き継ぎ）だけ。手順は **企業の選択 → 鮮度確認 → 準備 → 執筆 → ビルド** に固定されている。

## 実行手順

Python は `.venv` のものを使う（Windows: `.venv\Scripts\python.exe`、macOS/Linux: `.venv/bin/python`）。以下 `$PY` と書く。
各コマンドの標準出力は1行の JSON。

### 0. 企業の選択（`company` が無いときだけ）

```
$PY -I tools/analysis/moat.py list
```

`companies` の各行（`dir`・`name`・`last_collected`・`moat`・`moat_date`・`verdict`・`three_c`）から選択肢を作り、ユーザーに選んでもらう（提示の方法はエントリーポイントの指示に従う）。
企業が1社だけなら選択肢を出さずにその企業で進み、完了報告の「材料」行に「対象は1社だけのため選択を省略」と書く。
選択肢には `moat` の状態（`none` 未分析 / `fresh` 有効 / `expired` 期限切れ / `triggered` 新しい raw・3Cあり / `draft` 作成途中）と、3Cの状態（`fresh` 以外なら先に実行される）を添える。
一覧に無い企業を指定されたら、手順 1 の `company_missing` と同じ扱いにする。

### 1. 鮮度確認（スクリプト）

```
$PY -I tools/analysis/moat.py check --company {company}
```

`next` に従う。

| `next`・状態 | すること |
|---|---|
| `ok: false` で `candidates` あり | 複数の企業が当たった。候補からユーザーに選んでもらい、もう一度 check |
| `ok: false` で `company_missing: true` | 企業の情報が無い。ユーザーにホームページ URL を確認し、collect-company-info を `mode=full` で実行してから check をやり直す |
| `report_existing`（`result: fresh`） | 有効期間内。`latest`（md・結論・有効期限）を完了報告の形式で伝えて**終わる**（執筆しない）。`redo` の指示があるときだけ手順 2 へ |
| `collect` で `needs_full_collect: true` | raw が無い。collect-company-info を `mode=full` で実行し、check をやり直す |
| `three_c` | 3C分析（STEP 1-2）の結果が無い・期限切れ・再分析要・作成途中（`three_c.result`）。**three-c スキルを最後の完了報告まで実行**してから check をやり直す（ファイブフォース・材料の収集が要れば three-c の中で行われる） |
| `collect` | モートに必須の材料が足りない（節が無い・空・中身が薄い）、または営業利益率を同業と比べられた年が7年未満で、どの年も同業平均を上回っている（古い年を集めれば「強い」になりうる。項目は「競合: 営業利益率の推移（7年以上）」）。collect-company-info を `mode=update` で実行し、`missing_inputs` の担当（`agent`）と項目（`items`）を範囲として伝える。終わったら check をやり直す |
| `prepare`（`none` / `expired` / `triggered` / `draft`） | 手順 2 へ |

- **3C の結論（勝てる理由 なし・判定保留）ではモート分析を止めない**。3C の結論は md のヘッダーと1章に記録され、執筆の前提になる
- 地合い（outlook.md）は md のヘッダーで参照するだけで、モートの判断には使わない。古くても（`outlook_stale: true`）market-report・collect-market-info は実行しない。完了報告の「材料」行に「地合いは N 日前の週（古い）」と書く
- three-c の実行は**1回の実行につき1回まで**。やり直した check でまだ `three_c` が出たら（three-c が止まった・作成途中のまま）、このスキルも止めて状況を報告する。three-c を実行したときは、その理由（`three_c.reason`。期限切れ・新しい raw・作成途中など）と結論が前回から変わったかを完了報告の「材料」行に書く
- 収集（collect-company-info）は**1回の実行につき1回まで**（three-c・five-forces の中で収集した場合も1回と数える）。やり直した check でまだ `collect` が出ても、もう一度は収集せず手順 2 に `--skip-collect` を付けて進む（取れなかった材料に関わる判定は「不明」として扱い、8章に書く）
- check と prepare を1つのコマンドにつなげない（check の `next` を見てから次へ進む）。prepare も `next` を確かめ、`three_c`・`collect` のままなら `ok: false` で拒否する
- `unavailable` は「収集を試みたが取れなかった」材料（status.md の未取得項目）。再収集しない
- 収集スキル・three-c が止まった（ユーザーへの確認待ち・エラー）ときは、このスキルも止めて状況を報告する

### 2. 準備（スクリプト）

```
$PY -I tools/analysis/moat.py prepare --company {company} [--redo] [--skip-collect]
```

- `{日付}_brief.md`（材料）と `{日付}_moat.md`（FILL つきの骨組み）を作る。返り値の `brief`・`md` がそのパス
- 骨組みには、**1章の3Cの結論と強み候補**、スクリプトが計算した **3.1 営業利益率の同業比較**（年度ごとの自社・同業平均・差・比較した競合と決算期）と判定候補、**3.2 コスト構造**（competitors.md の表と競合の単純平均）、前回の判定が記入済み。brief には同じ表を載せない
- 作成途中の md（FILL が残っている）は上書きせず残す（`kept: true`）。続きから書く
- 一字も書いていない骨組み（前回の prepare が書いたままの md）は、`--redo` なしで作り直す（`regenerated: true`）。材料が変わった・スクリプトを直したときは prepare をもう一度実行すればよい
- `--redo` は完成済みの結果（有効期間内）と書きかけの md を作り直すときだけ使う（ユーザーの指示があるときだけ）。同じ日に build 済みの結果があると `--redo` は拒否される。その日の md を Edit で直して build し直す
- `warnings`（brief の「警告」節にも出る）は、スクリプトが raw を読み違えた可能性（表の列がすべて読めない、自社の営業利益率が出典で違うなど）。空でなければ、執筆の前に該当する表を確かめ、完了報告の「警告」行に書く
- `candidates.margin` はスクリプトの判定候補（営業利益率が同業平均を連続で上回った年数 `years_above` から 強い/弱い/なし。確定）。シェアの推移と合わせた「数字の裏付け」は build が決める

### 3. 執筆（LLM）

brief.md を読み、moat.md の `<!-- FILL:... -->` を Edit で置き換える。

- 読むのは brief.md と moat.md だけ。raw・PDF・CSV・summaries を個別に開かない（必要な節は brief.md に集約済み）
- brief.md が Read の上限を超えるときは、offset/limit で分けて最後（取れていない材料）まで読む
- 書く順番と Edit の単位（各1回）: 1章の「確かめる強み」 → 2章の表 → 3.3 の表 → 4章の要因の表 → 4章の持続の見込み → 6章の表 → 7章 → 8章
- 書き方の規則は moat.md 冒頭の `>` 行に従う。要点:
  - 1章の「確かめる強み」は、3C の勝てる理由・強み候補から持続性を確かめる強みを1〜2文。3C が「なし」「判定保留」でも止めず、その旨と代わりに確かめる自社の事実（brief 0章の SWOT の強み候補・モート分析で確かめること）を書く
  - 2章は5行（ブランド / スイッチングコスト / ネットワーク効果 / コスト優位 / 規制・特許・許認可 の順・この名前）。判定は `該当` / `該当なし` / `不明` の1語。下の判断基準に当てた**事実と数値**を根拠に書く。会社の主張（IR 資料の自己評価）だけで「該当」にしない。材料が無ければ「不明」（良い方に解釈しない）
  - 「該当」には情報源と根拠の確度（`一次` / `二次` / `参考`）が要る。「該当なし」「不明」で根拠が無ければ確度は `—` でよい
  - コスト優位は 3.2 の原価率・販管費率と 3.1 の営業利益率を同業と比べて判断する（競合平均は 3.2 の「競合の単純平均」の行を転記する。手で計算しない）
  - 3.3 のシェアの推移は `拡大` / `安定` / `横ばい〜微減` / `低下` / `不明` の1語。brief「シェアの推移の材料」の数値で決める。推移が無く一時点の値しか無ければ「不明」
  - 4章は崩しうる要因（技術革新・特許切れ・規制緩和・新たな代替手段・顧客の内製化など）を1行ずつ。時期は `5年以内` / `5〜10年` / `10年超・不明` の1語。brief「持続性の材料」（業界構造を変えうる要因・事業等のリスク）とファイブフォースの新規参入・代替品から書く。具体的な要因が無ければ1行目を `なし` にし、確認した資料を根拠に書く
  - 4章の持続の見込みは「モートは〇年程度持続する見込み。リスク要因は〇〇」の1文
  - 6章は後続の分析への引き継ぎ（SWOT の強み・脅威候補、STEP 2 の整合性チェックで見る数値、評価が変わる条件）
  - 2段階で迷ったら**不利な方**を採り（policy.md 行動指針6）、根拠・理由に「迷った:」で始まる文を入れる
  - 前回の判定と違う判定にするときは、根拠・理由に「前回から変更:」で始まる文を入れ、7章にも書く。前回と同じ材料なら同じ判定にする
  - 根拠に書く事実は brief.md の記述と同じ強さで書く。brief で「未確認」「要旨」とある事柄を確認済みの事実として書かない
  - 表のセルに `|` を書かない。5章（結論）は build が書くので触らない
- 見出し・表の列・ヘッダー・スクリプト記入済みの欄（1章の3Cの結論と強み候補・3.1・3.2・前回の判定）は変えない。ファイルを丸ごと書き直さない（Write は hook がブロックする）

#### 判断基準（企業分析フレームワーク.md 1-3 の転記）

**手順1 モートの特定**（LLM が 該当 / 該当なし / 不明 を判定）

| モートの種類 | 見るもの | 該当と判断する根拠の例 |
|---|---|---|
| ブランド | 価格水準、値上げ後の販売数量 | 競合より高価格でもシェアを維持、値上げ後も数量の減少が小さい |
| スイッチングコスト | 継続率・解約率、ストック型売上の比率、製品の業務への組み込み度 | 継続率が高い（例：90%以上）、乗り換えに多大な時間・費用・リスクが伴う |
| ネットワーク効果 | 利用者数の推移、1位と2位のシェア差 | 利用者が増えるほど価値が上がる構造で、1位と2位の差が拡大傾向 |
| コスト優位 | 売上原価率・販管費率の同業比較 | 同業より低コストで、同等以上の利益率を出している |
| 規制・特許・許認可 | 主要特許の期限、必要な許認可 | 主力製品が有効期限の長い特許や取得困難な許認可で守られている |

**手順2 数字の裏付け**（build が判定。参考）

- スクリプト: 自社の営業利益率（data/ の CSV → raw の財務時系列・有報 → competitors.md の自社欄。会社予想は除く）と、competitors.md の競合（最大5社）の営業利益率を、決算期が6か月以内の年度どうしで突き合わせ、競合の単純平均と比べる。直近の比較できる年から遡って**連続で上回った年数**が 7年以上 → 強い候補、1〜6年 → 弱い候補、直近が平均以下 → なし。比べられなければ候補なし
- build: 上の候補と 3.3 のシェアの推移を合わせる

| 数字の裏付け | 条件 |
|---|---|
| **不明** | 営業利益率を同業と比べられない |
| **なし** | 営業利益率が直近で同業平均以下、またはシェアが 低下 |
| **強い** | 7年以上連続で同業平均を上回り、かつシェアが 拡大・安定 |
| **弱い** | それ以外（上回るのが7年未満、またはシェアが 横ばい〜微減・不明） |

- 裏付けが **なし** のとき、2章で「該当」としたモートを build が「該当なし」に修正する（フレームワークの規則）

**手順3 持続性**: 今後5〜10年以内にモートを崩す具体的な要因があるか（4章）。

**手順4 モートの強さ**（build が判定。上から順に当てはめる）

| 結論 | 条件 |
|---|---|
| **なし** | 「該当」のモートが無い |
| **なし** | 数字の裏付けが 不明（裏付けの無いモートは該当しないため、該当したモートを該当なしとみなす（材料不足のため保守的に判定。結果 JSON の conservative に記録）） |
| **なし** | 数字の裏付けが なし（該当を「該当なし」に修正） |
| **広い** | 該当が2つ以上、裏付けが 強い、かつ 5年以内 の要因なし |
| **狭い** | 上のどれでもない（該当が1つ、裏付けが 弱い、5年以内 の要因あり のいずれか） |

### 4. ビルド（スクリプト）

```
$PY -I tools/analysis/moat.py build --company {company}
```

- `ok: true` → md の5章に結論を書き込み、json を作る。返り値の `verdict`・`verdict_reason`・`effective_moats`（残ったモート）・`claimed_moats`・`corrected`（裏付けなしで修正したか）・`backing`・`backing_reason`・`share`・`near_risks`（5年以内の要因）・`durability`・`tie_breaks`（迷った判定）・`low_confidence`（根拠の確度が参考の判定）・`unknown`（不明の判定）・`gaps`（8章の全件）を完了報告に使う
- `ok: false` → `issues` の指摘箇所だけを Edit で直し、もう一度 build（2回まで。それでも残れば未完了として、指摘をそのまま報告する）

## してはいけないこと

- 5段以外の作業（追加の web 検索、raw・PDF・CSV の閲覧、数値の手計算）をしない。材料が足りなければ「不明」にして 8章に書く
- スクリプトが作るファイル（brief.md・json）と、moat.md の1章の3Cの結論・強み候補・3.1・3.2・前回の判定・5章を手で直さない
- 有効期間内の結果を作り直さない（`--redo` はユーザーの指示があるときだけ）。過去の日付の完成済み md を変更しない（hook がブロックする）
- 投資の勧誘・推奨、「おそらく」「〜と思われる」を書かない（build が検出する）
- 収集担当（collect-company-info）へのプロンプトで、raw の書き方（範囲外の章に「変更なし」と書く、前回の表を再掲するなど）を指示しない。書き方は collect-company-info.md の保存ルールに任せる（「変更なし」の節や再掲は、前回の材料を隠したり上流の分析を再実行させたりする）

※ グローバル設定の hook（Fact-Forcing Gate）が、最初の Bash と、ファイルごとの最初の Edit を一度差し戻すことがある。求められた事実を示して同じ操作を再実行すれば通る。

## 完了報告（ユーザー向け）

check・prepare・build の JSON（three-c・収集を実行した場合はその完了報告も）だけを使い、次の形式で短く報告する。

```
## モート分析 — {name}
- 結果: {md}（機械可読: {json}）
- モートの強さ: {verdict}（{verdict_reason}。前回 {previous.verdict または「初回」}）
  - 該当するモート: {effective_moats を「、」で。無ければ「なし」。corrected なら「{claimed_moats} を裏付けなしで修正」}
  - 数字の裏付け: {backing}（{backing_reason}）　シェアの推移: {share}
  - 持続の見込み: {durability}（5年以内の要因: {near_risks。無ければ「なし」}）
- 判断が分かれた判定: {tie_breaks。無ければ「なし」} / 根拠が参考情報だけの判定: {low_confidence。無ければ「なし」} / 不明の判定: {unknown。無ければ「なし」}
- 有効期限: {valid_until}（それまでは再実行しても再分析しない）
- 材料: {3C {three_c.date}（勝てる理由 {three_c.verdict}）。今回 three-c・collect-company-info を実行した・しなかった（three-c を実行したならその理由と、結論が前回から変わったか。--skip-collect で進んだならその項目）。地合いが古ければ「地合いは N 日前の週（古い）」。1社のため選択を省略したならその旨。unavailable があれば列挙}
- 警告: {prepare の warnings。無ければ「なし」}
- 欠損: {gaps の全件の要点。無ければ「なし」}
- 次に集める材料: {verdict が「判定保留」のときだけ。競合の営業利益率の推移（collect-peers-valuation）。collect-company-info で集めると新しい raw として再分析の対象になる}
```
