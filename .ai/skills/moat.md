# モート分析スキル（moat）

`企業分析フレームワーク.md` の **STEP 1-3 経済的な堀（モート）分析**（強みが資本コストを上回る利益として表れ、それが続くか。モート 広い / 狭い / なし。材料不足なら 判定保留）を、
collect-company-info・collect-market-info・market-report が集めた材料と、three-c（STEP 1-2）・five-forces（STEP 1-1）の結果から行う。成果物は次の3つ。

- `companies/{ticker}_{name}/analysis/moat/{日付}_moat.md` — 分析結果。企業分析レポート・SWOT はこれ（と json）を参照する
- `.../{日付}_moat.json` — 同じ結果の機械可読版（超過収益（ROIC と資本コスト）・価格決定力・6種の源泉の判定・営業利益率の同業比較・コスト構造・シェアの推移・崩しうる要因・幅/深さ/拡張性・堀の傾向・結論・SWOT/STEP 2 への引き継ぎ・有効期限。`version: 2`）
- `.../{日付}_brief.md` — 執筆の材料（raw から必要な節を抜き出し、ROIC・粗利率・営業利益率の同業比較を計算したもの）

`{日付}` は分析日。結果は **365日有効**で、期間内は再実行しても既存の結果を返すだけにする。
ただし期限前でも、新しい期の有報、業界データ・中期経営計画の新しい収集、または3Cの結論が変わったときは再分析する。競合・株価・事業概要の取り直しや、同じ期の数値の訂正だけでは再分析しない（有効期限を待つ）。上流の分析は作り直されても結論が同じなら再分析しない（`tools/analysis/freshness.py`）。

抽出・数値の計算（ROIC と資本コストの差・経済的利益・差の傾向、粗利率と価格決定力、営業利益率の同業比較、コスト構造の表）・材料の過不足の判定・検証・**超過収益（強い/弱い/なし/不明）・堀の幅・堀の傾向・結論（広い/狭い/なし/判定保留）の判定**はスクリプト（`tools/analysis/moat.py`。計算は `mt_returns.py`・`mt_metrics.py`）が行う。
LLM が受け持つのは moat.md の FILL 欄（6種の源泉の判定と根拠・シェアの推移・崩しうる要因・深さ・拡張性・引き継ぎ）だけ。手順は **企業の選択 → 鮮度確認 → 準備 → 執筆 → ビルド** に固定されている。

## 実行手順

Python は `.venv` のものを使う（Windows: `.venv\Scripts\python.exe`、macOS/Linux: `.venv/bin/python`）。以下 `$PY` と書く。
各コマンドの標準出力は1行の JSON。

### 0. 企業の選択（`company` が無いときだけ）

```
$PY -I tools/analysis/moat.py list
```

`companies` の各行（`dir`・`name`・`last_collected`・`moat`・`moat_date`・`verdict`・`three_c`）から選択肢を作り、ユーザーに選んでもらう（提示の方法はエントリーポイントの指示に従う）。
企業が1社だけなら選択肢を出さずにその企業で進み、完了報告の「材料」行に「対象は1社だけのため選択を省略」と書く。
選択肢には `moat` の状態（`none` 未分析 / `fresh` 有効 / `expired` 期限切れ / `triggered` 新しい raw・3Cあり / `draft` 作成途中）と、3Cの状態（`fresh` 以外なら先に実行される）を添える。
一覧に無い企業を指定されたら、手順 1 の `company_missing` と同じ扱いにする。

### 1. 鮮度確認（スクリプト）

```
$PY -I tools/analysis/moat.py check --company {company}
```

`next` に従う。

| `next`・状態 | すること |
|---|---|
| `ok: false` で `candidates` あり | 複数の企業が当たった。候補からユーザーに選んでもらい、もう一度 check |
| `ok: false` で `company_missing: true` | 企業の情報が無い。ユーザーにホームページ URL を確認し、collect-company-info を `mode=full` で実行してから check をやり直す |
| `report_existing`（`result: fresh`） | 有効期間内。`latest`（md・結論・有効期限）を完了報告の形式で伝えて**終わる**（執筆しない）。`redo` の指示があるときだけ手順 2 へ |
| `collect` で `needs_full_collect: true` | raw が無い。collect-company-info を `mode=full` で実行し、check をやり直す |
| `three_c` | 3C分析（STEP 1-2）の結果が無い・期限切れ・再分析要・作成途中（`three_c.result`）。**three-c スキルを最後の完了報告まで実行**してから check をやり直す（ファイブフォース・材料の収集が要れば three-c の中で行われる） |
| `collect` | モートに必須の材料が足りない（節が無い・空・中身が薄い）、または ROIC を計算できた年が5年未満（超過収益が不明。項目は「財務時系列: 営業利益・自己資本・有利子負債（5年以上。ROIC の計算）」）。collect-company-info を `mode=update` で実行し、`missing_inputs` の担当（`agent`）と項目（`items`）を範囲として伝える。終わったら check をやり直す |
| `prepare`（`none` / `expired` / `triggered` / `draft`） | 手順 2 へ |

- **3C の結論（勝てる理由 なし・判定保留）ではモート分析を止めない**。3C の結論は md のヘッダーと1章に記録され、執筆の前提になる
- 地合い（outlook.md）は md のヘッダーで参照するだけで、モートの判断には使わない。古くても（`outlook_stale: true`）market-report・collect-market-info は実行しない。完了報告の「材料」行に「地合いは N 日前の週（古い）」と書く
- three-c の実行は**1回の実行につき1回まで**。やり直した check でまだ `three_c` が出たら（three-c が止まった・作成途中のまま）、このスキルも止めて状況を報告する。three-c を実行したときは、その理由（`three_c.reason`。期限切れ・新しい raw・作成途中など）と結論が前回から変わったかを完了報告の「材料」行に書く
- 収集（collect-company-info）は**1回の実行につき1回まで**（three-c・five-forces の中で収集した場合も1回と数える）。やり直した check でまだ `collect` が出ても、もう一度は収集せず手順 2 に `--skip-collect` を付けて進む（取れなかった材料に関わる判定は「不明」として扱い、11章に書く）
- インストールベース・セグメント情報・参入と撤退・外部の評価・競合の貸借（ROIC 用）は**必須ではない**（無くても収集を求めない）。brief の「取れていない材料」に出るので、判定が「不明」になったら完了報告の「次に集める材料」に書く
- check と prepare を1つのコマンドにつなげない（check の `next` を見てから次へ進む）。prepare も `next` を確かめ、`three_c`・`collect` のままなら `ok: false` で拒否する
- `unavailable` は「収集を試みたが取れなかった」材料（status.md の未取得項目）。再収集しない
- 収集スキル・three-c が止まった（ユーザーへの確認待ち・エラー）ときは、このスキルも止めて状況を報告する

### 2. 準備（スクリプト）

```
$PY -I tools/analysis/moat.py prepare --company {company} [--redo] [--skip-collect]
```

- `{日付}_brief.md`（材料）と `{日付}_moat.md`（FILL つきの骨組み）を作る。返り値の `brief`・`md` がそのパス
- 骨組みには、**1章の3Cの結論と強み候補**、スクリプトが計算した **2.1 ROIC と資本コスト**（年度ごとの営業利益・投下資本・ROIC・差・同業 ROIC の中央値・境界の年、経済的利益と超過収益の判定）、**2.2 営業利益率の同業比較**（同業中央値）、**3.1 粗利率の推移と価格決定力**、**3.2 コスト構造**、**7章の幅**、前回の判定が記入済み。brief には同じ表を載せない
- 作成途中の md（FILL が残っている）は上書きせず残す（`kept: true`）。続きから書く
- 一字も書いていない骨組み（前回の prepare が書いたままの md）は、`--redo` なしで作り直す（`regenerated: true`）。材料が変わった・スクリプトを直したときは prepare をもう一度実行すればよい
- `--redo` は完成済みの結果（有効期間内）と書きかけの md を作り直すときだけ使う（ユーザーの指示があるときだけ）。同じ日に build 済みの結果があるときの `--redo` は、その日の md・json・brief を `analysis/{種類}/_superseded/{日付}-{n}/` に退避してから作り直す（返り値の `superseded`。退避した結果は消さず、最新の結果としては読まれない）。小さな直しだけなら、その日の md を Edit で直して build し直してもよい
- `warnings`（brief の「警告」節にも出る）は、スクリプトが raw を読み違えた可能性（表の列がすべて読めない、自社の営業利益率が出典で違うなど）。空でなければ、執筆の前に該当する表を確かめ、完了報告の「警告」行に書く
- `candidates` はスクリプトの判定（`returns` 超過収益・`roic_years`・`width` 堀の幅・`spread_trend` 差の傾向・`pricing` 価格決定力・`margin` 営業利益率の同業比較（参考））。どれも確定で、書き手は変えられない

### 3. 執筆（LLM）

brief.md を読み、prepare の返り値 `fill_spec`（書く欄のキー・指示・表のセルかどうか）に従って本文を書く。moat.md を開いて FILL を探さなくてよい。

- 書いた本文は `{"FILL のキー": "本文"}` の JSON 1つにまとめて、返り値の `fills_json`（md と同じ場所の `{日付}_fills.json`）に Write し、`$PY -I tools/analysis/moat.py fill --company {company} --build` で流し込んで build する（表のセルの本文は1行にまとめられ、`|` は `｜` に置き換わる。FILL が残っていれば build せず `remaining` を返すので、その欄を書いて JSON を作り直す）。md の FILL を Edit で置き換えてもよい
- `strengths`・`threats`・`changes`・`gaps`（返り値の `filled_at_build`）は、ほかの欄を書き終えると build が書き手の行から記入する。書かない
- 読むのは brief.md だけ（moat.md は build の指摘を直すときだけ開く）。brief の「〜と同じ内容のため省略」は同じ日のほかの分析の brief の節で、読んでいなければその節だけを読む。raw・PDF・CSV・summaries を個別に開かない（必要な節は brief.md に集約済み）
- brief.md が Read の上限を超えるときは、offset/limit で分けて最後（取れていない材料）まで読む
- 書く順番（`fill_keys` にあるものだけ）: 1章の「確かめる強み」 → 4章の源泉の表 → 5章のシェアの推移 → 6章の要因の表 → 6章の持続の見込み → 7章の深さ・拡張性 → 9章の表
- 書き方の規則は moat.md 冒頭の `>` 行に従う。要点:
  - **まず brief 1章の超過収益を見る**。超過収益が「なし」なら、源泉を「強」「中」にしても結論は「なし」になる（数字に表れていない仕組みはモートとはみなさない）。源泉の判定は、超過収益がどの仕組みから生まれているかを説明できるものだけを「強」「中」にする
  - 1章の「確かめる強み」は、3C の勝てる理由・強み候補から持続性を確かめる強みを1〜2文。3C が「なし」「判定保留」でも止めず、その旨と代わりに確かめる自社の事実（brief 0章の SWOT の強み候補・モート分析で確かめること）を書く
  - 4章は6行（ブランド / 規制・特許・許認可 / スイッチングコスト / ネットワーク効果 / コスト優位 / 効率的規模 の順・この名前。最初の2つは無形資産）。判定は `強` / `中` / `弱` / `該当なし` / `不明` の1語
    - 「強」「中」は**仕組みの事実**（なぜ競合が奪えないか）と**数値の痕跡**（その仕組みが数字に表れていること）の両方、情報源、根拠の確度（`一次` / `二次` / `参考`）が要る。build が空欄を拒否する
    - 「強」は数値の痕跡が同業との比較や長期の推移で示せるもの（継続率 90% 以上が5年続く、粗利率が同業より 10pt 高く安定、など）。一時点の値や自社だけの値なら「中」まで
    - 仕組みはあるが数値の痕跡が無い、または会社の主張（IR 資料の自己評価）だけなら「弱」。材料が無ければ「不明」（良い方に解釈しない）。「該当なし」「不明」でも、仕組みか数値の痕跡の欄に確認した資料を書く
    - コスト優位は 3.2 の原価率・販管費率と 2.1 の ROIC・2.2 の営業利益率を同業と比べて判断する（競合平均は 3.2 の「競合の単純平均」の行を転記する。手で計算しない）
    - ブランドの数値の痕跡には 3.1 の価格決定力（粗利率の安定・原価高の局面での変化・同業との差）を使える
  - 5章のシェアの推移は `拡大` / `安定` / `横ばい〜微減` / `低下` / `不明` の1語。brief「シェアの推移の材料」の数値で決める。推移が無く一時点の値しか無ければ「不明」
  - 6章は崩しうる要因を1行ずつ。分類は `技術` / `規制` / `顧客行動` / `破壊的イノベーション` / `内製化` / `その他`、時期は `5年以内` / `5〜10年` / `10年超・不明` の1語。brief「持続性の材料」（業界構造を変えうる要因・事業等のリスク）とファイブフォースの新規参入・代替品から書く。具体的な要因が無ければ1行目を `なし` にし、確認した資料を根拠に書く
  - 6章の持続の見込みは「モートは〇年程度持続する見込み。リスク要因は〇〇」の1文。過去に堀があったことと今後も続くことを分けて書く
  - 7章の深さは `深い` / `中程度` / `浅い` / `不明`（競合が同じものを作るのに要る時間・投資・累積した資産と、重なっているモートの数）、拡張性は `あり` / `限定的` / `なし` / `不明`（中期経営計画などの新しい領域で同じ仕組みが効くか）。幅はスクリプトが記入済み
  - 9章は後続の分析への引き継ぎ（STEP 2 の整合性チェックで見る数値、評価が変わる条件）
  - 2段階で迷ったら**不利な方**を採り（policy.md 行動指針6）、根拠・理由に「迷った:」で始まる文を入れる
  - 前回の判定と違う判定にするときは、仕組み・理由に「前回から変更:」で始まる文を入れる（前回が旧基準（該当/該当なし/不明）の結果なら不要。build が比べない）。前回と同じ材料なら同じ判定にする
  - 根拠に書く事実は brief.md の記述と同じ強さで書く。brief で「未確認」「要旨」とある事柄を確認済みの事実として書かない。brief「外部の評価」は判定の根拠にしない（結論と食い違うときに理由を確かめるためだけに使う）
  - 表のセルに `|` を書かない。8章（結論）は build が書くので触らない
- 見出し・表の列・ヘッダー・スクリプト記入済みの欄（1章の3Cの結論と強み候補・2章・3章・7章の幅・前回の判定）は変えない。ファイルを丸ごと書き直さない（Write は hook がブロックする）

#### 判断基準（企業分析フレームワーク.md 1-3 の転記）

**手順1 超過収益**（スクリプトが判定。参考）

- ROIC = 営業利益 ×（1 − 法定実効税率。日本 30.6%・米国 25%）÷ 投下資本（自己資本 + 有利子負債の期首と期末の平均。現金は控除しない）。営業赤字の年は税を引かない。資本コストは日本株 7%・米国株 9% の固定値（`mt_returns.py` の `HURDLE`）。差が ±2pt 以内の年は「境界」
- 自己資本・有利子負債・営業利益は data/financials.csv（EDINET・EDGAR）と raw の有報・財務時系列から読む。競合の ROIC は competitors.md の営業利益率 ×「収益性の分解」の売上高 ÷（自己資本 + 有利子負債）で、同業の中央値として参考に示す

| 超過収益 | 条件（直近最大10年） |
|---|---|
| **不明** | ROIC を計算できた年が5年未満（ただし直近3年がすべて資本コスト以下、または営業赤字なら なし） |
| **なし** | 資本コストを上回った年が半分未満、または直近3年の差の平均が 0 以下 |
| **強い** | 7年以上の推移があり、8割以上の年で上回り、差の中央値が +5pt 以上 |
| **弱い** | それ以外 |

- 堀の幅: 直近3年の差の平均が +10pt 以上 大 / +3pt 以上 中 / 0 超 小 / 0 以下 なし
- 差の傾向: 直近5年の差の平均とそれより前の年の平均を比べ、+2pt 以上 拡大 / −2pt 以下 縮小 / ほか 安定（6年未満は 不明）
- 価格決定力: 粗利率が原価高の局面（2021→2023年度）で 2pt 以上低下か振れ幅 10pt 超 → 弱い、低下せず振れ幅 5pt 以内で同業の中央値以上 → 強い、ほか 普通（5年未満は 不明）
- 営業利益率の同業比較（2.2）は同業の**中央値**と比べ、連続で上回った年数を参考に示す（判定には使わない）

**手順2 源泉の特定**（LLM が 強 / 中 / 弱 / 該当なし / 不明 を判定）

| モートの種類 | 仕組みの事実（例） | 数値の痕跡（例。開示が無い業種の代わりの指標を含む） |
|---|---|---|
| ブランド（無形資産） | 指名買い、価格プレミアム | 競合より高価格でもシェアを維持、値上げ後も数量の減少が小さい、粗利率が同業より高く安定（3.1） |
| 規制・特許・許認可（無形資産） | 主力製品を守る特許、取得が難しい許認可 | 主要特許の期限と件数の推移、許認可の保有社数 |
| スイッチングコスト | 業務への組み込み、認定・採用の手続き、データ移行の負担 | 継続率が高い（例：90%以上）、保守・サービス・消耗品売上の比率、設置台数、主要顧客との取引年数 |
| ネットワーク効果 | 利用者が増えるほど価値が上がる | 利用者数の推移、1位と2位の差が拡大傾向 |
| コスト優位 | 規模・工程・立地・調達 | 売上原価率・販管費率が同業より低く、同等以上の利益率・ROIC |
| 効率的規模 | 市場が小さく、少数の企業しか採算が合わない | プレイヤー数・上位3社のシェア合計、過去10年の新規参入が無く撤退・統合がある |

**手順3 持続性と傾向**: 今後5〜10年以内にモートを崩す具体的な要因があるか（6章）。堀の傾向は build が決める: 差の傾向が 縮小 かシェアが 低下 → 縮小、差の傾向が 拡大 でシェアが 拡大・安定 → 拡大、どちらも 不明 → 不明、ほか 安定。

**手順4 モートの強さ**（build が判定。上から順に当てはめる）

| 結論 | 条件 |
|---|---|
| **判定保留** | 超過収益が 不明 |
| **なし** | 超過収益が なし（「強」「中」の源泉は数字に表れていないため除く。結果 JSON の corrected に記録） |
| **判定保留** | 「強」「中」の源泉が無く、「不明」の源泉がある |
| **なし** | 「強」「中」の源泉が無い |
| **広い** | 超過収益が 強い、「強」が1つ以上（または「中」以上が2つ以上）、深さが 深い・中程度、5年以内の要因なし、堀の傾向が 縮小 でない |
| **狭い** | 上のどれでもない |

### 4. ビルド（スクリプト）

```
$PY -I tools/analysis/moat.py build --company {company}
```

- `ok: true` → md の8章に結論を書き込み、json を作る。返り値の `verdict`・`verdict_reason`・`effective_moats`（「強」「中」で残ったモート）・`claimed_moats`・`corrected`（超過収益が無く除いたか）・`backing`（超過収益）・`backing_reason`・`width`・`depth`・`trend`（堀の傾向）・`pricing`・`share`・`near_risks`（5年以内の要因）・`durability`・`unknown_sources`・`tie_breaks`（迷った判定）・`low_confidence`（根拠の確度が参考の判定）・`unknown`（不明の判定）・`gaps`（11章の全件）を完了報告に使う
- `ok: false` → `issues` の指摘箇所だけを Edit で直し、もう一度 build（2回まで。それでも残れば未完了として、指摘をそのまま報告する）

---

## してはいけないこと

- 5段以外の作業（追加の web 検索、raw・PDF・CSV の閲覧、数値の手計算）をしない。材料が足りなければ「不明」にして 11章に書く
- スクリプトが作るファイル（brief.md・json）と、moat.md の1章の3Cの結論・強み候補・2章・3章・7章の幅・前回の判定・8章を手で直さない
- 有効期間内の結果を作り直さない（`--redo` はユーザーの指示があるときだけ）。過去の日付の完成済み md を変更しない（hook がブロックする）
- 投資の勧誘・推奨、「おそらく」「〜と思われる」を書かない（build が検出する）。モートがあることを「良い投資」と書かない（株価への織り込みは STEP 3 で見る）
- 収集担当（collect-company-info）へのプロンプトで、raw の書き方（範囲外の章に「変更なし」と書く、前回の表を再掲するなど）を指示しない。書き方は collect-company-info.md の保存ルールに任せる（「変更なし」の節や再掲は、前回の材料を隠したり上流の分析を再実行させたりする）

※ グローバル設定の hook（Fact-Forcing Gate）が、最初の Bash と、ファイルごとの最初の Edit を一度差し戻すことがある。求められた事実を示して同じ操作を再実行すれば通る。

## 完了報告（ユーザー向け）

check・prepare・build の JSON（three-c・収集を実行した場合はその完了報告も）だけを使い、次の形式で短く報告する。

```
## モート分析 — {name}
- 結果: {md}（機械可読: {json}）
- モートの強さ: {verdict}（{verdict_reason}。前回 {previous.verdict または「初回」}）
  - 超過収益: {backing}（{backing_reason}）　堀の幅: {width}　堀の傾向: {trend}
  - 該当するモート: {effective_moats を「、」で。無ければ「なし」。corrected なら「{claimed_moats} は超過収益に表れていないため除いた」}
  - 価格決定力: {pricing}　深さ: {depth}　シェアの推移: {share}
  - 持続の見込み: {durability}（5年以内の要因: {near_risks。無ければ「なし」}）
- 判断が分かれた判定: {tie_breaks。無ければ「なし」} / 根拠が参考情報だけの判定: {low_confidence。無ければ「なし」} / 不明の判定: {unknown。無ければ「なし」}
- 有効期限: {valid_until}（それまでは再実行しても再分析しない）
- 材料: {3C {three_c.date}（勝てる理由 {three_c.verdict}）。今回 three-c・collect-company-info を実行した・しなかった（three-c を実行したならその理由と、結論が前回から変わったか。--skip-collect で進んだならその項目）。地合いが古ければ「地合いは N 日前の週（古い）」。1社のため選択を省略したならその旨。unavailable があれば列挙}
- 警告: {prepare の warnings。無ければ「なし」}
- 欠損: {gaps の全件の要点。無ければ「なし」}
- 次に集める材料: {verdict が「判定保留」のときだけ。超過収益が不明なら自社の営業利益・自己資本・有利子負債の時系列（collect-filings）、源泉が不明なら unknown_sources に効く材料（インストールベースとアフター売上・値上げの実績は collect-ir、参入と撤退・シェアの推移は collect-market）。collect-company-info で集めると新しい raw として再分析の対象になる}
```

有効期間内で再分析しなかった場合は、`latest` の md・結論・有効期限と「有効期間内のため再分析していない（作り直す場合は redo を指示）」だけを書く。
