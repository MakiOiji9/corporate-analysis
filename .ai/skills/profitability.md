# 収益性分析スキル（profitability）

`企業分析フレームワーク.md` の **STEP 2-1 収益性（ROE・デュポン分解）**（会社が効率よく稼げているか、その稼ぐ力が本業由来か。収益性 良好 / 普通 / 懸念。材料不足なら 判定保留）を、
collect-company-info が集めた財務時系列・有報・競合の材料から行う。成果物は次の3つ。

- `companies/{ticker}_{name}/analysis/profitability/{日付}_profitability.md` — 分析結果。企業分析レポート・STEP 2 判定はこれ（と json）を参照する
- `.../{日付}_profitability.json` — 同じ結果の機械可読版（ROE の年次表・手順1〜3の判定と数値・3要素の推移と同業比較・ROE が動いた年・一過性の損益・STEP 1 との整合性・引き継ぎ・有効期限）
- `.../{日付}_brief.md` — 執筆の材料（数値の要点と、数値の背景になる raw の節の抜粋）

`{日付}` は分析日。結果は **200日有効**で、期間内は再実行しても既存の結果を返すだけにする。
ただし期限前でも、新しい中間・本決算の決算短信が出たとき、またはモート・3Cの結論が変わったときは再分析する。競合・株価・事業概要の取り直しや、同じ期の数値の訂正だけでは再分析しない（有効期限を待つ）。上流の分析は作り直されても結論が同じなら再分析しない（`tools/analysis/freshness.py`）。

**数値の抽出・ROE とデュポン分解の計算・同業比較・手順1〜4の判定・STEP 1 との整合性はすべてスクリプト（`tools/analysis/profitability.py`）が行う。**
LLM が受け持つのは profitability.md の FILL 欄（数値の背景と解釈・引き継ぎ）だけ。手順は **企業の選択 → 鮮度確認 → 準備 → 執筆 → ビルド** に固定されている。

STEP 1（five-forces / three-c / moat / swot）は前提にしない。モート・3C の結果があれば整合性チェックに使い、無ければ「未実施」と記録する（上流のスキルは実行しない）。
地合い（outlook.md）は md のヘッダーで参照するだけで、収益性の判定には使わない。古くても market-report・collect-market-info は実行しない。

## 実行手順

Python は `.venv` のものを使う（Windows: `.venv\Scripts\python.exe`、macOS/Linux: `.venv/bin/python`）。以下 `$PY` と書く。
各コマンドの標準出力は1行の JSON。

### 0. 企業の選択（`company` が無いときだけ）

```
$PY -I tools/analysis/profitability.py list
```

`companies` の各行（`dir`・`name`・`last_collected`・`profitability`・`profitability_date`・`verdict`・`moat`・`three_c`）から選択肢を作り、ユーザーに選んでもらう（提示の方法はエントリーポイントの指示に従う）。
企業が1社だけなら選択肢を出さずにその企業で進み、完了報告の「材料」行に「対象は1社だけのため選択を省略」と書く。
選択肢には `profitability` の状態（`none` 未分析 / `fresh` 有効 / `expired` 期限切れ / `triggered` 材料・数値・上流の分析が変わった / `draft` 作成途中）と、モート・3C の結論（無ければ「未実施」）を添える。
一覧に無い企業を指定されたら、手順 1 の `company_missing` と同じ扱いにする。

### 1. 鮮度確認（スクリプト）

```
$PY -I tools/analysis/profitability.py check --company {company}
```

`next` に従う。

| `next`・状態 | すること |
|---|---|
| `ok: false` で `candidates` あり | 複数の企業が当たった。候補からユーザーに選んでもらい、もう一度 check |
| `ok: false` で `company_missing: true` | 企業の情報が無い。ユーザーにホームページ URL を確認し、collect-company-info を `mode=full` で実行してから check をやり直す |
| `report_existing`（`result: fresh`） | 有効期間内。`latest`（md・結論・有効期限）を完了報告の形式で伝えて**終わる**（執筆しない）。`redo` の指示があるときだけ手順 2 へ |
| `collect` で `needs_full_collect: true` | raw が無い。collect-company-info を `mode=full` で実行し、check をやり直す |
| `collect` | 材料が足りない。collect-company-info を `mode=update` で実行し、`missing_inputs` の担当（`agent`）と項目（`items`）を範囲として伝える。終わったら check をやり直す。主な項目: 自社の財務時系列が5年未満（collect-filings「財務時系列: 売上高・当期純利益・総資産・自己資本（5年以上）」）、競合の「収益性の分解」が無い（collect-peers-valuation）、競合の営業利益率の推移が無い（collect-peers-valuation） |
| `prepare`（`none` / `expired` / `triggered` / `draft`） | 手順 2 へ |

- 収集（collect-company-info）は**1回の実行につき1回まで**。やり直した check でまだ `collect` が出ても、もう一度は収集せず手順 2 に `--skip-collect` を付けて進む（比べられない手順はスクリプトが「不明」として扱い、結論が 判定保留 になることがある。8章に書く）
- check と prepare を1つのコマンドにつなげない（check の `next` を見てから次へ進む）。prepare も `next` を確かめ、`collect` のままなら `ok: false` で拒否する
- `unavailable` は「収集を試みたが取れなかった」材料（status.md の未取得項目）。再収集しない
- 収集スキルが止まった（ユーザーへの確認待ち・エラー）ときは、このスキルも止めて状況を報告する

#### 収集を依頼するとき

collect-company-info には `missing_inputs` の担当・項目だけを渡す。担当へのプロンプトに載せる前回の競合リスト・原本の場所・同じ日の raw の扱いは、collect-company-info.md の mode=update の手順（分析スキルからの依頼）に従う。終わったら collect-company-info の集約（status.md・overview.md・summaries）まで済ませてから check に戻る。

### 2. 準備（スクリプト）

```
$PY -I tools/analysis/profitability.py prepare --company {company} [--redo] [--skip-collect]
```

- `{日付}_brief.md`（材料）と `{日付}_profitability.md`（FILL つきの骨組み）を作る。返り値の `brief`・`md` がそのパス
- 骨組みには **1章 ROE の年次表と手順1の判定**、**2章 営業利益率の同業比較と手順2の判定**、**3.1 自社の3要素の推移**、**3.2 同業比較と手順3の判定**、**3.3 ROE が前年から2pt以上動いた年と主因の要素（営業利益率・特別損益の前年比つき）**、**3.4 特別損益の表と除いた ROE・除いた場合の手順1**、**5章 STEP 1 との整合性の判定**がすべて記入済み。`candidate` が結論の候補（build が同じ規則で確定する）
- `fill_keys` が書く欄の一覧（md を読み直して探さなくてよい）、`peer_summary` が 3.2 の自社と同業平均の3要素・ROE、`borderline` が境界に近い比較
- 作成途中の md（FILL が残っている）は上書きせず残す（`kept: true`）。続きから書く
- 一字も書いていない骨組み（前回の prepare が書いたままの md）は、`--redo` なしで作り直す（`regenerated: true`）
- `--redo` は完成済みの結果（有効期間内）と書きかけの md を作り直すときだけ使う（ユーザーの指示があるときだけ）。同じ日に build 済みの結果があると `--redo` は拒否される。その日の md を Edit で直して build し直す
- `warnings`（brief の「警告」節にも出る）は、スクリプトが raw を読み違えた可能性（有報の ROE と計算値が1pt超ずれる、競合の行から3要素を計算できないなど）。空でなければ完了報告の「警告」行に書く

### 3. 執筆（LLM）

brief.md を読み、profitability.md の `<!-- FILL:... -->` を Edit で置き換える。

- 読むのは brief.md と profitability.md だけ。raw・PDF・CSV・summaries を個別に開かない（必要な節は brief.md に集約済み）
- 書く順番と Edit の単位（各1回）: 3.2 同業との差の背景 → 3.3 の背景（年ごと） → 3.4 一過性要因の評価 → 5章 コメント → 6章 → 7章 → 8章
- 書き方の規則は profitability.md 冒頭の `>` 行に従う。要点:
  - 書くのは**数値の背景と解釈だけ**。表の数値・判定・年度の行を変えない。数値を新しく計算しない
  - 3.3 の背景は、その年に主因の要素が動いた理由を1文。同じ行の「3要素の変化」にスクリプトが営業利益率と特別損益の純額の前年比を付けてあるので、それと brief の特別損益の内訳・株主還元（自社株買い・配当）・事業の記述から書く（2章の表と突き合わせなくてよい）。brief に無ければ「不明（brief に記載なし）」（推測で埋めない）
  - 3.4 は「要確認」の年の特別損益の中身（売却益・減損など）を書く。除いた ROE と、除いた場合の手順1の判定はスクリプトが表と「除いた場合の手順1」の行に記入済み。引用するだけで再計算しない
  - brief「数値の要点」の「境界に近い比較」は、6章の「評価が変わる条件」に使う（材料の誤差や次の決算で判定が1段階動きうる比較）
  - 5章は「不整合」の行があれば STEP 1 のどの判定を見直す候補かを書く（判定そのものは変えない。STEP 1 の分析を作り直すのはユーザーの判断）
  - 6章は企業分析レポートの INPUT になる。レポートで使う要点（4章の結論と根拠の数値）、会社の ROE 目標・資本政策との関係、STEP 2 の他の分析（成長性・安全性・キャッシュフロー）で確かめること、評価が変わる条件
  - 根拠に書く事実は brief.md の記述と同じ強さで書く。表のセルに `|` を書かない。4章（結論）は build が書くので触らない
- 見出し・表の列・ヘッダー・スクリプト記入済みの欄は変えない。ファイルを丸ごと書き直さない（Write は hook がブロックする）

#### 判断基準（企業分析フレームワーク.md 2-1 の転記。判定はすべてスクリプト）

- ROE = 当期純利益 ÷ 自己資本 = 売上高純利益率 × 総資産回転率 × 財務レバレッジ（純利益率 = 純利益 ÷ 売上高、回転率 = 売上高 ÷ 総資産、レバレッジ = 総資産 ÷ 自己資本）
- 総資産・自己資本は期首期末平均（前年の残高が無い年は期末）。自己資本は「自己資本」の記載値、無ければ 総資産 × 自己資本比率（純資産は使わない）
- 手順1の ROE は 有報・短信の開示値（一次）→ 計算値 → 集計サイトの開示値（二次）の順に採用

| 手順 | 見るもの | 判定（スクリプト） |
|---|---|---|
| 1 ROE の水準と安定性 | 直近最大10年（5年未満なら判定しない） | **懸念**: 平均8%未満、または赤字の年あり / **良好**: 平均10%以上かつ最低5%以上 / **普通**: それ以外（平均8〜10%、または平均10%以上だが最低5%未満） |
| 2 営業利益率の同業比較 | 直近の比較できる年の自社と同業平均（競合最大5社の単純平均、決算期6か月以内を同年扱い）、5年の推移 | 差 +1pt 超 **上回る** / ±1pt 以内 **同等** / −1pt 未満 **下回る** / 比べられなければ 不明 |
| 3 ROE の源泉 | 3要素の同業比較（自社の直近最大5年と、同じ時期の競合の平均） | 直近の財務レバレッジが3倍超かつ同業平均超 → **借入依存** / 純利益率か回転率が同業平均超 → **本業由来** / どちらでもない → **特定できず** / 競合の3要素が無い → 不明（3倍超なら借入依存）。「同業平均超」は、純利益率は差が +1pt 超、回転率・レバレッジは比が 1.05 超のときだけ。それ以内は同等とみなす（迷ったら保守的に） |

**手順4 収益性**（上から順に当てはめる）

| 結論 | 条件 |
|---|---|
| **懸念** | 手順1が懸念、または手順3が借入依存 |
| **判定保留** | 手順1を判定できない（ROE が3年未満）。3〜4年なら判定するが良好にはしない（材料不足のため保守的に判定。結果 JSON の conservative に記録） |
| **普通** | 手順1が普通、または手順2が下回る、または手順3が特定できず |
| **普通** | 手順1が良好で、手順2・3のどちらかが不明（比べられない比較は満たさないとみなす（材料不足のため保守的に判定。結果 JSON の conservative に記録）） |
| **良好** | 手順1が良好、手順2が上回る・同等、手順3が本業由来 |

**STEP 1 との整合性**（5章。スクリプト）: モートが「広い」なのに営業利益率が同業平均を上回らない、勝てる理由が「明確」なのに ROE・営業利益率が同業未満 → 不整合（STEP 1 見直し候補）。収益性の判定は変えない。

### 4. ビルド（スクリプト）

```
$PY -I tools/analysis/profitability.py build --company {company}
```

- `ok: true` → md の4章に結論を書き込み、json を作る。返り値の `verdict`・`verdict_reason`・`step1`〜`step3`（各手順の結論の文）・`consistency`・`borderline`（境界に近い比較）・`one_off_checks`（一過性要因を確かめた年）・`unknown_backgrounds`（背景が不明の年）・`gaps`（8章の全件）を完了報告に使う
- `ok: false` → `issues` の指摘箇所だけを Edit で直し、もう一度 build（2回まで。それでも残れば未完了として、指摘をそのまま報告する）

## してはいけないこと

- 5段以外の作業（追加の web 検索、raw・PDF・CSV の閲覧、数値の手計算）をしない。材料が足りなければ背景を「不明」にして 8章に書く
- スクリプトが作るファイル（brief.md・json）と、profitability.md のスクリプト記入済みの欄（1〜3章の表と判定、5章の表、4章）を手で直さない
- 有効期間内の結果を作り直さない（`--redo` はユーザーの指示があるときだけ）。過去の日付の完成済み md を変更しない（hook がブロックする）
- STEP 1 のスキル（five-forces・three-c・moat・swot）や地合いのスキル（collect-market-info・market-report）をこのスキルから実行しない
- 投資の勧誘・推奨、「おそらく」「〜と思われる」を書かない（build が検出する）
- 収集担当（collect-company-info）へのプロンプトで、raw の書き方（範囲外の章に「変更なし」と書く、前回の表を再掲するなど）を指示しない。書き方は collect-company-info.md の保存ルールに任せる

※ グローバル設定の hook（Fact-Forcing Gate）が、最初の Bash と、ファイルごとの最初の Edit を一度差し戻すことがある。求められた事実を示して同じ操作を再実行すれば通る。

## 完了報告（ユーザー向け）

check・prepare・build の JSON（収集を実行した場合はその完了報告も）だけを使い、次の形式で短く報告する。

```
## 収益性分析 — {name}
- 結果: {md}（機械可読: {json}）
- 収益性: {verdict}（{verdict_reason}。前回 {previous.verdict または「初回」}）
  - 手順1: {step1}
  - 手順2: {step2}
  - 手順3: {step3}
- STEP 1 との整合性: {consistency を「、」で}
- 境界に近い比較: {borderline を「。」で。無ければ「なし」}（材料の誤差や次の決算で判定が1段階動きうる）
- 一過性要因を確かめた年: {one_off_checks。無ければ「なし」} / 背景が不明の年: {unknown_backgrounds。無ければ「なし」}
- 有効期限: {valid_until}（それまでは再実行しても再分析しない）
- 材料: {今回 collect-company-info を実行した・しなかった（--skip-collect で進んだならその項目）。モート・3C の結果の日付（無ければ「未実施」）。1社のため選択を省略したならその旨。unavailable があれば列挙}
- 警告: {prepare の warnings。無ければ「なし」}
- 欠損: {gaps の全件の要点。無ければ「なし」}
- 次に集める材料: {verdict が「判定保留」のときだけ。競合の「収益性の分解」（collect-peers-valuation）または自社の財務時系列（collect-filings）}
```

有効期間内で再分析しなかった場合は、`latest` の md・結論・有効期限と「有効期間内のため再分析していない（作り直す場合は redo を指示）」だけを書く。
