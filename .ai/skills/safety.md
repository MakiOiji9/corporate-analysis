# 安全性分析スキル（safety）

`企業分析フレームワーク.md` の **STEP 2-3 安全性**（不況や業績悪化に耐えられる財務体力があるか。自己資本比率・D/E レシオ・流動比率・ネットキャッシュの水準、その推移、借入の目的から 安全性 良好 / 普通 / 懸念。材料不足なら 判定保留）を、
collect-company-info が集めた財務時系列・有報・競合の材料から行う。成果物は次の3つ。

- `companies/{ticker}_{name}/analysis/safety/{日付}_safety.md` — 分析結果。企業分析レポート・STEP 2 判定はこれ（と json）を参照する
- `.../{日付}_safety.json` — 同じ結果の機械可読版（3指標の直近値と判定・同業比較・5年の推移・借入が増えた年の分類・引き継ぎ・有効期限）
- `.../{日付}_brief.md` — 執筆の材料（数値の要点と、数値の背景になる raw の節・収益性の結果・地合いの金利の行の抜粋）

`{日付}` は分析日。結果は **120日有効**で、期間内は再実行しても既存の結果を返すだけにする。
ただし期限前でも、新しい四半期の決算短信が出たときは再分析する。競合・株価・事業概要の取り直しや、同じ期の数値の訂正だけでは再分析しない（有効期限を待つ）。上流の分析は作り直されても結論が同じなら再分析しない（`tools/analysis/freshness.py`）。

**数値の抽出・3指標の計算・同業比較・推移・借入目的の分類・手順1〜4の判定はすべてスクリプト（`tools/analysis/safety.py`）が行う。**
LLM が受け持つのは safety.md の FILL 欄（数値の背景と引き継ぎ）だけ。手順は **企業の選択 → 鮮度確認 → 準備 → 執筆 → ビルド** に固定されている。

STEP 1（five-forces / three-c / moat / swot）も収益性（profitability）も前提にしない。収益性の結果があれば brief に引用し、無ければ「未実施」と記録する（上流のスキルは実行しない）。
地合い（outlook.md）は金利・金融政策の行を brief に抜粋するだけで、安全性の判定には使わない。古くても market-report・collect-market-info は実行しない。

## 実行手順

Python は `.venv` のものを使う（Windows: `.venv\Scripts\python.exe`、macOS/Linux: `.venv/bin/python`）。以下 `$PY` と書く。
各コマンドの標準出力は1行の JSON。

### 0. 企業の選択（`company` が無いときだけ）

```
$PY -I tools/analysis/safety.py list
```

`companies` の各行（`dir`・`name`・`last_collected`・`safety`・`safety_date`・`verdict`・`profitability`）から選択肢を作り、ユーザーに選んでもらう（提示の方法はエントリーポイントの指示に従う）。
企業が1社だけなら選択肢を出さずにその企業で進み、完了報告の「材料」行に「対象は1社だけのため選択を省略」と書く。
選択肢には `safety` の状態（`none` 未分析 / `fresh` 有効 / `expired` 期限切れ / `triggered` 材料・数値が変わった / `draft` 作成途中）と、収益性の結論（無ければ「未実施」）を添える。
一覧に無い企業を指定されたら、手順 1 の `company_missing` と同じ扱いにする。

### 1. 鮮度確認（スクリプト）

```
$PY -I tools/analysis/safety.py check --company {company}
```

`next` に従う。

| `next`・状態 | すること |
|---|---|
| `ok: false` で `candidates` あり | 複数の企業が当たった。候補からユーザーに選んでもらい、もう一度 check |
| `ok: false` で `company_missing: true` | 企業の情報が無い。ユーザーにホームページ URL を確認し、collect-company-info を `mode=full` で実行してから check をやり直す |
| `report_existing`（`result: fresh`） | 有効期間内。`latest`（md・結論・有効期限）を完了報告の形式で伝えて**終わる**（執筆しない）。`redo` の指示があるときだけ手順 2 へ |
| `collect` で `needs_full_collect: true` | raw が無い。collect-company-info を `mode=full` で実行し、check をやり直す |
| `collect` | 材料が足りない。collect-company-info を `mode=update` で実行し、`missing_inputs` の担当（`agent`）と項目（`items`）を範囲として伝える。終わったら check をやり直す。主な項目: 自社の貸借・CF が足りない（有利子負債の行が無い、推移が3年未満など。collect-filings）、競合の「安全性の指標」が無い（collect-peers-valuation） |
| `prepare`（`none` / `expired` / `triggered` / `draft`） | 手順 2 へ |

- 収集（collect-company-info）は**1回の実行につき1回まで**。やり直した check でまだ `collect` が出ても、もう一度は収集せず手順 2 に `--skip-collect` を付けて進む（判定できない指標はスクリプトが「不明」として扱い、結論が 判定保留 になることがある。7章に書く）
- check と prepare を1つのコマンドにつなげない（check の `next` を見てから次へ進む）。prepare も `next` を確かめ、`collect` のままなら `ok: false` で拒否する
- `unavailable` は「収集を試みたが取れなかった」材料（status.md の未取得項目）。再収集しない
- 収集スキルが止まった（ユーザーへの確認待ち・エラー）ときは、このスキルも止めて状況を報告する

#### 収集を依頼するとき

collect-company-info には `missing_inputs` の担当・項目だけを渡す。担当へのプロンプトに載せる前回の競合リスト・原本の場所・同じ日の raw の扱いは、collect-company-info.md の mode=update の手順（分析スキルからの依頼）に従う。終わったら collect-company-info の集約（status.md・overview.md・summaries）まで済ませてから check に戻る。

### 2. 準備（スクリプト）

```
$PY -I tools/analysis/safety.py prepare --company {company} [--redo] [--skip-collect]
```

- `{日付}_brief.md`（材料）と `{日付}_safety.md`（FILL つきの骨組み）を作る。返り値の `brief`・`md` がそのパス
- `borderline` は判定が1段階動きうる比較だけ（クリアの根拠が目安か同業平均の片方だけで、その余裕が帯の2倍以内。未達は近い方）
- 骨組みには **1章 3指標とネットキャッシュの表・同業の表・手順1の判定**、**2章 推移の表と手順2の判定**、**3章 有利子負債が増えた年の表（CF・その後の売上高と営業利益・分類）と手順3の判定**がすべて記入済み。`candidate` が結論の候補（build が同じ規則で確定する）
- `fill_keys` が書く欄の一覧（md を読み直して探さなくてよい）、`net_cash` が直近のネットキャッシュ、`debt_years` が背景を書く年、`borderline` が境界に近い比較
- 作成途中の md（FILL が残っている）は上書きせず残す（`kept: true`）。続きから書く
- 一字も書いていない骨組み（前回の prepare が書いたままの md）は、`--redo` なしで作り直す（`regenerated: true`）
- `--redo` は完成済みの結果（有効期間内）と書きかけの md を作り直すときだけ使う（ユーザーの指示があるときだけ）。同じ日に build 済みの結果があると `--redo` は拒否される。その日の md を Edit で直して build し直す
- brief は、同じ raw の節を1回だけ載せる。新しい「貸借・CF の主要項目」の節があれば、それより古い日付の貸借・CF の節は載せない（古い注記が訂正されている場合があるため）。事業等のリスク・財務3表・主要な経営指標は、財務に関わる行（借入・資金・金利・減損・引当・資本・債務・現金など）だけを載せる
- `warnings`（brief の「警告」節にも出る）は、スクリプトが raw を読み違えた可能性や注意点（開示の自己資本比率と計算値が1pt超ずれる、債務超過、有利子負債を内訳の合計で出した、競合の年度が合わないなど）。空でなければ完了報告の「警告」行に書く

### 3. 執筆（LLM）

brief.md を読み、safety.md の `<!-- FILL:... -->` を Edit で置き換える。

- 読むのは brief.md と safety.md だけ。raw・PDF・CSV・summaries・収益性の md・outlook.md を個別に開かない（必要な節は brief.md に集約済み）
- 書く順番と Edit の単位（各1回）: 1章 水準の背景 → 3章 背景（年ごと） → 5章 → 6章 → 7章
- 書き方の規則は safety.md 冒頭の `>` 行に従う。要点:
  - 書くのは**数値の背景と解釈だけ**。表の数値・判定・年度の行を変えない。数値を新しく計算しない。書いた数値は build が brief と md の記入済みの部分に出てくるかを照合し、無ければ指摘する（2桁以下の整数と年は対象外）。要約・raw で見た数値を持ち込まない
  - 1章の水準の背景は、自己資本・借入・手元資金の水準を生んでいる事業上・資本政策上の理由を brief の記述から書く。未達・不明の指標があればその理由（債務超過の中身、競合の材料なしなど）にも触れる
  - 3章の背景は、その年に借り入れた理由を1文。同じ行の CF・その後の売上高と営業利益と、brief の財務時系列・有報・資本政策の記述（設備投資・M&A の内容）から書く。brief に無ければ「不明（brief に記載なし）」（推測で埋めない）。分類（成長投資・赤字補填など）はスクリプトが決めたもので、背景で覆さない
  - brief「数値の要点」の「境界に近い比較」は、5章の「評価が変わる条件」に使う（材料の誤差や次の決算で判定が1段階動きうる比較）
  - 5章は企業分析レポートの INPUT になる。レポートで使う要点（4章の結論と根拠の数値）、財務方針・資本政策との関係、STEP 2 の他の分析（キャッシュフロー・収益性・成長性）で確かめること、評価が変わる条件。金利の局面に触れるときは brief の地合いの抜粋だけを引用する
  - 根拠に書く事実は brief.md の記述と同じ強さで書く。表のセルに `|` を書かない。4章（結論）は build が書くので触らない
- 見出し・表の列・ヘッダー・スクリプト記入済みの欄は変えない。ファイルを丸ごと書き直さない（Write は hook がブロックする）

#### 判断基準（企業分析フレームワーク.md 2-3 の転記。判定はすべてスクリプト）

- 自己資本比率 = 自己資本 ÷ 総資産、D/E レシオ = 有利子負債 ÷ 自己資本、流動比率 = 流動資産 ÷ 流動負債、ネットキャッシュ = 現金及び現金同等物 − 有利子負債（いずれも期末残高）
- 自己資本は「自己資本」の記載値、無ければ 総資産 × 自己資本比率（純資産は使わない）。有利子負債は「有利子負債」の行、無ければ借入金・社債・CP の内訳の合計（リース債務は含まない）。どちらも無い年は不明（0 とみなさない）。現金は「現金及び現金同等物」、無ければ「現金及び預金」

| 手順 | 見るもの | 判定（スクリプト） |
|---|---|---|
| 1 現状の水準 | 3指標の直近値と同業平均（競合最大5社の単純平均、決算期6か月以内を同年扱い） | 指標ごとに 目安（自己資本比率 40%以上 / D/E 1倍以下 / 流動比率 120%以上。150%以上は余裕ありと表示）をクリア、または同業平均と同等以上（自己資本比率 −2pt、流動比率 −5pt、D/E ×1.05 以内）なら **クリア**、どちらも満たさなければ **未達**、目安未達で同業と比べられなければ **不明**。ネットキャッシュがプラスなら D/E は **クリア（実質無借金）**。債務超過なら自己資本比率は **未達**。銀行・保険・証券・不動産・リースなどは目安を使わず同業平均だけと比べる |
| 2 推移 | 直近5年（3年未満なら判定しない） | 自己資本比率が5年で10pt以上低下、または D/E が3期連続で上昇し初年より高い → **悪化傾向** / それ以外 → **悪化傾向なし** |
| 3 借入の目的 | 有利子負債が前年から総資産の1%以上増えた年（直近5年） | 営業CF がマイナスか赤字 → **赤字補填・運転資金不足（懸念）** / 投資CF の支出が増加額の半分以上 → 成長投資（2年以内に売上高・営業利益とも増えていれば **許容**、そうでなければ要確認） / それ以外 → **その他（要確認）**。全体は 懸念の年があれば懸念、増えた年が無い・全年許容なら許容、それ以外は要確認 |

**手順4 安全性**（上から順に当てはめる）

| 結論 | 条件 |
|---|---|
| **判定保留** | 3指標がすべて不明（判定に使える事実が無い） |
| **懸念** | 2指標以上が未達、または 悪化傾向 かつ 借入の目的が懸念 |
| **良好** | 3指標ともクリア、かつ悪化傾向なし |
| **普通** | 上記以外 |
| **最も悪い結論** | 不明の指標・推移・借入の目的をクリア／未達のどちらと置くかで結論が分かれるときは、最も悪い結論を採る（材料不足のため保守的に判定。結果 JSON の conservative に記録） |

### 4. ビルド（スクリプト）

```
$PY -I tools/analysis/safety.py build --company {company}
```

- `ok: true` → md の4章に結論を書き込み、json を作る。返り値の `verdict`・`verdict_reason`・`step1`〜`step3`（各手順の結論の文）・`borderline`（境界に近い比較）・`debt_years`（借入が増えた年）・`unknown_backgrounds`（背景が不明の年）・`gaps`（7章の全件）を完了報告に使う
- `ok: false` → `issues` の指摘箇所だけを Edit で直し（「数値 X が brief・md に無い」は、brief にある値に書き換えるか数値を消す）、もう一度 build（2回まで。それでも残れば未完了として、指摘をそのまま報告する）

## してはいけないこと

- 5段以外の作業（追加の web 検索、raw・PDF・CSV の閲覧、数値の手計算）をしない。材料が足りなければ背景を「不明」にして 7章に書く
- スクリプトが作るファイル（brief.md・json）と、safety.md のスクリプト記入済みの欄（1〜3章の表と判定、4章）を手で直さない
- 有効期間内の結果を作り直さない（`--redo` はユーザーの指示があるときだけ）。過去の日付の完成済み md を変更しない（hook がブロックする）
- STEP 1 のスキル（five-forces・three-c・moat・swot）、収益性（profitability）、地合いのスキル（collect-market-info・market-report）をこのスキルから実行しない
- 投資の勧誘・推奨、「おそらく」「〜と思われる」を書かない（build が検出する）
- 収集担当（collect-company-info）へのプロンプトで、raw の書き方（範囲外の章に「変更なし」と書く、前回の表を再掲するなど）を指示しない。書き方は collect-company-info.md の保存ルールに任せる

※ グローバル設定の hook（Fact-Forcing Gate）が、最初の Bash と、ファイルごとの最初の Edit を一度差し戻すことがある。求められた事実を示して同じ操作を再実行すれば通る。

## 完了報告（ユーザー向け）

check・prepare・build の JSON（収集を実行した場合はその完了報告も）だけを使い、次の形式で短く報告する。

```
## 安全性分析 — {name}
- 結果: {md}（機械可読: {json}）
- 安全性: {verdict}（{verdict_reason}。前回 {previous.verdict または「初回」}）
  - 手順1: {step1}
  - 手順2: {step2}
  - 手順3: {step3}
- 境界に近い比較: {borderline を「。」で。無ければ「なし」}（材料の誤差や次の決算で判定が1段階動きうる）
- 借入が増えた年: {debt_years。無ければ「なし」} / 背景が不明の年: {unknown_backgrounds。無ければ「なし」}
- 有効期限: {valid_until}（それまでは再実行しても再分析しない）
- 材料: {今回 collect-company-info を実行した・しなかった（--skip-collect で進んだならその項目）。収益性分析の結果の日付（無ければ「未実施」）。1社のため選択を省略したならその旨。unavailable があれば列挙}
- 警告: {prepare の warnings。無ければ「なし」}
- 欠損: {gaps の全件の要点。無ければ「なし」}
- 次に集める材料: {verdict が「判定保留」のときだけ。競合の「安全性の指標」（collect-peers-valuation）または自社の貸借・CF（collect-filings）}
```

有効期間内で再分析しなかった場合は、`latest` の md・結論・有効期限と「有効期間内のため再分析していない（作り直す場合は redo を指示）」だけを書く。
