# SWOT分析スキル（swot）

`企業分析フレームワーク.md` の **STEP 1-4 SWOT分析（総括）**（1-1〜1-3 の結果を統合し、最大の強みで最大の脅威に対抗できるか。SWOT の結論 Yes / 条件付き / No。材料不足なら 判定保留）を、
collect-company-info・collect-market-info・market-report が集めた材料と、five-forces（1-1）・three-c（1-2）・moat（1-3）の結果から行う。成果物は次の3つ。

- `companies/{ticker}_{name}/analysis/swot/{日付}_swot.md` — 分析結果。企業分析レポートはこれ（と json）を参照する
- `.../{日付}_swot.json` — 同じ結果の機械可読版（4象限の各項目・影響度・最大の強み/脅威・判定・結論・引き継ぎ・有効期限）
- `.../{日付}_brief.md` — 執筆の材料（raw から必要な節、上流3分析の結論、地合いの該当行を抜き出したもの）

`{日付}` は分析日。結果は **180日有効**で、期間内は再実行しても既存の結果を返すだけにする。
ただし期限前でも、分析が使った節（有報・中期経営計画・事業概要・業界概要）の中身が新しい raw で変わったとき、または新しいファイブフォース・3C・モート分析ができたときは再分析する（build が使った節のハッシュを json に記録し、check が比べる）。地合い（outlook.md）が新しくなっただけでは再分析しない。

抽出・必ず記載する項目の抽出・影響度の目安（売上・利益の 20%・5% の金額）の計算・材料の過不足の判定・検証・**最大の強み/脅威の選び方の確認と SWOT の結論の判定**はスクリプト（`tools/analysis/swot.py`）が行う。
LLM が受け持つのは swot.md の FILL 欄（4象限の各項目と影響度・最大の強み/脅威の選択・対抗できるかの判定・引き継ぎ）だけ。手順は **企業の選択 → 鮮度確認 → 準備 → 執筆 → ビルド** に固定されている。
STEP 1 判定（A/B/C）はこのスキルでは行わない。

## 実行手順

Python は `.venv` のものを使う（Windows: `.venv\Scripts\python.exe`、macOS/Linux: `.venv/bin/python`）。以下 `$PY` と書く。
各コマンドの標準出力は1行の JSON。

### 0. 企業の選択（`company` が無いときだけ）

```
$PY -I tools/analysis/swot.py list
```

`companies` の各行（`dir`・`name`・`last_collected`・`swot`・`swot_date`・`verdict`・`moat`）から選択肢を作り、ユーザーに選んでもらう（提示の方法はエントリーポイントの指示に従う）。
企業が1社だけなら選択肢を出さずにその企業で進み、完了報告の「材料」行に「対象は1社だけのため選択を省略」と書く。
選択肢には `swot` の状態（`none` 未分析 / `fresh` 有効 / `expired` 期限切れ / `triggered` 新しい raw・上流の分析あり / `draft` 作成途中）と、モートの状態（`fresh` 以外なら先に実行される）を添える。
一覧に無い企業を指定されたら、手順 1 の `company_missing` と同じ扱いにする。

### 1. 鮮度確認（スクリプト）

```
$PY -I tools/analysis/swot.py check --company {company}
```

`next` に従う。

| `next`・状態 | すること |
|---|---|
| `ok: false` で `candidates` あり | 複数の企業が当たった。候補からユーザーに選んでもらい、もう一度 check |
| `ok: false` で `company_missing: true` | 企業の情報が無い。ユーザーにホームページ URL を確認し、collect-company-info を `mode=full` で実行してから check をやり直す |
| `report_existing`（`result: fresh`） | 有効期間内。`latest`（md・結論・有効期限）を完了報告の形式で伝えて**終わる**（執筆しない）。`redo` の指示があるときだけ手順 2 へ |
| `collect` で `needs_full_collect: true` | raw が無い。collect-company-info を `mode=full` で実行し、check をやり直す |
| `moat` | モート分析（STEP 1-3）の結果が無い・期限切れ・再分析要・作成途中（`moat.result`）。**moat スキルを最後の完了報告まで実行**してから check をやり直す（3C・ファイブフォース・材料の収集が要れば moat の中で行われる） |
| `market_report` | 地合い（`market/report/{週}_outlook.md`）が無い、または35日より古い（`outlook`）。**market-report スキルを最後の完了報告まで実行**してから check をやり直す（材料が古ければ market-report の中で collect-market-info が実行される） |
| `collect` | SWOT に必須の材料が足りない（節が無い・空・中身が薄い）。collect-company-info を `mode=update` で実行し、`missing_inputs` の担当（`agent`）と項目（`items`）を範囲として伝える。終わったら check をやり直す |
| `prepare`（`none` / `expired` / `triggered` / `draft`） | 手順 2 へ |

- **上流の結論（業界の魅力度 低、勝てる理由 なし・判定保留、モート なし・判定保留）では SWOT を止めない**。結論は md の1章に記録され、執筆の前提になる
- moat・market-report・collect-company-info の実行は、**それぞれ1回の実行につき1回まで**（moat の中で three-c・five-forces・収集をした場合も、収集は1回と数える）
  - やり直した check でまだ `moat` が出たら（moat が止まった・作成途中のまま）、このスキルも止めて状況を報告する
  - やり直した check でまだ `market_report` が出たら、もう一度は実行せず手順 2 に `--skip-market-report` を付けて進む（地合いは brief で「古い」と示され、機会・脅威の根拠にするときは確度を下げる）
  - やり直した check でまだ `collect` が出たら、もう一度は収集せず手順 2 に `--skip-collect` を付けて進む（取れなかった材料に関わる項目は影響度「不明」として扱い、9章に書く）
- moat・market-report を実行したときは、その理由（`moat.reason`・`outlook` の古さ）と結論を完了報告の「材料」行に書く
- check と prepare を1つのコマンドにつなげない（check の `next` を見てから次へ進む）。prepare も `next` を確かめ、`moat`・`market_report`・`collect` のままなら `ok: false` で拒否する
- `unavailable` は「収集を試みたが取れなかった」材料（status.md の未取得項目）。再収集しない
- 収集スキル・moat・market-report が止まった（ユーザーへの確認待ち・エラー）ときは、このスキルも止めて状況を報告する

### 2. 準備（スクリプト）

```
$PY -I tools/analysis/swot.py prepare --company {company} [--redo] [--skip-collect] [--skip-market-report]
```

- `{日付}_brief.md`（材料）と `{日付}_swot.md`（FILL つきの骨組み）を作る。返り値の `brief`・`md` がそのパス
- 骨組みには、**1章の上流3分析の結論**、**1.1 必ず記載する項目**（ファイブフォースで「強」の要因 → 脅威、モート分析で残ったモート → 強み。返り値の `required`）、**3章の影響度の目安**（直近の売上高・営業利益と、その 20%・5% の金額）、前回の最大の強み/脅威と判定が記入済み。brief には同じ表を載せない
- brief には、上流3分析の結論と引き継ぎ（強み・弱み・脅威の候補）、raw の節（事業の内容・主要な販売先・中期経営計画・経営方針・成長戦略・事業等のリスク・市場規模・代替・構造を変えうる要因）、地合いの該当市場の行（総合判断・財政・政策・中長期の展望・リスク要因）が入る
- 作成途中の md（FILL が残っている）は上書きせず残す（`kept: true`）。続きから書く
- 一字も書いていない骨組み（前回の prepare が書いたままの md）は、`--redo` なしで作り直す（`regenerated: true`）
- `--redo` は完成済みの結果（有効期間内）と書きかけの md を作り直すときだけ使う（ユーザーの指示があるときだけ）。同じ日に build 済みの結果があると `--redo` は拒否される。その日の md を Edit で直して build し直す

### 3. 執筆（LLM）

brief.md を読み、swot.md の `<!-- FILL:... -->` を Edit で置き換える。

- 読むのは brief.md と swot.md だけ。raw・PDF・CSV・summaries・上流の分析 md・outlook.md を個別に開かない（必要な部分は brief.md に集約済み）
- brief.md が Read の上限を超えるときは、offset/limit で分けて最後（取れていない材料）まで読む
- 書く順番と Edit の単位（各1回）: 2.1 強み → 2.2 弱み → 2.3 機会 → 2.4 脅威 → 4章 → 5章 → 7章 → 8章 → 9章
- 書き方の規則は swot.md 冒頭の `>` 行に従う。要点:
  - 4象限の各行は `番号 | 由来 | 事実 | 根拠（数値） | 情報源 | 根拠の確度 | 影響度 | 影響度の理由`。番号は S1・W1・O1・T1 から連番
  - 由来は `1-1`（ファイブフォース）/ `1-2`（3C）/ `1-3`（モート）/ `中計` / `リスク`（有報の事業等のリスク）/ `業界` / `地合い` / `財務` / `事業` のいずれかで始め、続けて元の項目名を書く
  - **1.1 の項目は指定の象限に必ず書く**（脅威は「1-1 {要因名}」、強みは「1-3 {モートの種類}」の由来で）。書かないと build が拒否する
  - 内部要因（会社自身でコントロールできる: 人材・顧客構成・製品・コスト構造・財務）は S/W、外部要因（市場・業界・規制・政策・景気・技術の変化）は O/T。同じ事実を両側に書かない
  - 事実だけを書く。会社の主張（IR 資料の自己評価）は「会社は〜と説明」と書いて事実と区別する。brief で「未確認」「要旨」とある事柄を確認済みの事実として書かない
  - 影響度は 3章の目安と比べて `大`（主力事業の売上・利益の20%以上）/ `中`（5〜20%）/ `小`（5%未満）/ `不明` の1語。影響度の理由には、影響しうる売上・利益の金額か比率（brief の数値の転記）と、3章のどの目安に当てたかを書く。金額・比率が書けなければ「不明」
  - 象限に書く事実が無ければ1行だけ「なし」（番号の列に `なし`、事実の列に確認した材料、ほかの列は `—`）
  - 4章: 最大の強みは影響度「大」の強みから1つ（無ければ「なし」）、最大の脅威は「大」の脅威から、無ければ「中」から1つ（どちらも無ければ「なし」）。番号で書く
  - 5章: 今後3〜5年、最大の強みが最大の脅威に耐えられるかを `Yes` / `条件付き` / `No` の1語で判定し、理由・必要な対策（条件付きのときは中計・対処すべき課題・成長戦略の施策と brief の節）・結論の文（テンプレート）を書く
  - 最大の強みが「なし」なら判定は `No`、最大の脅威が「なし」なら `Yes` にする（build が確認する）
  - 2段階で迷ったら**不利な方**を採り（policy.md 行動指針6。強み・機会は小さい方、弱み・脅威は大きい方、判定は No 寄り）、理由に「迷った:」で始まる文を入れる
  - 前回と違う判定にするときは、5章の理由に「前回から変更:」で始まる文を入れ、8章にも書く
  - 表のセルに `|` を書かない。6章（結論）は build が書くので触らない。推奨表現（「買い推奨」など）、「おそらく」「〜と思われる」を書かない
- 見出し・表の列・ヘッダー・スクリプト記入済みの欄（1章・1.1・3章・前回の欄）は変えない。ファイルを丸ごと書き直さない（Write は hook がブロックする）

#### 判断基準（企業分析フレームワーク.md 1-4 の転記）

**手順1 事実を4象限に振り分ける**

- 内部要因（会社自身でコントロールできる）→ 強み（S）/ 弱み（W）
- 外部要因（市場・業界・社会の変化）→ 機会（O）/ 脅威（T）
- 1-1 で「強」となった要因は必ず脅威（T）、1-3 で特定したモートは必ず強み（S）に記載する
- 意見や推測ではなく、根拠のある事実のみ記載する

**手順2 各項目の影響度を評価する**

| 影響度 | 条件 |
|---|---|
| 大 | 主力事業の売上・利益の20%以上に影響しうる |
| 中 | 5〜20%に影響しうる |
| 小 | 5%未満 |

影響度「大」の中から「最大の強み」と「最大の脅威」を1つずつ選ぶ（脅威が「大」なしの場合は「中」から選ぶ）。

**手順3 最大の強みで最大の脅威に対抗できるか**（今後3〜5年）

| 判定 | 条件 |
|---|---|
| **Yes** | 強みが脅威を直接打ち消せる、または脅威の影響を受けにくい |
| **条件付き** | 会社が特定の対策（中計の施策など）を実行できれば耐えられる |
| **No** | 強みが脅威の影響を受ける、または対策が見当たらない |

結論の文: 「〈最大の強み〉により、〈最大の脅威〉に対して〈耐えられる/条件付きで耐えられる/耐えられない〉。理由：〇〇」

**SWOT の結論**（build が判定。上から順に当てはめる）

| 結論 | 条件 |
|---|---|
| **判定保留** | 強みがすべて影響度「不明」、脅威がすべて「不明」、または中以上の脅威は無いが「不明」の脅威がある（材料不足。No とは区別し、不明を良い方に解釈して Yes にしない） |
| **No** | 影響度「大」の強みが無い |
| **Yes** | 影響度が中以上の脅威が無い |
| 5章の判定 | 上のどれでもない（条件付きには会社の施策の記述が要る） |

### 4. ビルド（スクリプト）

```
$PY -I tools/analysis/swot.py build --company {company}
```

- `ok: true` → md の6章に結論を書き込み、json を作る。返り値の `verdict`・`verdict_reason`・`sentence`・`top_strength`・`top_threat`・`counts`（象限ごとの項目数）・`tie_breaks`（迷った項目）・`low_confidence`（根拠の確度が参考の項目）・`unknown`（影響度が不明の項目）・`gaps`（9章の全件）を完了報告に使う
- `ok: false` → `issues` の指摘箇所だけを Edit で直し、もう一度 build（2回まで。それでも残れば未完了として、指摘をそのまま報告する）

## してはいけないこと

- 5段以外の作業（追加の web 検索、raw・PDF・CSV・上流の分析 md・outlook.md の閲覧、数値の手計算）をしない。材料が足りなければ影響度を「不明」にして 9章に書く
- スクリプトが作るファイル（brief.md・json）と、swot.md の1章・1.1・3章・前回の欄・6章を手で直さない
- 有効期間内の結果を作り直さない（`--redo` はユーザーの指示があるときだけ）。過去の日付の完成済み md を変更しない（hook がブロックする）
- STEP 1 判定（A/B/C）や投資の勧誘・推奨を書かない
- 収集担当（collect-company-info）へのプロンプトで、raw の書き方（範囲外の章に「変更なし」と書く、前回の表を再掲するなど）を指示しない。書き方は collect-company-info.md の保存ルールに任せる

※ グローバル設定の hook（Fact-Forcing Gate）が、最初の Bash と、ファイルごとの最初の Edit を一度差し戻すことがある。求められた事実を示して同じ操作を再実行すれば通る。

## 完了報告（ユーザー向け）

check・prepare・build の JSON（moat・market-report・収集を実行した場合はその完了報告も）だけを使い、次の形式で短く報告する。

```
## SWOT分析 — {name}
- 結果: {md}（機械可読: {json}）
- SWOT の結論: {verdict}（{verdict_reason}。前回 {previous.verdict または「初回」}）
  - {sentence}
  - 最大の強み: {top_strength.id} {top_strength.fact}（影響度 {top_strength.impact}）
  - 最大の脅威: {top_threat.id} {top_threat.fact}（影響度 {top_threat.impact}）
  - 項目数: S {counts.S} / W {counts.W} / O {counts.O} / T {counts.T}
- 上流の結論: 業界の魅力度 {upstream.five_forces.verdict}（{date}）/ 勝てる理由 {upstream.three_c.verdict}（{date}）/ モート {upstream.moat.verdict}（{date}）
- 判断が分かれた項目: {tie_breaks。無ければ「なし」} / 根拠が参考情報だけの項目: {low_confidence。無ければ「なし」} / 影響度が不明の項目: {unknown。無ければ「なし」}
- 有効期限: {valid_until}（それまでは再実行しても再分析しない）
- 材料: {今回 moat・market-report・collect-company-info を実行した・しなかった（実行したならその理由と結論。--skip-collect・--skip-market-report で進んだならその項目）。1社のため選択を省略したならその旨。unavailable があれば列挙}
- 欠損: {gaps の全件の要点。無ければ「なし」}
```

有効期間内で再分析しなかった場合は、`latest` の md・結論・有効期限と「有効期間内のため再分析していない（作り直す場合は redo を指示）」だけを書く。
