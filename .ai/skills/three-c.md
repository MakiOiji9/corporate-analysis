# 3C分析スキル（three-c）

`企業分析フレームワーク.md` の **STEP 1-2 3C分析**（会社の立ち位置。勝てる理由 明確 / あいまい / なし。材料不足なら 判定保留）を、
collect-company-info・collect-market-info・market-report が集めた材料と、five-forces（STEP 1-1）の結果から行う。成果物は次の3つ。

- `companies/{ticker}_{name}/analysis/three-c/{日付}_three-c.md` — 分析結果。企業分析レポートはこれ（と json）を参照する
- `.../{日付}_three-c.json` — 同じ結果の機械可読版（顧客・KBF・成長性・競合比較表と判定・KBF 比較・勝てる理由と結論・SWOT/モートへの引き継ぎ・有効期限）
- `.../{日付}_brief.md` — 執筆の材料（raw から必要な節を抜き出し、比較表と判定候補を計算したもの）

`{日付}` は分析日。結果は **365日有効**で、期間内は再実行しても既存の結果を返すだけにする。
ただし期限前でも、新しい期の有報、業界データ・中期経営計画の新しい収集、またはファイブフォースの結論が変わったときは再分析する。競合・株価・事業概要の取り直しや、同じ期の数値の訂正だけでは再分析しない（有効期限を待つ）。上流の分析は作り直されても結論が同じなら再分析しない（`tools/analysis/freshness.py`）。

抽出・数値の計算（比較表・成長性と競合比較の判定候補・競合の営業利益率の平均）・材料の過不足の判定・検証・**結論（明確/あいまい/なし/判定保留）の判定**はスクリプト（`tools/analysis/three_c.py`）が行う。
LLM が受け持つのは three-c.md の FILL 欄（顧客・KBF・評価と根拠の文章・KBF 比較表）だけ。手順は **企業の選択 → 鮮度確認 → 準備 → 執筆 → ビルド** に固定されている。

## 実行手順

Python は `.venv` のものを使う（Windows: `.venv\Scripts\python.exe`、macOS/Linux: `.venv/bin/python`）。以下 `$PY` と書く。
各コマンドの標準出力は1行の JSON。

### 0. 企業の選択（`company` が無いときだけ）

```
$PY -I tools/analysis/three_c.py list
```

`companies` の各行（`dir`・`name`・`last_collected`・`three_c`・`three_c_date`・`verdict`・`five_forces`）から選択肢を作り、ユーザーに選んでもらう（提示の方法はエントリーポイントの指示に従う）。
企業が1社だけなら選択肢を出さずにその企業で進み、完了報告の「材料」行に「対象は1社だけのため選択を省略」と書く。
選択肢には `three_c` の状態（`none` 未分析 / `fresh` 有効 / `expired` 期限切れ / `triggered` 新しい raw・ファイブフォースあり / `draft` 作成途中）と、ファイブフォースの状態（`fresh` 以外なら先に実行される）を添える。
一覧に無い企業を指定されたら、手順 1 の `company_missing` と同じ扱いにする。

### 1. 鮮度確認（スクリプト）

```
$PY -I tools/analysis/three_c.py check --company {company}
```

`next` に従う。

| `next`・状態 | すること |
|---|---|
| `ok: false` で `candidates` あり | 複数の企業が当たった。候補からユーザーに選んでもらい、もう一度 check |
| `ok: false` で `company_missing: true` | 企業の情報が無い。ユーザーにホームページ URL を確認し、collect-company-info を `mode=full` で実行してから check をやり直す |
| `report_existing`（`result: fresh`） | 有効期間内。`latest`（md・結論・有効期限）を完了報告の形式で伝えて**終わる**（執筆しない）。`redo` の指示があるときだけ手順 2 へ |
| `collect` で `needs_full_collect: true` | raw が無い。collect-company-info を `mode=full` で実行し、check をやり直す |
| `five_forces` | ファイブフォース（STEP 1-1）の結果が無い・期限切れ・再分析要・作成途中（`five_forces.result`）。**five-forces スキルを最後の完了報告まで実行**してから check をやり直す（材料の収集が要れば five-forces の中で行われる） |
| `collect` | 3C に必須の材料が足りない（節が無い・空・中身が薄い）。collect-company-info を `mode=update` で実行し、`missing_inputs` の担当（`agent`）と項目（`items`）を範囲として伝える。終わったら check をやり直す |
| `prepare`（`none` / `expired` / `triggered` / `draft`） | 手順 2 へ |

- 地合い（outlook.md）は md のヘッダーで参照するだけで、3C の判断には使わない。そのため古くても（`outlook_stale: true`）market-report・collect-market-info は実行しない。完了報告の「材料」行に「地合いは N 日前の週（古い）」と書く
- five-forces の実行は**1回の実行につき1回まで**。やり直した check でまだ `five_forces` が出たら（five-forces が止まった・作成途中のまま）、このスキルも止めて状況を報告する
- 収集（collect-company-info）は**1回の実行につき1回まで**（five-forces の中で収集した場合も1回と数える）。やり直した check でまだ `collect` が出ても、もう一度は収集せず手順 2 に `--skip-collect` を付けて進む（取れなかった材料に関わる評価は「不明」「？」として扱い、8章に書く）
- check と prepare を1つのコマンドにつなげない。prepare も `next` を確かめ、`five_forces`・`collect` のままなら `ok: false` で拒否する
- `unavailable` は「収集を試みたが取れなかった」材料（status.md の未取得項目）。再収集しない
- 「中身が薄い」は、KBF の調査・競合の顧客・人員の KPI・競合の強みの節で、表に空の会社の行（会社名以外がすべて —）があるもの、または表の無い節が「見つからなかった」「確認できず」などと書いているもの。KBF の比較（3章）が成り立たなくなるため収集を求める
- 収集スキル・five-forces が止まった（ユーザーへの確認待ち・エラー）ときは、このスキルも止めて状況を報告する

### 2. 準備（スクリプト）

```
$PY -I tools/analysis/three_c.py prepare --company {company} [--redo] [--skip-collect]
```

- `{日付}_brief.md`（材料）と `{日付}_three-c.md`（FILL つきの骨組み）を作る。返り値の `brief`・`md` がそのパス
- 骨組みには、スクリプトが計算した **2.1 比較表**（対象企業と競合最大5社の売上高・営業利益率・シェア・売上高3年CAGR）、**3章の競合の凡例**（競合A〜E）、判定候補、前回の評価が記入済み
- 作成途中の md（FILL が残っている）は上書きせず残す（`kept: true`）。続きから書く
- 一字も書いていない骨組み（前回の prepare が書いたままの md）は、`--redo` なしで作り直す（`regenerated: true`）
- 同じ日に build 済みの結果があると `--redo` は拒否される。その日の md を Edit で直して build し直す
- `candidates` はスクリプトの判定候補（成長性: 先頭の市場の CAGR、競合との比較: 営業利益率とシェアの順位）。`competitor_fixed: true` なら競合との比較は確定で変えられない

### 3. 執筆（LLM）

brief.md を読み、three-c.md の `<!-- FILL:... -->` を Edit で置き換える。

- 読むのは brief.md と three-c.md だけ。raw・PDF・CSV・summaries を個別に開かない（必要な節は brief.md に集約済み）
- brief.md が Read の上限を超えるときは、offset/limit で分けて最後（5. 取れていない材料）まで読む
- 書く順番と Edit の単位（各1回）: 1章の表 → 2.2 の表 → 3章の KBF 表の行 → 3章の結論 → 4章の表 → 6章の表 → 7章 → 8章
- 書き方の規則は three-c.md 冒頭の `>` 行に従う。要点:
  - 1章の主力セグメントは、brief.md 0章のファイブフォースの業界の定義と同じ主力事業にする
  - KBF は「、」区切りで重要度の高い順に2〜5個。順番の根拠（業界調査・会社資料の記述）を「KBFの根拠」に書く。brief に KBF の調査が無く記事の評価軸しか無いときは、候補を記事の評価軸とフレームワークの例（価格・品質・性能・サポート・ブランド）から選び、順番に裏付けがある位置と無い位置を書く
  - 3章の KBF 表は、1章の KBF と**同じ名前・同じ順番**で1行ずつ。セルは各社がその KBF でどうか: `○`（比較した中で優れる）/ `△`（同等）/ `×`（劣る）/ `？`（brief に根拠が無い・比べられない）。凡例が「—（比較対象なし）」の競合の列は `—`。根拠には事実（製品・価格・実績・顧客数や継続率・顧客評価・受賞など）と出典を書く。brief「競合: 顧客・人員の KPI」の数値は、自社の KPI と並べて比べる
  - 記号は**比較の結果**。自社に事実（顧客数・事例など）があっても、競合に同じ種類の材料が無く比べられなければ、自社の列も `？` にする。会社の主張（IR 資料での自己評価）だけを根拠に ○ にしない。最重要 KBF（1行目）が比べられないと、build は ？ を △ とみなし、2.2 の競合との比較で結論を決める（劣位→なし、同等・優位→あいまい）
  - 成長性は `高` / `中` / `低` / `不明`、競合との比較は `優位` / `同等` / `劣位` / `不明` の1語。下の判断基準で決める。2段階で迷ったら**低い方**（不利な方）を採り（policy.md 行動指針6）、理由に「迷った:」で始まる文を入れる
  - 理由に書く事実は brief.md の記述と同じ強さで書く。brief で「未確認」「要旨」とある事柄を確認済みの事実として書かない
  - 「根拠の確度」は、評価を決めた根拠のうち最も弱いものの種類: `一次`（有報・会社資料・官公庁統計）/ `二次`（調査会社の公表値を記事経由で引用、IRBANK・株探など集計サイトの財務数値の転記）/ `参考`（ブログ・比較サイト・検索結果の要旨）。不明で根拠が無ければ `—`。どれに当たるかは brief.md 0章の「raw の情報源と注意」（raw の冒頭の情報源・注意書き）で判断し、推測で決めない
  - 2.2 の結論は「営業利益率〇% vs 競合平均〇%」の形。競合平均は 2.1 の注記・判定候補にある単純平均を転記する（手で計算しない）
  - 4章の勝てる理由は「〈顧客〉が重視する〈KBF〉において、〈自社の強み〉により、競合より優れている」の1文。テンプレートが埋まらなければ「なし」で始め、埋まらない理由（材料不足か、競合に劣るか）を続ける
  - 4章の「評価が変わる条件」は、監視する指標と、結論が1段階変わるしきい値を1文で書く（企業分析レポートの監視項目になる）
  - 6章は後続の分析（1-3 モート・1-4 SWOT）への引き継ぎ。強み候補は3章で ○ の KBF、弱み候補は × の KBF・2章で劣る指標・1章の顧客への依存（最大顧客・上位顧客の比率とその推移）。○ が無いときは「なし」と書き、SWOT で確かめる自社の事実を続けてよい
  - スクリプトの判定候補より**有利**な評価にするときは、理由に「候補と異なる理由:」で始まる文を入れる。「（確定）」の候補は変えられない
  - 前回の評価と違う評価にするときは、理由に「前回から変更:」で始まる文を入れ、7章にも書く。前回と同じ材料なら同じ評価にする
  - 表のセルに `|` を書かない。5章（結論）は build が書くので触らない
- 見出し・表の列・ヘッダー・スクリプト記入済みの欄（判定候補・前回の評価・2.1 の比較表・3章の凡例）は変えない。ファイルを丸ごと書き直さない（Write は hook がブロックする）

#### 判断基準（企業分析フレームワーク.md 1-2 の転記）

**手順1 顧客（成長性）**: 主力事業の市場の成長率が 年3%以上 **高** / 0〜3% **中** / マイナス **低**。
スクリプトの候補は brief の市場規模の表で**先頭**の市場の CAGR。主力事業の市場が別の行なら、その市場の数値で判定し「候補と異なる理由:」を書く（有利になる場合）。成長率の数値が無ければ「不明」。

**手順2 競合との比較**: 対象企業と競合2〜5社の中で、営業利益率・シェアの両方で上位 **優位** / どちらか一方で上位、または中位 **同等** / 両方で下位 **劣位**。

- 「上位」は比較した中で1位、「下位」は最下位（同率は中位）。スクリプトが 2.1 の比較表から計算する
- 両方の数値がそろえば候補は「確定」。シェアの数値が無いときは営業利益率だけの候補（未確定）になり、1位でも「同等」、最下位なら「劣位」（迷ったら不利な方）。brief にシェアの順位を示す一次・二次の記述があるときだけ、「候補と異なる理由:」を書いて有利側に変えてよい
- 各社の年度が1年以上ずれていると候補は未確定になる。ずれを理由に書く

**手順3 自社（KBF 比較）**: KBF ごとに ○ / △ / × / ？ を付ける（上の執筆規則）。

**手順4 勝てる理由（build が判定。参考。上から順に当てはめる）**

| 結論 | 条件 |
|---|---|
| **なし** | 競合との比較が 劣位（数値で裏付けのある不利は、材料不足より優先） |
| **あいまい / なし** | 最重要 KBF（1行目）の比較が成り立たない（自社が ？、または比較した競合が全員 ？）ときは ？ を △ とみなし、競合との比較で決める: 劣位→なし、同等・優位→あいまい（明確にはしない（材料不足のため保守的に判定。結果 JSON の conservative に記録）） |
| **判定保留** | 最重要 KBF の比較も、競合との比較（不明）も材料が無い（判定に使える事実が無い） |
| **なし** | 勝てる理由が「なし」 |
| **明確** | 最重要 KBF で自社が ○ かつ比較した競合が全員 △ か ×、かつ競合との比較が 優位 |
| **あいまい** | 上のどれでもない（競合に ○・？ がある、競合との比較が 同等・不明 など） |

### 4. ビルド（スクリプト）

```
$PY -I tools/analysis/three_c.py build --company {company}
```

- `ok: true` → md の5章に結論を書き込み、json を作る。返り値の `verdict`・`verdict_reason`・`win_reason`・`kbf`・`growth`・`competitor`・`tie_breaks`（迷った評価）・`low_confidence`（根拠の確度が参考の評価）・`unknown_kbf`（？ がある KBF）・`gaps`（8章の全件）を完了報告に使う
- `ok: false` → `issues` の指摘箇所だけを Edit で直し、もう一度 build（2回まで。それでも残れば未完了として、指摘をそのまま報告する）

## してはいけないこと

- 5段以外の作業（追加の web 検索、raw・PDF・CSV の閲覧、数値の手計算）をしない。材料が足りなければ「不明」「？」にして 8章に書く
- スクリプトが作るファイル（brief.md・json）と、three-c.md の判定候補・前回の評価・2.1 の比較表・3章の凡例・5章を手で直さない
- 有効期間内の結果を作り直さない（`--redo` はユーザーの指示があるときだけ）。過去の日付の完成済み md を変更しない（hook がブロックする）
- 投資の勧誘・推奨、「おそらく」「〜と思われる」を書かない（build が検出する）

※ グローバル設定の hook（Fact-Forcing Gate）が、最初の Bash と、ファイルごとの最初の Edit を一度差し戻すことがある。求められた事実を示して同じ操作を再実行すれば通る。

## 完了報告（ユーザー向け）

check・prepare・build の JSON（five-forces・収集を実行した場合はその完了報告も）だけを使い、次の形式で短く報告する。

```
## 3C分析 — {name}
- 結果: {md}（機械可読: {json}）
- 勝てる理由: {verdict}（{verdict_reason}。前回 {previous.verdict または「初回」}）
  - {win_reason}
  - 顧客: KBF {kbf を「、」で}／成長性 {growth}　競合との比較: {competitor}
- 判断が分かれた評価: {tie_breaks。無ければ「なし」} / 根拠が参考情報だけの評価: {low_confidence。無ければ「なし」} / ？ がある KBF: {unknown_kbf。無ければ「なし」}
- 有効期限: {valid_until}（それまでは再実行しても再分析しない）
- 材料: {ファイブフォース {five_forces.date}（業界の魅力度 {five_forces.attractiveness}）。今回 five-forces・collect-company-info を実行した・しなかった。地合いが古ければ「地合いは N 日前の週（古い）」。1社のため選択を省略したならその旨。unavailable があれば列挙}
- 欠損: {gaps の全件の要点。無ければ「なし」}
- 次に集める材料: {verdict が「判定保留」のときだけ。最重要 KBF を比べるのに要る材料と担当（gaps から）。collect-company-info で集めると新しい raw として再分析の対象になる}
```

有効期間内で再分析しなかった場合は、`latest` の md・結論・有効期限と「有効期間内のため再分析していない（作り直す場合は redo を指示）」だけを書く。
