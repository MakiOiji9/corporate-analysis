# バリュエーション分析スキル（valuation）

`企業分析フレームワーク.md` の **STEP 3 バリュエーション**（今の株価は妥当か。3-1 PER・3-2 PBR・3-3 PEG・3-4 EV/EBITDA を 割安 / 妥当 / 割高 / 評価対象外 で判定し、点数の平均で STEP 3 割安 / 妥当 / 割高。材料不足なら 判定保留）を、
collect-company-info が集めた株価データ・競合・財務時系列・有報の材料と成長性分析の結果から行う。成果物は次の3つ。

- `companies/{ticker}_{name}/analysis/valuation/{日付}_valuation.md` — 分析結果。判定シートの STEP 3・総合判断はこれ（と json）を参照する
- `.../{日付}_valuation.json` — 同じ結果の機械可読版（4指標の判定と数値・共通ルールの2軸・適正PBR・PEG の3ケース・EV の内訳・STEP 3 の点数・判定が変わる株価・引き継ぎ・有効期限）
- `.../{日付}_brief.md` — 執筆の材料（数値の要点と、数値の背景になる raw の節の抜粋、上流の分析の結論）

`{日付}` は分析日。株価は日々動くため、結果は **7日有効**で、期間内は再実行しても既存の結果を返すだけにする。
ただし期限前でも、分析が使った節（株価データ・競合・有報・財務時系列・中期経営計画）の中身や数値（新しい株価・決算期・訂正）が変わったとき、または新しい成長性分析ができたときは再分析する。

**数値の抽出・倍率の計算・各指標の手順・STEP 3 の点数と最終確認・判定が変わる株価はすべてスクリプト（`tools/analysis/valuation.py`）が行う。**
LLM が受け持つのは valuation.md の FILL 欄（数値の背景と解釈・引き継ぎ）と、PBR のバリュートラップに当たるときの「改善策の有無」（あり / なし / 不明）の回答だけ。手順は **企業の選択 → 鮮度確認 → 準備 → 執筆 → ビルド** に固定されている。

成長性分析（growth）は**必須の上流**（PER の手順2が会社計画の信頼性を、PEG が EPS CAGR を使う）。有効な結果が無ければ先に growth を実行する（成長性の結論では止めない）。
収益性・安全性・キャッシュフロー・SWOT の結果は手順3（最終確認）にだけ使い、無ければ「未実施」と記録する（それらのスキルは実行しない）。
地合い（outlook.md）は md のヘッダーで参照するだけで、判定には使わない。古くても market-report・collect-market-info は実行しない。
割安・割高は現時点の株価の位置づけで、将来の株価の予測ではない（`.ai/instructions/policy.md`）。

## 実行手順

Python は `.venv` のものを使う（Windows: `.venv\Scripts\python.exe`、macOS/Linux: `.venv/bin/python`）。以下 `$PY` と書く。
各コマンドの標準出力は1行の JSON。

### 0. 企業の選択（`company` が無いときだけ）

```
$PY -I tools/analysis/valuation.py list
```

`companies` の各行（`dir`・`name`・`last_collected`・`valuation`・`valuation_date`・`verdict`・`growth`）から選択肢を作り、ユーザーに選んでもらう（提示の方法はエントリーポイントの指示に従う）。
企業が1社だけなら選択肢を出さずにその企業で進み、完了報告の「材料」行に「対象は1社だけのため選択を省略」と書く。
選択肢には `valuation` の状態（`none` 未分析 / `fresh` 有効 / `expired` 期限切れ / `triggered` 材料・数値・成長性分析が変わった / `draft` 作成途中）と、成長性分析の結論（無ければ「未実施」）を添える。
一覧に無い企業を指定されたら、手順 1 の `company_missing` と同じ扱いにする。

### 1. 鮮度確認（スクリプト）

```
$PY -I tools/analysis/valuation.py check --company {company}
```

`next` に従う。

| `next`・状態 | すること |
|---|---|
| `ok: false` で `candidates` あり | 複数の企業が当たった。候補からユーザーに選んでもらい、もう一度 check |
| `ok: false` で `company_missing: true` | 企業の情報が無い。ユーザーにホームページ URL を確認し、collect-company-info を `mode=full` で実行してから check をやり直す |
| `report_existing`（`result: fresh`） | 有効期間内。`latest`（md・結論・有効期限）を完了報告の形式で伝えて**終わる**（執筆しない）。`redo` の指示があるときだけ手順 2 へ |
| `collect` で `needs_full_collect: true` | raw が無い。collect-company-info を `mode=full` で実行し、check をやり直す |
| `growth` | 成長性分析が無い・期限切れ・作成途中・材料が変わった（`growth.reason`）。growth スキルを最後まで実行してから check をやり直す（growth が収集も行う。成長性の結論では止めない） |
| `collect` | 材料が足りない、または株価が古い（`price_age` が7日超）。collect-company-info を `mode=update` で実行し、`missing_inputs` の担当（`agent`）と項目（`items`）を範囲として伝える。終わったら check をやり直す。主な項目: 株価の基準日が古い（collect-peers-valuation「株価のみ」: 自社の株価データと競合 6章を同じ基準日で取り直す）、競合 12章「EV/EBITDA の材料」が無い（collect-peers-valuation）、株価データの 1・2・4章や競合 6章が無い（collect-peers-valuation） |
| `prepare`（`none` / `expired` / `triggered` / `draft`） | 手順 2 へ |

- 収集（collect-company-info）は**1回の実行につき1回まで**。やり直した check でまだ `collect` が出ても、もう一度は収集せず手順 2 に `--skip-collect` を付けて進む（株価が古いままなら brief と prepare の `warnings` に出る。判定できない指標は 判定保留 になることがある。9章に書く）
- growth の実行は収集の回数に数えない（growth の中で収集した場合も、このスキルの収集の1回は残る）
- check と prepare を1つのコマンドにつなげない（check の `next` を見てから次へ進む）。prepare も `next` を確かめ、`collect`・`growth` のままなら `ok: false` で拒否する
- `unavailable` は「収集を試みたが取れなかった」材料（status.md の未取得項目）。再収集しない
- 収集スキル・growth が止まった（ユーザーへの確認待ち・エラー）ときは、このスキルも止めて状況を報告する

#### 収集を依頼するとき

collect-company-info には `missing_inputs` の担当・項目だけを渡す。担当へのプロンプトに載せる原本の場所・同じ日の raw の扱いは、collect-company-info.md の mode=update の手順（分析スキルからの依頼）に従う。終わったら collect-company-info の集約（status.md・overview.md・summaries）まで済ませてから check に戻る。

### 2. 準備（スクリプト）

```
$PY -I tools/analysis/valuation.py prepare --company {company} [--redo] [--skip-collect]
```

- `{日付}_brief.md`（材料）と `{日付}_valuation.md`（FILL つきの骨組み）を作る。返り値の `brief`・`md` がそのパス
- 骨組みには **0章 前提（株価・株式数・EPS・BPS・有利子負債・現金・営業利益・減価償却費、年次の倍率の表、同業の倍率の表）**、**1〜4章 各指標の手順ごとの数値と判定**、**5章 STEP 3 の点数・平均点・最終確認**、**7章 判定シートの STEP 3 と判定が1段階変わる株価**がすべて記入済み。`candidate` が結論の候補（build が同じ規則で確定する）
- `fill_keys` が書く欄の一覧（md を読み直して探さなくてよい）。`measures_matter: true` のときは 2章「改善策の有無」の回答で PBR（と STEP 3）の判定が変わる
- 当てはまらない欄（特別損益の調整なし・バリュートラップに当たらない・PER と EV/EBITDA の食い違いなし・割安になりえない）は、スクリプトが「該当なし（…）」と記入済み。書き換えない
- 作成途中の md（FILL が残っている）は上書きせず残す（`kept: true`）。続きから書く
- 一字も書いていない骨組み（前回の prepare が書いたままの md）は、`--redo` なしで作り直す（`regenerated: true`）
- `--redo` は完成済みの結果（有効期間内）と書きかけの md を作り直すときだけ使う（ユーザーの指示があるときだけ）。同じ日に build 済みの結果があると `--redo` は拒否される。その日の md を Edit で直して build し直す
- `warnings`（brief の「警告」節にも出る）は、スクリプトが raw を読み違えた可能性や材料が古いこと（計算した PER・PBR と株価データ 3章の値が10%超ずれる、株価の基準日が7日超前、競合 6章と基準日が違う、株式数が未確定、競合の表示 PER・PBR と計算値のずれ、時価総額を年次の単位にそろえられない。株式分割の調整は直近期の EPS に影響しないので警告しない）。空でなければ完了報告の「警告」行に書く

### 3. 執筆（LLM）

brief.md を読み、valuation.md の `<!-- FILL:... -->` を Edit で置き換える。

- 読むのは brief.md と valuation.md だけ。raw・PDF・CSV・summaries・他の分析の md を個別に開かない（必要な節は brief.md に集約済み）
- 書く順番と Edit の単位（各1回。`fill_keys` にあるものだけ）: 1章 特別損益の中身（`special-bg`） → 2章 改善策の有無（`measures`） → 4章 食い違いの背景（`divergence-bg`） → 5章 割安の理由（`cheap-reason`） → 7章 → 8章 → 9章
- 書き方の規則は valuation.md 冒頭の `>` 行に従う。要点:
  - 書くのは**数値の背景と解釈だけ**。表の数値・判定・年度の行を変えない。数値を新しく計算しない
  - **改善策の有無**は「あり: 」「なし: 」「不明: 」のどれかで始め、根拠（brief の中期経営計画・有報の資本政策の記述と出典）を続ける。ROE 目標・資本コストを意識した経営・自社株買いや増配など株主還元の強化が示されていれば「あり」、記載が無ければ「なし」、材料が無ければ「不明」（不明は「なし」と同じ扱いで割安とみなさない）。良い方に解釈しない
  - **食い違いの背景**は、4章の「数値からの候補」（現金が多い・減価償却が重い・借入が多い）を brief の記述で確かめて書く。brief に無ければ「不明（brief に記載なし）」
  - **割安の理由**は、市場がこの会社を安く評価している理由を brief の SWOT の最大の脅威・STEP 2 の懸念・地合いから説明する。説明できなければ「不明（brief に記載なし）」。「あり」の回答で割安になる場合も書いておく（build が確定する。割安にならなければ「該当なし」と書いてよい）
  - 7章の「レポートで使う要点」は STEP 3 の結論とそれを決めた指標の数値（過去レンジでの位置・同業の中央値との差・PEG）。「総合判断で確かめること」は PBR と ROE の関係・PEG に使った成長率の現実性・割安に見える理由など
  - 判定が1段階変わる株価（7章）は「その株価になれば判定が変わる」という境界で、株価の予測ではない。「〜円になる」「〜円まで上がる」と書かない
  - **数値は md の表・brief にあるものだけを引用する。** build は、書いた欄にある数値が md のスクリプト記入部分と brief のどちらにも無いとき、また「約〜」「〜割」の概数を書いたときに拒否する（年・ページ番号・2桁以下の整数は対象外）
  - 根拠に書く事実は brief.md の記述と同じ強さで書く。表のセルに `|` を書かない。6章（結論）と 7章の「判定シートの STEP 3」は build が書くので触らない
- 見出し・表の列・ヘッダー・スクリプト記入済みの欄は変えない。ファイルを丸ごと書き直さない（Write は hook がブロックする）

#### 判断基準（企業分析フレームワーク.md STEP 3 の転記。判定はすべてスクリプト）

- 株価は株価データ 1章の直近の確定終値（基準日を記録）。株式数は自己株式を除く数。時価総額 = 株価 × 株式数。EPS は株式分割を調整した値（直近期は財務時系列・決算短信、無ければ株価データ 2章）。予想EPS は決算短信の次期予想（無ければ 2章）。BPS は決算短信（data/tdnet_facts.csv の最新の連結 BPS。期末・四半期末）、無ければ 2章の一番新しい日付の行
- 株式数が未確定（1章の株式数に「未確認」、または期末後のコーポレートアクションの記載あり）のときは、自己株式を含む株式数を上限として時価総額・EV/EBITDA も計算し、判定が変わるかを 4章と境界に近い比較に出す（判定は自己株式を除く株式数で行う）
- 同業の倍率は競合 6章の 株価 ÷ EPS（実績・予想）・BPS（列が無い・空の会社は 6章の表示値）。表示値と計算値が10%超ずれる会社は警告に出す
- 有利子負債・現金及び現金同等物・営業利益・減価償却費は安全性・キャッシュフロー分析と同じ読み方の直近期の値

**全指標共通の判定ルール**

| 軸 | 見るもの | 判定（スクリプト） |
|---|---|---|
| 軸1 過去レンジ | 位置 =（現在値 − 過去5年の最低値）÷（最高値 − 最低値）。直近5期の年次の高値・安値 | 33%以下 割安圏 / 34〜66% 妥当圏 / 67%以上 割高圏（整数に丸める。レンジの外は下なら割安圏・上なら割高圏）。3期未満は判定できない |
| 軸2 同業比較 | 同業（競合 6章）の中央値との差 | −20%以下 割安圏 / ±20%以内 妥当圏 / +20%以上 割高圏。2社未満は判定できない。「成長率や利益率の差で説明できる」は代理指標: 割安圏で自社の成長率（PER・PEG・EV/EBITDA は売上高の3年CAGR、PBR は ROE）が同業の中央値より5pt 以上低い、または割高圏で5pt 以上高いときは妥当圏とする |
| 組み合わせ | 2軸の3×3表 | 割安圏×割安圏・割安圏×妥当圏・妥当圏×割安圏 → 割安 / 割安圏×割高圏・割高圏×割安圏 → 妥当（要因を確認） / 妥当圏×妥当圏 → 妥当 / 妥当圏×割高圏・割高圏×妥当圏・割高圏×割高圏 → 割高。片方の軸だけ判定できればその軸で決める（片軸）。どちらも判定できなければ 判定保留 |

**各指標**

| 指標 | 手順 | 判定（スクリプト） |
|---|---|---|
| 3-1 PER | 手順1 EPS の精査 | 特別損益（特別利益 − 特別損失）の絶対値が純利益の10%以上なら 調整EPS = 実績EPS × 調整純利益 ÷ 純利益（調整純利益 = 純利益 −（特別利益 − 特別損失）× 0.7） |
| | 手順2 実績・予想 | 予想PER（株価 ÷ 予想EPS）で判定。成長性分析の会社計画の信頼性が「割り引いて扱う」なら実績PER も判定し、割高寄りの方を採る。予想EPS が無ければ実績PER |
| | 手順3 | 共通ルール。過去レンジは年次の PER（株価 ÷ 実績EPS）の高値・安値なので、軸1は同じ基準の**実績PER** で位置を見る（予想PER を実績のレンジに当てると成長企業ほど割安に寄るため）。軸2は予想PER と競合 6章の予想PER の中央値（予想PER が2社に無ければ実績PER どうし） |
| | 手順4 適用可否 | **評価対象外**: 直近期が赤字、予想EPS がプラスでない、純利益が前年から50%以上減った。保守的に、直近期が営業赤字（純利益が本業の外から出ている）も評価対象外 |
| 3-2 PBR | 手順1 | 共通ルール（過去レンジは年次の PBR の高値・安値、同業は競合 6章、成長率の補正は ROE の差） |
| | 手順2 ROE との関係 | 適正PBR = 予想ROE（予想EPS ÷ BPS。無ければ株価データ 3章の予想ROE）× 過去5年の平均PER（有報の期末PER の平均。3期無ければ年次の（高値 + 安値）÷ 2 の平均）。現在の PBR が 20%以上低い 割安 / ±20%以内 妥当 / 20%以上高い 割高。手順1と食い違えば手順2を採る。計算できなければ手順1 |
| | 手順3 バリュートラップ | PBR < 1倍 かつ ROE（直近期の 純利益 ÷ 自己資本）< 8% で、手順2までの判定が割安のとき、LLM の回答「改善策の有無」が なし・不明 なら 妥当 に引き上げる（あり なら割安のまま） |
| 3-3 PEG | 手順1 適用可否 | **評価対象外**: 3-1 で PER が評価対象外、標準ケースの成長率が5%未満、過去5年に純利益が前年の半分以下になった年がある |
| | 手順2 成長率 | 候補: 成長性分析の EPS CAGR、会社計画（予想EPS ÷ 実績EPS − 1）、アナリスト予想の EPS 成長率（数値があるときだけ）。標準 = 最小、悲観 = 標準の半分、楽観 = 最大 |
| | 手順3 | PEG = 3-1 で採った PER ÷ 標準ケースの成長率（%の数値）。1倍以下 割安 / 1〜2倍 妥当 / 2倍超 割高。悲観ケースでも2倍以下なら「安全域あり」 |
| 3-4 EV/EBITDA | 手順1 | EV = 時価総額 + 有利子負債 − 現金及び現金同等物、EBITDA = 営業利益 + 減価償却費（直近期）。EBITDA または EV（現金が時価総額と有利子負債の合計を上回るとき）がプラスでなければ **評価対象外**。過去レンジは算出値: 各年の（PER の高値・安値 × その年の純利益。赤字の年は PBR × 自己資本（プラスの年だけ））+ 有利子負債 − 現金 を EBITDA で割る。同業は（競合 6章の時価総額 + 11章の有利子負債 − 現金）÷（12章の営業利益 + 減価償却費）、12章が無ければ 6章の記載値。共通ルールで判定 |
| | 手順2 PER との食い違い | PER 割高・EV/EBITDA 割安、または PER 割安・EV/EBITDA 割高のとき、数値からの候補（ネットキャッシュがプラス＝現金が多い、減価償却費が EBITDA の半分以上＝減価償却が重い、D/E 1倍以上＝借入が多い）を出す。LLM が背景を書く。点数は変えない |

**STEP 3 判定**（上から順に当てはめる）

| 手順 | 判定（スクリプト） |
|---|---|
| 手順1 点数化 | 割安 +1 / 妥当 0 / 割高 −1。評価対象外・判定保留は集計から除外 |
| 手順2 平均点 | 点数になった指標が2つ未満なら **判定保留**（材料不足・評価対象外が多い。割安・妥当・割高とは区別する）。平均点 +0.5 以上 **割安** / −0.5 以下 **割高** / それ以外 **妥当** |
| 手順3 最終確認 | 割安のとき、収益性・成長性・安全性・キャッシュフローのいずれかが「懸念」、または SWOT が「No」なら **妥当** に引き上げる（市場が安く評価する理由が投資判断を覆しうる）。それらが未実施なら「未実施のため確認できない」と記録し割安のまま。LLM は 5章に割安の理由を書く |

### 4. ビルド（スクリプト）

```
$PY -I tools/analysis/valuation.py build --company {company}
```

- `ok: true` → md の6章に結論と 7章の判定シートの行を書き込み、json を作る。返り値の `verdict`・`verdict_reason`・`PER`・`PBR`・`PEG`・`EV/EBITDA`（各指標の判定と文）・`sheet`（判定シートの STEP 3）・`flip_prices`（判定が1段階変わる株価）・`borderline`（境界に近い比較）・`measures`（改善策の回答）・`unknown_backgrounds`（「不明」と書いた欄）・`pending`（判定保留の指標）・`gaps`（9章の全件）を完了報告に使う
- `ok: false` → `issues` の指摘箇所だけを Edit で直し、もう一度 build（2回まで。それでも残れば未完了として、指摘をそのまま報告する）

---

## してはいけないこと

- 5段以外の作業（追加の web 検索、raw・PDF・CSV の閲覧、数値の手計算、株価の取得）をしない。材料が足りなければ背景を「不明」にして 9章に書く
- スクリプトが作るファイル（brief.md・json）と、valuation.md のスクリプト記入済みの欄（0〜5章の表と判定、6章、7章の判定シートと株価の行）を手で直さない
- 有効期間内の結果を作り直さない（`--redo` はユーザーの指示があるときだけ）。過去の日付の完成済み md を変更しない（hook がブロックする）
- growth 以外の分析スキル（STEP 1 の five-forces・three-c・moat・swot、profitability・safety・cash-flow）、地合いのスキル（collect-market-info・market-report）をこのスキルから実行しない
- 投資の勧誘・推奨、将来の株価の予測（「〜円になる」）、「おそらく」「〜と思われる」を書かない（build が検出する）
- 収集担当（collect-company-info）へのプロンプトで、raw の書き方（範囲外の章に「変更なし」と書く、前回の表を再掲するなど）を指示しない。書き方は collect-company-info.md の保存ルールに任せる

※ グローバル設定の hook（Fact-Forcing Gate）が、最初の Bash と、ファイルごとの最初の Edit を一度差し戻すことがある。求められた事実を示して同じ操作を再実行すれば通る。

## 完了報告（ユーザー向け）

check・prepare・build の JSON（収集・growth を実行した場合はその完了報告も）だけを使い、次の形式で短く報告する。

```
## バリュエーション分析 — {name}
- 結果: {md}（機械可読: {json}）
- STEP 3: {verdict}（{verdict_reason}。前回 {previous.verdict または「初回」}）
  - PER: {PER}
  - PBR: {PBR}
  - PEG: {PEG}
  - EV/EBITDA: {EV/EBITDA}
- 判定シート: {sheet}
- 株価: {price.value}（基準日 {price.date}。割安・割高は現時点の位置づけで、株価の予測ではない）
- 判定が1段階変わる株価: {flip_prices を「。」で。無ければ「なし」}
- 境界に近い比較: {borderline を「。」で。無ければ「なし」}（材料の誤差や株価の小さな動きで判定が1段階動きうる）
- 改善策の回答: {measures。バリュートラップに当たらなければ「該当なし」} / 背景が不明の欄: {unknown_backgrounds。無ければ「なし」}
- 有効期限: {valid_until}（それまでは再実行しても再分析しない）
- 材料: {今回 collect-company-info・growth を実行した・しなかった（--skip-collect で進んだならその項目）。成長性分析の日付と結論。STEP 2・SWOT の未実施。1社のため選択を省略したならその旨。unavailable があれば列挙}
- 警告: {prepare の warnings。無ければ「なし」}
- 欠損: {gaps の全件の要点。無ければ「なし」}
- 次に集める材料: {pending があるか verdict が「判定保留」のときだけ。株価データ・競合 6章・12章（collect-peers-valuation）など}
```

有効期間内で再分析しなかった場合は、`latest` の md・結論・有効期限と「有効期間内のため再分析していない（作り直す場合は redo を指示）」だけを書く。
