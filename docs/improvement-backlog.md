## BL-01 主張ごとの原典・ページまでの証拠の連鎖

- **優先・出典**: P0。改善案.md「最優先の改善」「1. collect-company-info」「横断提案 2」
- **内容**: 原本の台帳（`sources/manifest.csv`）と raw の情報源はあるが、分析・レポートの個々の主張から、資料 ID・URL・公開日・対象期・ページまでを一貫してたどれない。今の情報源の列は「raw のファイル名と節」まで。未検証・抽出失敗の表示も無い
- **見送った理由**: 全スキルのテンプレート・brief・検証（build の検査）の作り直しになる。一度に広げると既存の分析の作り直しが全社で発生する
- **着手の条件**: いつでも着手できる。最初は小さく試す
- **進め方の案**:
  1. 1社（6506）・1分析（moat）で試す。raw の表に「資料 ID」の列を足し（manifest.csv の doc_id か新しい ID）、brief と md の情報源の列を資料 ID で参照させる
  2. build が、資料 ID が manifest に無い・ページが無い主張を「未検証」と表示する
  3. うまくいけば、他の分析・地合い（BL-07）に広げる
- **完了条件**: 企業レポートの任意の主張から、原本のファイルとページまでたどれる。たどれない主張には「未検証」が付く
- **試行（2026-11-15）**: 案1の「raw の表に列を足す」ではなく、raw の先頭の **Front Matter**（YAML）に資料の一覧と「節 → 資料 ID・ページ」を持たせた。分析の情報源の列は今の書き方（raw のファイル名「節」）のままで、本文・テンプレートを作り直さずに済む

  - moat の build が 12章「出典の連鎖」と json の `evidence`（`moats[].evidence` も）を書く。企業レポートのモートの表に「出典」の列（資料名は取得元の URL へのリンク、検証済みはページも、未検証は理由）。未検証でも build は止めない
  - 原本のファイル（`sources/`）は git 管理外で手元と Actions のキャッシュにしか無いため、レポートと12章は manifest の取得元 URL を出す。`sources/` のパスは URL が無い資料のときだけ（6506 では0件）
  - 新しく作る raw: 雛形 `raw-header.md` と collect-company-info の保存ルールに Front Matter の書き方を足した。`raw_financials.py`・`refresh_valuation.py` が書く raw にも付く（data/ の表は `d1`、API は `w1`。ページは null）
  - 6506 の結果: moat が参照する raw 5本に付けた（ページは raw の本文の記載を、原本のテキストを `find_pages.py` で検索して確かめた）。61件の参照のうち 検証済み 23・未検証 38（検索要約 22、原本なし 13 … 調査会社の記事など web だけの資料、ページなし 3 … EDINET CSV など）。結論（なし）は変わらない
  - 3798・6532・CBRS は Front Matter が無いまま（moat を build し直すと全件「未検証（Front Matter なし）」になる）
- **広げた（2026-11-15）**: five-forces（7章）・three-c（9章）・swot（10章）も、各 doc モジュールの `claims`・`with_evidence` で同じ「出典の連鎖」と json の `evidence` を出す。企業レポートは、五つの力の表に「出典」の列、3C の顧客・競合のカードに「出典」の行、SWOT は格子の下に折りたたみの「各項目の出典」（表示は `tools/report/cr_evidence.py` に共通化）。地合いの outlook.md への参照はたどらない（BL-07）

## BL-32 企業レポート: 期間別の行動計画と長期の3年後・5年後の水準

- 課題: 行動計画（`tools/report/cr_strategy.py`）は長期の判定だけで行動・利益確定・見直しを決め、株価の目安は「今の」割安・割高の帯だけだった。短期・中期に戦略が無く、長期に「どこで売るか」の目安が無かった
- 対応: 短期・中期・長期の3ブロックに分けた。短期はチャートの価格（`cr_scenarios` と同じ）、中期は指標の帯と次の決算の進み具合、長期は分割買いに加えて `tools/report/cr_projection.py` の3年後・5年後の水準（EPS × (1+成長率)^年数 × 過去5年の平均PER。成長率は PEG の3ケースで、楽観は 基本×1.5・25% で上限）を売りの目安にする。基本ケースの3年後の水準で一部の利益確定、楽観ケースの5年後の水準を超えたら残りも見直し、EPS の伸びが悲観ケースを下回り続けたら保有の理由を見直す
- 残り: 上限（1.5倍・25%）と平均PER の妥当性は BL-02 と同じくバックテストで確かめる。配当込みの利回りは出していない
- 状態: 完了（3196b4f）
