# 提案: テクニカル分析の充実（企業分析レポートに専用の章を追加）

Closes #3 の「案」の段階。実装前にレビューを受けるための提案書。

## 1. 目的

- 企業分析レポートに「テクニカル分析」の章を設け、チャートを根拠に「この後どう動く可能性が高いか」を示す。
- 1つの指標でなく、複数の切り口の結果をそれぞれ確認できるようにする。
- 三尊・ダブルトップなどのチャートの形（パターン）を検出し、チャートで図示する。
- 終値が更新されたら再分析する（時間による有効期限は設けない）。
- 最終的に `companies/{ticker}_{name}/reports/{日付}_company-report.html` に出力する。

## 2. 現状

- `tools/report/cr_technicals.py` が移動平均・RSI・MACD・ボリンジャーバンド・出来高から状態と押し目・利益確定・損切りの目安を計算し、短期・中期の「株価のテクニカル」要素の点数になる。
- `tools/report/cr_ch_price.py`・`charts.py` が株価チャートを描画。株価は `tools/collect/stock_prices.py` が取得。
- チャートの形（パターン）の検出、複数切り口の並列表示、終値更新による再分析の管理は未実装。

## 3. 多面的な分析（切り口）

各切り口を独立した結果（状態・根拠の数値・見通し・確度）として出し、章内でタブ／折りたたみで個別に確認できるようにする。

| 切り口 | 内容 | 出力 |
|---|---|---|
| トレンド | 移動平均（25/75/200）の並び・傾き、高値安値の切り上げ/下げ（ダウ理論） | 上昇/横ばい/下降 |
| モメンタム | RSI・MACD・ストキャスティクス、ダイバージェンス | 過熱/中立/売られすぎ |
| ボラティリティ | ボリンジャーバンド幅・ATR、スクイーズ | 拡大/収縮 |
| 出来高 | 出来高の増減、OBV、価格との乖離 | 裏付けあり/なし |
| 水準 | 支持線・抵抗線、直近高安、フィボナッチ戻し | 近い価格帯のリスト |
| チャートパターン | 後述 | 形成中/完成/無し |
| 総合 | 各切り口の方向を集計し、強気/弱気/中立のシナリオと確度を表示 | シナリオ3本 |

既存の cr_technicals.py の計算は再利用し、重複計算しない。順張り・逆張り指標の相殺は BL-22（対応しない）の方針に従い、総合では切り口ごとの内訳を併記して相殺の有無を見えるようにする。

## 4. チャートパターン分析

### 対象
- 反転: 三尊（ヘッド&ショルダーズ）、逆三尊、ダブルトップ、ダブルボトム、トリプルトップ/ボトム
- 継続・収束: 三角持ち合い（上昇/下降/対称）、フラッグ、ウェッジ、ボックス
- その他: カップウィズハンドル

### 検出方法（Python、決定的）
1. 終値（または高値・安値）から zigzag（変動率閾値、または scipy の極値検出）で転換点列を作る。
2. 転換点列に対し、各パターンの幾何条件を判定する（例: 三尊 = 3つの山で中央が最高、両肩の高さの差が許容内、ネックラインの傾きが許容内）。
3. 状態を 3 段階に分ける: 「形成中（条件の一部を満たす）」「完成（ネックライン割れ/上抜け確認）」「失敗（無効化）」。
4. 形成中・完成のとき、パターン理論から目標値を計算する（例: 三尊の下値目標 = ネックライン − (頭 − ネックライン)）、無効化ラインも併記。
5. 閾値は設定ファイルに置き、感度を変えて結果が安定するかを確認する（BL-02 と整合）。

### 見せ方
- 価格チャートにパターンの転換点・ネックライン・目標値・無効化ラインを重ね、「三尊を形成しそう → ネックライン○○円を割れると目標△△円」のように図と文章で示す。
- 「形成中」は確定でないこと、過去の同パターンの的中は保証でないことを明記（予想・推奨でなく条件付きの目安）。
- 同銘柄の過去の同パターン後の値動きを実績表示する（件数が少なければ「参考値」と表示）。

## 5. 見通しの出し方

- 切り口ごとに「条件 → 想定される動き」の形で記述（例: 「25日線を終値で割れると、75日線付近まで調整余地」）。
- 総合では、強気・基本・弱気の 3 シナリオを、トリガー価格・目標価格・無効化価格つきで表示。確率の断定はせず、根拠の数と一致度から「確度: 高/中/低」とする。
- 数値・判定は Python が出し、LLM は文章の整形のみ（既存の役割分担を踏襲）。

## 6. 再分析の条件（終値の更新）

時間による有効期限（20 時間）は採用しない。株価は日足の終値で確定するため、終値が更新されたかどうかを再分析の条件にする。

- 分析結果 JSON に `generated_at`（JST ISO8601）と、分析に使った株価の最終日（`price_asof`、最新の確定終値の日付）を持たせる。
- 保存先: `companies/{ticker}_{name}/analysis/technical/`（`technical.md` と `technical.json`）。
- 再分析の判定: 株価データの最新の確定終値の日付が JSON の `price_asof` より新しければ再分析。同じなら再利用。
- 時間・日数の期限は持たない。終値が動かない休場日は再分析しない（同じ入力で結果が変わらないため）。
- レポートには「分析時刻・使った終値の日付」を表示する。終値が古い結果は掲載せず、株価を取り直して再分析する（GitHub Actions の定期実行でも、実行時にチェックする）。
- 判定は `tools/report` の共通関数にし、`tools/collect/refresh_valuation.py` の最新終値の扱いと揃える。

## 8. レビューでの決定事項

- 再分析の条件: 20 時間の期限ではなく、終値の更新（第 6 節）。
- パターンの的中実績: 含める。同銘柄の過去の同パターン後の値動きを表示し、件数が少なければ「参考値」と明記する（第 4 節）。
- 点数への反映: 予想であるため評価（短期・中期判定の点数）には含めない。既存の点数計算は変えず、本章は参考表示のみ。
- 時間軸: 当面は現在使っている日足を基本とする。より良い案として、**週足を併用する多時間軸**を採用する。週足で大きなトレンドと大きな形（三尊・ダブルトップなど）を見て、日足で転換点・トリガー価格を見る。週足は日足から集計して作り（追加の取得は不要）、切り口ごとに時間軸を切り替えて確認できるようにする。分足は日々の更新運用に合わないため対象外。
- 予測の限界の伝え方: レポートで必ず明示する（第 9 節）。

## 9. 注意

- 本章は投資判断の参考で、予想・推奨ではない。パターンは主観が入りやすく、だましも多い。
- この点は章の冒頭と各パターンの説明、シナリオ表に必ず表示する（「予想であり確実ではない」「形成中は確定でない」「過去の的中は将来を保証しない」）。レポートの HTML 生成側で固定文言として出し、LLM の文章に任せない。
